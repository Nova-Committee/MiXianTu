# 灵根与体质拆分设计

## 定义边界

灵根与体质必须是两个独立系统，不能用同一个注册表或同一字段表达。

| 维度   | 灵根                     | 体质                          |
|------|------------------------|-----------------------------|
| 核心含义 | 对单一元素的修炼与术法亲和          | 与元素无关的先天/后天被动加成             |
| 绑定关系 | 每条灵根必须引用一个 `element`   | 不允许引用 `element` 或元素标签作为效果依据 |
| 实体持有 | 可同时持有多条灵根              | 可持有多条，但通过互斥标签限制组合           |
| 影响范围 | 元素灵气转化、对应元素能力适配、元素克制计算 | 属性修正、状态抗性、独立能力、独立资源修正       |
| 典型示例 | 火灵根、雷灵根、冰灵根            | 先天剑骨、纯阳体、霸体、长生体             |

同一玩家的火灵根和先天剑骨可以共存：前者只影响火元素相关规则，后者只提供剑类或生存类加成，二者不互相改变定义。

## 数据模型

### `element`

元素是独立动态注册表。它定义元素 ID、显示、关系和环境偏向，供灵根、法术、灵气环境和克制逻辑共同引用。五行、雷、风、冰、光、暗均是元素条目，不是硬编码枚举。

### `spirit_root`

每条灵根必须有且只有一个 `element` 引用。多灵根不使用“多元素灵根”定义，而是在 `SpiritData.spirit_roots` 中保存多个灵根
ID。灵根字段只允许表达：

- 元素修炼倍率与灵气转化倍率。
- 对其绑定元素的术法、功法和环境适配。
- 元素相关的授予能力或条件。
- 稀有度、洗练/获得规则和灵根之间的兼容标签。

灵根不得提供与绑定元素无关的生命、攻击、减伤等泛用属性；这类效果必须移入 `physique`、功法、装备或能力定义。

### `physique`

体质不含元素字段，也不参与元素克制和元素灵气计算。其字段包括：

- 独立属性修正，例如生命、移速、抗性、近战伤害、寿元。
- 授予的 `ability` 列表，例如剑骨的剑类被动、霸体的击退抗性。
- 获得/激活条件、稀有度、显示信息和互斥标签。
- 可选的堆叠策略；默认同一体质 ID 只能持有一次。

体质可有“纯阳体”这一名称，但实现上仍是独立体质效果，不能隐式视为火元素灵根。若需要同时具备火灵根，则数据包显式授予或要求火灵根。

## 附件与能力授予

`SpiritData` 分别保存 `spirit_roots: List<ResourceLocation>` 与 `physiques: List<ResourceLocation>`
。两者独立同步、独立版本迁移、独立洗练/移除 API。

当来源变更时：

1. 先重新解析灵根的元素引用和体质的独立定义。
2. 分别计算它们授予的能力、属性修正和互斥规则。
3. 将最终能力 ID 以来源键写入 `AbilityHolderData`，例如 `spirit_root:<id>` 或 `physique:<id>`。
4. 移除来源时只撤销该来源授予的能力；若另一来源仍授予同一能力，则保留其运行状态。

修炼结算时，所有有效灵根分别以 `cultivation_multiplier * max(0, 1 + 当前区块对应 element_bias)` 计算亲和度，取算术平均后再乘以已激活功法的修炼修正；无灵根时倍率为 `1`。体质不参与此计算。修炼动作的 `environment_tags` 必须全部存在于区块灵气附件，否则在扣除资源前拒绝本次 tick。

元素术法在 `ability.element_affinity` 中列出可适配的元素 ID。使用者必须持有至少一条匹配灵根；匹配灵根的 `element_ability_modifier` 取平均值，作为只读公式变量 `element_modifier` 注入能力及其嵌套动作的 `NumberProvider` 上下文。元素相关数值应在数据包公式中显式使用该变量，例如 `"damage": "12 * element_modifier"`。

## 数据包示例

```json
// data/example/mxt/element/fire.json
{
  "schema_version": 1,
  "relations": {
    "overcomes": [
      "example:wood"
    ]
  },
  "aura_tags": [
    "example:hot"
  ]
}
```

```json
// data/example/mxt/spirit_root/fire_root.json
{
  "schema_version": 1,
  "element": "example:fire",
  "cultivation_multiplier": 1.25,
  "element_ability_modifier": 1.1,
  "rarity": "rare"
}
```

```json
// data/example/mxt/physique/innate_sword_bone.json
{
  "schema_version": 1,
  "attribute_modifiers": [
    {
      "attribute": "minecraft:generic_attack_damage",
      "operation": "add_value",
      "value": 2.0
    }
  ],
  "granted_abilities": [
    "example:sword_intent"
  ],
  "exclusive_tags": [
    "example:physique/skeletal"
  ],
  "rarity": "epic"
}
```

## 校验规则

1. `spirit_root.element` 必须存在；一个灵根不能引用多个元素。
2. `physique` 中禁止元素字段和元素关系字段；加载器发现时应报错，而不是忽略。
3. 灵根的能力、修炼修正必须带有与其绑定元素一致的适配约束；否则数据包校验报错。
4. 体质之间的互斥标签在授予时由服务端检查；冲突时拒绝新体质或按数据包定义替换。
5. 元素关系只读取 `element` 注册表；不得根据体质名称或体质标签推导元素克制。
