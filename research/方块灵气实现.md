### 四、核心查询服务（玩家调用入口）

```java
public class PlayerContributionQuery {
    
    public static float getTotal(Player player, ContributionType type) {
        Level level = player.level();
        SectionPos center = SectionPos.of(player.blockPosition());
        float total = 0.0f;
        Vec3 playerPos = player.position();
        
        // 1. 遍历 7x7x7 子区块
        for (int dx = -SEARCH_RADIUS; dx <= SEARCH_RADIUS; dx++) {
            for (int dy = -SEARCH_RADIUS; dy <= SEARCH_RADIUS; dy++) {
                for (int dz = -SEARCH_RADIUS; dz <= SEARCH_RADIUS; dz++) {
                    SectionPos targetSec = center.offset(dx, dy, dz);
                    
                    // 获取子区块缓存数据（若脏则自动重算）
                    SectionCacheData cache = ChunkAttachmentManager
                        .getOrCompute(level, targetSec);
                    if (cache == null) continue;
                    
                    double distSq;
                    float secValue;
                    
                    // 2. 判断是否在 3x3x3 精确范围内
                    if (Math.abs(dx) <= EXACT_RADIUS && 
                        Math.abs(dy) <= EXACT_RADIUS && 
                        Math.abs(dz) <= EXACT_RADIUS) {
                        // 精确计算：直接遍历内部方块，并累加距离权重
                        secValue = ExactSectionCalculator
                            .computeForPlayer(level, targetSec, playerPos, type);
                        // 注意：这里已经包含了除以距离平方，所以直接加到total
                        total += secValue;
                    } else {
                        // 远距离近似：使用子区块中心点
                        Vec3 centerPos = targetSec.getCenter(); // x+8, y+8, z+8
                        distSq = playerPos.distanceToSqr(centerPos);
                        if (distSq < 1.0) distSq = 1.0; // 防止除零
                        // cache中存的是该子区块所有方块贡献值之和（未加权）
                        total += cache.get(type) / distSq;
                    }
                }
            }
        }
        return total;
    }
}
```

### 五、精确计算器（遍历 3x3x3 内部的方块）

```java
public class ExactSectionCalculator {
    
    public static float computeForPlayer(Level level, SectionPos sec, 
                                         Vec3 playerPos, ContributionType type) {
        float sum = 0.0f;
        // 获取子区块的方块状态（需确保区块已加载）
        LevelChunk chunk = level.getChunk(sec.x(), sec.z());
        int yBase = sec.getMinY();
        
        // 遍历 16x16x16 子区块内的所有方块
        for (int x = 0; x < SECTION_SIZE; x++) {
            for (int y = 0; y < SECTION_SIZE; y++) {
                for (int z = 0; z < SECTION_SIZE; z++) {
                    BlockPos worldPos = new BlockPos(
                        sec.getMinX() + x,
                        yBase + y,
                        sec.getMinZ() + z
                    );
                    BlockState state = chunk.getBlockState(x, y, z);
                    float value = ContributionConfig.getContribution(state, type);
                    if (value != 0) {
                        double distSq = playerPos.distanceToSqr(
                            worldPos.getX() + 0.5, 
                            worldPos.getY() + 0.5, 
                            worldPos.getZ() + 0.5
                        );
                        if (distSq < 1.0) distSq = 1.0;
                        sum += value / distSq;
                    }
                }
            }
        }
        return sum;
    }
}
```

### 六、缓存管理（懒加载 + 脏标记）

```java
public class ChunkAttachmentManager {
    private static final int currentDataPackVersion = 1; // 数据包修改后+1
    
    public static SectionCacheData getOrCompute(Level level, SectionPos sec) {
        LevelChunk chunk = level.getChunk(sec.x(), sec.z());
        Map<SectionPos, SectionCacheData> map = 
            chunk.getData(ModMain.CONTRIBUTION_ATTACHMENT);
        
        SectionCacheData data = map.get(sec);
        // 若不存在，或版本过旧，则重新计算
        if (data == null || data.getVersion() != currentDataPackVersion) {
            data = computeSection(level, sec);
            map.put(sec, data);
        }
        return data;
    }
    
    private static SectionCacheData computeSection(Level level, SectionPos sec) {
        float[] values = new float[ContributionType.VALUES.length];
        LevelChunk chunk = level.getChunk(sec.x(), sec.z());
        int yBase = sec.getMinY();
        
        // 遍历子区块所有方块，累加各类贡献值（不带距离权重）
        for (int x = 0; x < 16; x++) {
            for (int y = 0; y < 16; y++) {
                for (int z = 0; z < 16; z++) {
                    BlockState state = chunk.getBlockState(x, y, z);
                    for (ContributionType type : ContributionType.VALUES) {
                        float val = ContributionConfig.getContribution(state, type);
                        if (val != 0) {
                            values[type.ordinal()] += val;
                        }
                    }
                }
            }
        }
        return new SectionCacheData(values, currentDataPackVersion);
    }
}
```

### 七、脏标记失效（监听方块事件）

```java
public class CacheInvalidator {
    
    @SubscribeEvent
    public void onBlockChanged(BlockEvent event) {
        Level level = event.getLevel();
        if (level.isClientSide()) return;
        
        SectionPos sec = SectionPos.of(event.getPos());
        LevelChunk chunk = level.getChunk(sec.x(), sec.z());
        Map<SectionPos, SectionCacheData> map = 
            chunk.getData(ModMain.CONTRIBUTION_ATTACHMENT);
        
        // 直接移除该子区块的缓存，下次查询时懒加载重算
        map.remove(sec);
    }
}
```

```java
public static void reloadConfigAndInvalidateAll() {
    // 1. 重新加载配置文件（ContributionConfig 内部刷新 Map）
    ContributionConfig.reload();
    
    // 2. 全局版本号 +1
    currentDataPackVersion++;

    //    对比版本号不一致，会自动触发重算，旧的缓存自然被覆盖。
}
```

```text

    │
    ▼
遍历 7×7×7 子区块（最多 343 个）

    │   精确遍历 27 × 4096 = 110,592 个方块（含距离权重）

            │
            ├─ 命中且版本一致 → 直接取值

            │
            ▼
        总值 / 子区块中心点到玩家的距离²
```

### 十、实现时的特别提醒

1. **Y轴限制**：如果Y轴超出世界高度（-64 ~ 320），`LevelChunk.getBlockState(x,y,z)` 会抛异常。在 `computeSection` 和精确遍历中，务必判断 `yBase + y` 是否在 `level.getMinBuildHeight()` 和 `level.getMaxBuildHeight()` 之间。

2. **方块实体（TileEntity）**：如果你的贡献值需要读取方块实体的NBT数据（例如箱子内的物品），那么 `ExactSectionCalculator` 中还要额外获取 `BlockEntity` 进行计算，但这会显著降低性能。建议只读 `BlockState`。

3. **多线程安全**：`getOrCompute` 可能在多个线程（如异步任务）中被调用，建议在 `computeSection` 外层加 `synchronized (chunk)` 或使用 `ConcurrentHashMap` 的 `computeIfAbsent` 配合 `ReentrantLock`。

4. **玩家查询频率**：建议不要每 Tick 都调用 `getTotal`，可以在玩家移动事件中每隔 5 Tick 计算一次，或者通过 `ScheduledExecutorService` 异步执行，只把结果同步回主线程显示。

这套架构代码边界清晰，后续无论是增加贡献类型、调整查询范围，还是优化距离算法，都只需修改对应模块，耦合度很低。祝你开发顺利！🚀

### 十一、当前工程的实现映射

当前工程的世界附件仍以 `LevelChunk` 为挂载点，使用 `block_aura_sections`（整数键为子区块 Y 索引，键乘 16 即底面高度）保存每个子区块的聚合值和匹配方块坐标。这样无需引入第二套持久化附件，也保留了区块库存的共享语义：

- 查询范围为玩家所在子区块周围 3 个子区块（7×7×7）；未加载区块直接跳过。
- 相对玩家子区块 3×3×3 范围内使用方块中心的精确距离，外围使用子区块中心近似。
- 衰减统一为 `1 / max(1, distanceSquared)`，避免零距离产生无穷值。
- 每 20 tick 重建 `AuraChunkAttachment` 的 `SectionPos -> 玩家访问数` 运行时表；同一来源子区块的贡献按访问数粗略平分。
- 方块来源的共享存量仍由区块附件中的 `auras` 管理，环境存量与方块存量在显示/计算时分离，方块不会改变环境基础上限的计算。
