# 75 数据表回退为注册表设计

> **状态**：**已落地**（2026-10-05，用户拍板）。本文推翻 [`70`](70_数据表与ItemMatcher替代评估.md) §11 那一轮"八张表全部迁成 NeoForge 数据表"的拍板：**九张表全部改回数据包注册表 + `ItemMatcher`**，`registry/MxtDataMaps.java` 删除。
> 落地记录见 §5；实现形状以代码为准。

## 1 决策与范围

用户 2026-10-05 决定：**把所有数据表的使用去掉，改回 `datapack registry` + `ItemMatcher`。**

范围是九张表，其中八张是 `70` 那一轮迁走的，第九张是数据表时代才新增、从来没有过注册表形态的：

| 表 | 键 | 迁移前形态 | 本稿形态 |
| --- | --- | --- | --- |
| `item_aura` | 物品 | 注册表 + `items` | 同前 |
| `currency` | 物品 | 注册表 + `items`（兼容旧 `item` 单值写法） | 同前 |
| `item_binding` | 物品 | 注册表 + `items` | 同前 |
| `weapon_binding` | 物品 | 注册表 + `items` | 同前 |
| `tool_binding` | 物品 | 注册表 + `items` | 同前 |
| `blueprint_binding` | 物品 | 注册表 + `items` | 同前 |
| `default_quality` | 物品 | *（不存在）* | **新设计**：注册表 + `items` + `quality` |
| `block_aura` | 方块 | 注册表 + `blocks` | 同前 |
| `heat_source` | 方块 | 注册表 + `blocks` | 同前 |

**为什么回退（用户口径 + 复核到的事实）：**

1. **数据表看不了堆。** `ItemMatcher` 里那几种条目（`mxt:wildcard` / `mxt:regex` / `mxt:technique` / `mxt:spirit_storage` / `mxt:herb_tag`）数据表一律表达不了，`item_binding` / `weapon_binding` 因此永久失去"任意堆算某概念"的能力（`70` §5.1 当时就是这条损失，用户当时接受了，现在不接受了）。
2. **值没有身份。** 数据表的值没有 id，不能被别的定义引用、不能进存档，picker 那一侧也得为此另造一套分类。
3. **本体自带的数据包一直是注册表形状。** `src/main/resources/data/mxt/mxt/{currency,item_aura,block_aura}/*.json` 从迁移那天起就没有跟着改——那些文件在迁移后**读不到**（灵石的面值与灵气燃料在没装测试包时会静默消失）。回退同时把这个缺口补上。

## 2 目标形状

- **物品键的七张**都是 `data/<命名空间>/mxt/<表>/<条目>.json`，条目实现 `util/matcher/ItemMatcher`：`items`（`ENTRIES_CODEC`）+ `priority`，与 `artifact` / `pill_binding` / `spirit_herb` / `technique_binding` 完全同形。`tool_binding` / `blueprint_binding` / `default_quality` 的 `items` 必填非空（没有"只由组件指认"的第二条路），`item_aura` / `currency` / `item_binding` / `weapon_binding` 可省略（省略＝这条定义谁也认领不到，与迁移前一致）。
- **方块键的两张**（`block_aura` / `heat_source`）是 `blocks`（`holderOrTagList(Registries.BLOCK)`）+ `priority`（`block_aura` 没有 `priority`，它按累加口径合并）。
- **`default_quality` 是本稿新设计的形状**：字段 `items` + `quality` + `priority`，`implements ItemMatcher`；`QualityService.find` 的第三层回到 `ItemMatcher.find(MxtDatapackRegistries.holders(access, MxtResourceKeys.DEFAULT_QUALITY).map(Reference::value), stack).map(DefaultQuality::quality)`。
  数据表时代的"裸档位 id 就是整个值"简写**取消**：注册表条目必须点名 `items`，这是注册表这一侧的统一形状，不为一张表开特例。
- **picker**：`PickerCategory`（为"数据表也是一种分类"而生的两层接口）删除，回到"一个注册表一个分类"的 `ResourceKey` 形状；`CreativeTabHelper` 的过滤谓词回到 `Predicate<Holder<?>>`（注册表条目的 id 在 holder 上）。
  `block_aura` / `heat_source` 仍然按**定义展开出的方块物品**出行（数据表时代的取法），不回退到迁移前那种"一块灵石当占位"的写法——分类内容不因为换回注册表而变少。
- **两个方块索引恢复**：`AlchemyHeatService`（供热方块 → `HeatSource`）与 `BlockAuraService`（方块 → 命中的 `BlockAura` 列表）。两者都按**方块注册表实例**开缓存键、由 `ServerCache.onDatapackLoaded` 显式 `invalidate()`（`/reload` 不换实例，键本身不足以发现换包）。
- **运行时的"按物品查定义"一律回到 `ItemMatcher.find`**：每 tick 每只手扫一遍注册表。这是迁移前的成本，本轮不做索引/缓存（`53` §7 与 §11 的那条开放项仍未做）。

## 5 落地记录

按 §3 清单实现。实际形状与设计的差异、以及实现时才定下来的细节：

1. **`default_quality` 的条目形状**：`{items, quality, priority}`（`DIRECT_CODEC`，`implements ItemMatcher`）。
   数据表时代那种"值就是一个档位 id"的简写取消——注册表条目必须点名它认领的物品；`DefaultQuality.of(...)`
   与那个 `Codec.either` 一并删除。测试包补了 7 份条目，与旧数据表的 8 条值逐一对应（`cobblestone` 与
   `#mxt_test:quality_probe` 合成一份，优先级与"同分"行为不变）。
2. **`QualityRequirements.test` 只收非空 `Provider`**：第三层要读 `mxt:default_quality` 注册表、链要走服务端索引，
   两件事都要 registry access，所以原来那条"没有 access 时只答成员判定、`min_quality` 直接答否"的分支被删除
   （数据表时代那一层不依赖 access，所以当时讲得通）；只拿得到一个堆的匹配路径（`QualityEntry` /
   `QualityIngredient`）自己问 `QualityRequirements.access()`、拿不到就答否。`QualityService.find` 的
   `Provider` 参数随之回到不可空。
3. **供热提示是新写的，不是回退**：`AlchemyHeatSourceTooltipAppender` 是数据表时代才加的文件，迁移前没有对应物；
   它现在扫 `mxt:heat_source` 注册表、按 `blocks` 匹配、取 `priority` 最高的一条（同分按注册表顺序），
   与 `AlchemyHeatService` 的索引同一条读法。
4. **`AlchemyHeatService.isHeatSource` 多收一个 `ServerLevel`**：它要用的索引按方块注册表实例开键，
   单凭一个 `BlockState` 答不出来（调用点只有 Jade 的服务端数据提供者，那里本来就有 `ServerLevel`）。
5. **picker 只去掉 `PickerCategory`，没回退过滤谓词**：`ItemProvider` 仍是数据表时代那份"按条目 id 过滤"的形状
   （`Predicate<Identifier>`），`CreativeTabHelper` 与探针因此不用改；`block_aura` / `heat_source` 的行仍然按
   定义展开成**方块物品**，没有回退到迁移前那种"拿一块灵石当占位"的写法。
6. **测试包**：迁移时删掉的 21 份注册表夹具按迁移前的版本恢复（内容与数据表值逐一对应），`data/mxt/data_maps/`
   整个目录删除。
7. **顺手补上的生产缺口**：本体自带数据包（`src/main/resources/data/mxt/mxt/{currency,item_aura,block_aura}/*.json`）
   从迁移那天起就没跟着改成数据表——那几张表在迁移后**读不到**（不装测试包时灵石的面值与灵气燃料会静默消失）。
   回退后这些文件重新生效，这次没有为它们新增文件。
8. **仍未做**：`ItemMatcher.find` 的解析缓存（`53` §7 / §11 的开放项）没有做，按物品查定义仍是每 tick 扫一遍注册表。
