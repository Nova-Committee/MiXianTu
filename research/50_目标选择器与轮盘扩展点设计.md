# 50 · 目标选择器与轮盘扩展点设计

> **基准**：`master` @ 本轮工作树（`2ecbccd` + 灵根多元素/子境界那一批）。动的是 `data/ability/target/`、`api/`、`runtime/wheel/`、`screen/wheel/**`、`network/payload/WheelActionC2SPayload`。
> **来源**：`research/audit/基座缺口审计.md` 的 **B2**（目标选择器只有 `self` / `area` / `js`）与 **B9**（轮盘来源页不可扩展）。
> **状态**：已落地（见文末 §6 落地记录）。

## 1. 两件事与结论

| # | 缺口 | 结论 |
|---|---|---|
| **B2** | 65 项条件之外，目标选择器只有 `self` / `area` / `js`：没有射线、锥形，也没有"最近 N / 随机 N" | 新增 `mxt:ray` 与 `mxt:cone` 两个**几何**选择器；`limit` / `order`（`nearest` / `farthest` / `random`）做成三种范围选择器**共用的筛选**。射线与锥形**不穿墙** |
| **B9** | `WheelSource` 是 5 值枚举、`WheelEntryKind` 是枚举、`WheelMenuContent.register` 单槽位、服务端 `switch` 认死三种 kind | `WheelSource` / `WheelEntryKind` 改成**接口**（放 `api/`）+ `WheelSourceTypes` / `WheelEntryKinds` 两个**代码注册表**；kind 自己拥有"按下做什么"；provider 按**来源 id** 多槽位注册；请求与存档里的来源/类型一律**传 id** |

用户拍板：B2 取"两个几何选择器 + `area` 加限量/排序"、语义取"几何 + 方块遮挡（不穿墙）"；B9 取"接口进 `api/` + 注册表 + kind 自处理"。

## 2. B2 · 目标选择器

### 2.1 形状

| 类型 | 专属字段 | 几何 |
|---|---|---|
| `mxt:self` | 无 | 施法者自己 |
| `mxt:area` | `radius`（必填，上限 128）、`include_actor` | 以行为者（或缺省原点）为中心的球 |
| `mxt:ray` | `length`（必填）、`radius`（默认 `0.5`） | 沿视线的**圆柱**，从眼睛（或缺省原点）出发 |
| `mxt:cone` | `length`（必填）、`angle`（必填，**半角**度数 0–180） | 沿视线的**锥体** |
| `mxt:js` | `id` / `params` | 服务端脚本给的列表 |

三者共用的筛选字段：`limit`（`int`，默认 `0`＝不限，负数同样不限）与 `order`（`nearest` 默认 / `farthest` / `random`）。**几何归几何、筛选归筛选**：射线与锥形也吃这两个字段，所以"最近三个"和"前方一条线"可以叠在一起写。

### 2.2 语义（一次定死）

- **排序基准是"这次激发的原点"**（`TargetSelector#select(actor, context, origin)` 的 `origin`；缺省＝行为者自己），与 `mxt:area` 原来的口径一致；距离相同时按实体 id 破平局，所以同一刻永远选出同一批人。
- **`random` 用世界的随机源洗一次牌**，不是"每个 tick 的随机子集"；它只在真的写了 `limit` 时才被问到。
- **不穿墙**：射线与锥形都先沿**视线中心线**做一次 `ClipContext.Block.COLLIDER` 裁剪，命中的方块把射程截短到方块表面。射线因此是光束；锥形是"被正前方那堵墙截短的横扫"——**锥体侧面不做逐目标遮挡判定**（写内容时不能指望"隔一道侧墙就安全"），这是刻意的：逐目标做视线检测要把锥内每个实体都 raycast 一遍，代价随锥体大小线性增长，而正前方的墙已经覆盖了绝大多数用例。
- **实体用自己整个碰撞箱判定**（`AABB#clip`），不是只看中心点：射线因此能擦到半个身子，锥形的角度则按实体中心算。
- **加载期校验**（常量）与运行期求值：`limit` 不可为负；`length` 有限且为正；`radius` 有限非负；`angle` 在 `0..180`。写成公式的到运行时才定，求值非法时这一次选择为空（与 `area` 的 `radius` 同口径）。
- `include_actor` 三种范围选择器都有，默认 `false`；被加进来的行为者按自己的距离参与排序（所以 `limit: 1, order: nearest` 会选中自己）。

### 2.3 不做

- **不做"锥体逐目标遮挡"**（见上），也不做"穿透方块"开关（用户已排除可配置穿墙）。
- **不做射线命中就停**：`limit: 1` 就是那个意思，不再加一个语义重复的 `first_hit`。
- **不给 `mxt:js` 补 `origin` 重载**：脚本选择器仍然只实现两参数 `select`，从展示台这类位置激发时会丢掉发生位置（这一条在 `基座缺口审计` 的 B2 里就记着，属已知边界）。

## 3. B9 · 轮盘扩展点

### 3.1 两个接口（`api/`）

```java
public interface WheelSource {                    // 一页
    Identifier id();
    Component displayName();
    boolean configured();                          // 是不是玩家自己摆的那一盘
    List<Identifier> grantSources(LivingEntity entity);   // 这一页由哪些授予来源拼成
    List<ItemStack> equipment(LivingEntity entity);       // 从哪几件栈上读承载物
    boolean offers(LivingEntity entity, WheelEntryKind kind, Identifier id);
}

public interface WheelEntryKind {                  // 一类格子
    Identifier id();
    Component displayName();
    boolean holdsEntry();
    boolean exists(RegistryAccess access, Identifier id);
    boolean trigger(ServerPlayer player, WheelSource source, Identifier id);
    default boolean directed(ServerPlayer player, WheelSource source, Identifier id, boolean wanted) { return false; }
}
```

- **`offers` 从服务里搬到页上**：原来 `WheelSources.offers` 用 `if (source == CONTRACT) … else if (!source.configured()) … else 读布局` 三段分支回答，现在由每一页自己回答；`WheelSources` 只留共享算术（授予账 → 可按技能列表、承载物映射、布局查找、装备页的"这一页的授予里有没有它"），内置页调用它们，第三方页想用也可以调用。
- **`trigger` 从 `switch` 搬到 kind 上**：`WheelService.trigger` 只剩"校验来源 + 交给 kind"，三个内置 kind 的实现留在 `WheelService`（包级静态），第三方 kind 写在它自己的类里。`directed`（点名一个状态）默认拒绝，只有开关那类实现它——原来那条 `if (kind != ABILITY) return false` 变成了默认实现。

### 3.2 两个注册表（`runtime/wheel`）

- `WheelSourceTypes`：`CONFIGURED` / `MAIN_HAND` / `OFF_HAND` / `CURIOS` / `CONTRACT` 五个内置页 + `register` / `byId` / `pages()`（**注册顺序即页顺序**）/ `first()` / `step(from, delta)` / `pageNumber(source)`。写法照 `ContractBehaviors`：静态块装内置项、`putIfAbsent` 让**先注册者胜**、只在游戏线程读、不加锁。
- `WheelEntryKinds`：`EMPTY` / `ABILITY` / `AURA` / `BEHAVIOR` 四个内置 kind + `register` / `byId` / `known()` / `parse(String)`。`EMPTY` 仍是一个 kind（空格子要有个类型，否则一份布局就不是十二格），`holdsEntry()` 为假。
- **显示名由实现自己给**：内置页返回 `wheel.mxt.source.<path>` / `wheel.mxt.kind.<path>`（键名与改造前一致，**两份 lang 未动**），第三方返回什么组件都行，不强加键约定。

### 3.3 网络与存储

- `WheelActionC2SPayload(source, kind, id, enabled)` 的前两个字段从"注册对象"改成 **`Identifier`**：客户端发自己手里那两个 id，服务端用 `byId` 取回。**取不回时不是解码失败，而是那一次触发被拒**（`WheelService.trigger` 收到 `null` 直接返回 false），所以内容模组加页/加类型不需要自带协议版本，也不会因为两侧注册表不同步而把连接打断。
- `WheelSlot.CODEC` / `STREAM_CODEC` 里的 kind 也从枚举换成 **id（`WheelEntryKinds.CODEC`）**，并且**读得宽容**：`artifact`（合并前的老写法）读成 `mxt:ability`、裸名字（`ability`）补上 `mxt:` 命名空间、**认不出的 id 读成 `EMPTY`**——与"服务端会把不认识的格子清成空"同一结果，而不会让整份存档解不出来。写出时一律写完整 id。
- **编号与页数仍在客户端**（`WheelMenuContent#pages` 走 `WheelSourceTypes.pages()`），服务端只按 id 认页。

### 3.4 客户端 provider 改成多槽位

`WheelMenuContent.register(source, provider)`：按**来源 id** 存一个 provider，`pages()` 逐页取；没注册的页就是空的。基座把同一个 `WheelContent` 注册到五个内置页上（它内部仍按页分支），第三方注册自己的页**不会覆盖**内置页——原来的"最后一次注册获胜"没了。

### 3.5 破坏性

- Java 侧：`runtime/wheel/WheelSource`、`runtime/wheel/WheelEntryKind` 两个枚举**删除**；`WheelSource.STREAM_CODEC` / `WheelEntryKind.STREAM_CODEC` 不再存在（两者的 id 用 `Identifier.STREAM_CODEC` 走网络，kind 另有 `WheelEntryKinds.CODEC` 用于存档）；`WheelMenuContent.register(provider)` → `register(source, provider)`；`WheelSources.equipment/offers` 的签名不变但语义变成转发。**内部只有一处外部调用点**（`WheelService` / 客户端若干），全部已改。
- 数据包侧：无字段变化（`target_selector` 只是多了两个类型与三个字段，老包照旧）。
- 存档：老布局里的 `"kind": "ability"` / `"artifact"` 照旧读得出来（§3.3），不需要迁移。

## 5. 不做 / 推迟

- **不给第三方页做"页顺序可指定"**：顺序就是注册顺序（内置先注册）。真要插到中间，可预期的方式是内容模组在自己 `register` 之前……这项先不做，接口留了口子（顺序由 `pages()` 一处决定）。
- **不做 kind 的"池子声明"接口**：配置界面仍按内置 kind 分池（灵气池 / 技能池），第三方 kind 的格子暂时进不了那两池的候选列表——它们能存、能画、能触发，但要"从界面里摆上去"还需要一个池子来源，留待有人真需要时再开（届时应该是 `WheelEntryKind` 上的一个可选池方法）。
- **不做来源的页内排序/过滤**：`limit` / `order` 是**目标选择器**的字段，与轮盘无关。
- **不给 `mxt:js` 选择器补 `origin` 重载**（同 §2.3）。
