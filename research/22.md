# MC NeoForge 26.1.2 修仙模组【底层框架规划方案】
## 前置说明
你的定位：**只搭建通用底层骨架、数据驱动、KubeJS ↔ Java双向互通**，不写具体修仙玩法（境界、丹药、功法、灵根等内容交给内容创作者）。
技术底座：NeoForge 26.1.2，Java核心逻辑 + KubeJS脚本扩展 + 全数据驱动，所有修仙实体、属性、配方、能力**尽量不在Java硬编码**。
核心目标：内容创作者只需要写JSON配置 / KubeJS脚本，不需要改动Java源码。

整体分层结构：
1. Java底层核心层（NeoForge原生，稳定框架）
2. 数据驱动配置层（JSON，资源包/数据包加载）
3. KubeJS 互操作桥接层（Java暴露API给JS，JS事件回调注入Java系统）
4. 内容扩展接口层（预留大量抽象接口，第三方/内容创作者实现）

下面分模块列出**必须预设的框架、接口、事件、数据结构、KJS绑定**。

# 一、通用基础属性框架（修仙一切系统的根基，最高优先级）
> 取代原版属性系统，或者拓展原版属性；玩家/妖兽通用。
## Java需要实现
1. **灵体数据附件（Attachment）【NeoForge推荐Attachment系统，废弃旧Capability】**
    - `SpiritData`：附加到 LivingEntity（玩家、妖兽、Boss）
    内置预留字段（全部支持数据包覆写默认值）
    - 修为进度、当前大境界、小境界（初期/中期/后期）
    - 灵力值 / 灵力上限、灵力恢复速率
    - 神魂强度、神识范围
    - 寿元、业力值、心魔值
    - 灵根实例列表（支持多灵根、变异灵根）
    - 已激活功法列表、持续BUFF（修真状态）
    - 灵压等级
2. **境界系统抽象（重点！完全数据驱动）**
    - Java仅提供抽象类 `RealmStage`，**所有境界定义由JSON数据包加载**
    JSON结构示例（数据包 `data/xxx/realm_stages/xxx.json`）
    ```json
    {
      "id": "foundation",
      "name": "筑基",
      "parent": "qi_refining",
      "break_require": {},
      "passive_attributes": {},
      "can_fly": true,
      "tribulation": "lightning"
    }
    ```
    Java职责：加载、缓存境界注册表；提供突破API；触发突破事件。
    **你不要内置炼气/筑基等，只提供加载器，内容组自己注册境界。**
3. **灵根注册表（数据驱动）**
    - 基础抽象 `SpiritRoot`，JSON定义灵根：五行灵根、变异灵根、废灵根
    属性：修炼倍率、法术增幅、天赋被动
    支持KJS动态注册新灵根
4. **属性修饰器系统**
    统一接口：来源区分【功法、丹药、装备、环境、阵法、临时buff】
    支持：瞬时效果 / 持续时效效果 / 永久效果；支持叠加规则、互斥规则。

## 需要对外暴露 KubeJS API
```js
// JS可调用
entity.spiritData.getRealm()
entity.spiritData.tryBreakThrough(breakConfig)
entity.spiritData.addCultivation(value)
entity.spiritData.setSpiritRoots([...])
entity.spiritData.consumeSpiritPower(amount)
// 事件：突破尝试、突破成功、突破失败、寿元耗尽
```

## Java 预留事件（可被KJS监听）
- `CultivationBreakEvent.Pre`（可取消）
- `CultivationBreakEvent.Post`
- `SpiritPowerConsumeEvent`
- `LifeSpanEndEvent`（寿元耗尽）

# 二、修炼机制框架（纯框架，不写打坐逻辑！只开放接口）
Java只定义流程，具体“打坐、闭关、吞丹修炼”由内容作者用KJS实现。
## 内置抽象系统
1. **修炼源环境检测框架**
    灵气区域检测器：读取区块【灵气浓度数值】
    - 区块附加数据 `BlockSpiritAuraAttachment`
    - 支持方块、多方结构、阵法动态修改区域灵气
    API：获取位置灵气浓度、灵气属性（金木水火土偏向）
2. **修炼动作抽象 `ICultivateAction`**
    预留接口：
    ```java
    public interface ICultivateAction {
        void tick(LivingEntity entity);
        boolean canStart(LivingEntity entity);
        void onStart(LivingEntity entity);
        void onStop(LivingEntity entity);
    }
    ```
    > 示例：内容创作者KJS注册【打坐修炼】【吞服灵药修炼】【闭关修炼】多种Action，Java只负责管理实体当前运行的修炼动作。
3. **丹毒积累通用容器**
    实体附件内置丹毒值；提供API查询、清除、触发丹毒爆发事件。

## KJS可做
注册自定义修炼行为，监听每tick修炼过程，自定义灵气转化效率。

# 三、功法 & 术法 & 神通 统一能力框架【极其重要】
## 设计思路
不要硬编码任何技能，做一套**通用施法系统**
## Java底层结构
1. **功法注册表 `CultivationTechnique`（数据包JSON驱动）**
    - 被动类：功法（常驻属性、灵根适配限制、功法冲突规则）
2. **法术注册表 `Spell`**
    统一施法参数：灵力消耗、吟唱时间、冷却、释放类型（弹道/区域/自身buff）、境界释放限制
    提供基础模板：弹道法术、持续区域法术、自身增益、召唤法术
3. **神通、秘术继承Spell，增加【代价标签】（燃烧寿元、消耗神魂等通用判定）**
4. **施法管理器 `SpellCasterAttachment`（附加玩家/实体）**
    - 当前吟唱状态、冷却缓存、锁定法术列表
5. **功法冲突检测框架：支持配置互斥标签，内容作者JSON配置哪些功法不能同修**

## 核心事件（KJS可拦截修改）
- `SpellCastEvent.Pre`（取消释放、修改消耗灵力）
- `SpellCastEvent.Post`
- `TechniqueLearnEvent`（学习功法）

## KJS扩展能力
允许JS编写**自定义施法逻辑**，不需要Java新增类：
```js
// KJS伪代码
SpellRegistry.register("fire_ball", {
    powerCost: 20,
    cast: (entity) => {
        // 生成火球实体、造成伤害
    }
})
```

> 你只封装法术发射、消耗校验、冷却框架；火球、水盾全部交给内容层实现。

# 四、装备 / 法器 / 法宝框架（兼容原版Item）
## Java框架部分
1. **修真物品标签系统 + 物品能力附件（ItemAttachment / ItemProperties）**
区分类型：储物、法器、飞剑、丹药、材料、阵旗
2. **祭炼框架通用接口 `IRefineItem`**
    接口预留：
    - 认主检测、解除认主
    - 温养进度
    - 灵力充能容器（法宝耐久用灵力代替原版耐久）
3. **飞剑专属抽象接口 `IFlyingSword`**
    预留：御剑召唤、飞行挂载、御剑攻击，**飞行移动逻辑封装为通用函数，外观、速度、伤害配置化**
4. **储物容器统一接口 `ISpiritStorage`**
    统一拓展背包API，不管是储物袋、储物戒，共用一套存取接口；
    你实现通用容器实现类，物品JSON配置格子数量。

## 关键特性：
所有法宝属性、最大灵力容量、温养需求写在物品JSON/标签，无硬编码物品。

## KJS
脚本可以监听物品祭炼、法宝充能、御剑启动事件，自定义特殊法宝效果。

# 五、丹药、灵药、炼丹系统框架
**只搭建流水线框架，不实现任何丹药配方！**
1. **灵药类型注册表（数据驱动）**
    定义灵药品质、年份加成、属性标签
2. **炼丹工作台抽象 `AlchemyCauldronBlockEntity`**
    预留炼丹生命周期事件：放入材料、点火、控温、成丹、炸炉
3. **丹方系统【全数据包驱动】**
    JSON丹方：材料列表、需要温度、成功产物、失败产物、所需丹炉等级、概率
4. **通用消耗品效果分发**
    丹药使用后触发效果事件，KJS监听事件添加修为、清除丹毒、恢复灵力

事件：
`PillUseEvent`、`AlchemyCraftEvent`

# 十、【重中之重】KubeJS 双向联动框架规范
## 你需要在Java侧完成：
1. **创建KubeJS Plugin模块**，向KJS注册所有自定义类、API、包装器
    - EntitySpiritWrapper
    - SpellBuilder
    - RealmBuilder
    - FormationBuilder
2. **Java事件总线全部转发到KubeJS事件总线**
    所有上面列出的自定义事件，KJS可以 `events.listen("xxx_event", e=>{})`
3. **允许KJS动态注册注册表条目**
    境界、灵根、法术、丹方、阵法 **支持运行时JS注册，叠加数据包注册**
4. **开放自定义接口注册入口**
    KJS可以注册自定义修炼动作、自定义劫类型

## 交互原则
- 重计算、同步、tick、实体数据、网络同步：放在Java
- 表现、数值微调、特殊玩法逻辑、自定义效果：下放KJS

## 网络同步约定（NeoForge）
所有实体附件（灵力、境界、修为）实现自动同步Packet；
提供简易同步Builder，内容创作者新增附加数据时可以快速注册同步包。

# 十四、模块依赖分层建议（工程分包结构，方便维护）
```
mod
├─ core // 核心附件、注册表、事件、网络包（基础必须加载）
├─ cultivation // 修炼、境界、灵气、寿元框架
├─ ability     // 功法、法术、神通施法框架
├─ artifact    // 法宝、御剑、储物物品框架
├─ alchemy     // 丹药、灵药、炼丹框架
├─ formation   // 阵法底层
├─ creature    // 妖兽、灵宠契约
├─ tribulation // 天劫、心魔通用系统
└─ kubejs-bridge // KJS桥接，依赖上面所有模块
```

# 十五、开发红线（非常适合你“只做框架”的定位）
1. ❌ 禁止Java硬编码任何：炼气、火球术、筑基丹、五行灵根具体数值
2. ✅ 所有游戏内容定义：JSON数据包 / KubeJS脚本
3. ✅ Java只负责：数据加载、生命周期管理、网络同步、碰撞、tick调度、基础校验
4. ✅ 所有拓展点使用：注册表 + 事件系统 + 接口实现
5. ✅ 所有可变数值通过配置/事件修改，杜绝写死常量
