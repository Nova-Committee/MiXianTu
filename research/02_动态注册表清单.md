## 通用约定

所有内容定义采用数据包路径 `data/<namespace>/mxt/<registry_name>/<path>.json`，其资源 ID 为 `<namespace>:<path>`。Java
启动时建立内置默认空注册表，数据包重载时原子替换快照，并向客户端同步可见定义与版本号。

每个定义至少包含：

```json
{
  "schema_version": 1,
  "id": "example:entry",
  "enabled": true,
  "tags": [
    "example:tag"
  ]
}
```

`id` 可由文件路径推导；若同时存在，加载器必须校验二者一致。引用其他定义时只保存资源 ID。数值使用有界校验；未知字段保留给扩展，不应造成整个数据包重载失败。

固有注册表与数据包注册表的协作、生命周期和两种联动模式见 `08_注册表协作规范.md`。本文件仅列出数据包定义的内容类型。

## 应通过标签而非独立注册表表达的内容

- 元素分组：`element` 注册表定义元素及关系；标签可用于表达五行、变异元素或可被某类法术匹配的元素集合。
- 流派与限制：剑修、体修、丹修、器修、符修、阵修、魔修、兽修。
- 物品分类：丹药、灵药、阵旗、灵石、储物、法器、灵宝、武器、服装。
- 生物和世界条件：妖兽、可契约、灵气富集生物群系、灵脉候选区块。

标签可被原版/第三方物品和实体复用，避免为每种武器、材料和元素组合生成注册表条目。

## KubeJS 与数据包合并规则

1. 数据包在重载阶段加载，KubeJS 在约定的注册阶段提交构建器产物；两者统一转为不可变定义对象。
2. 同一 ID 只能有一个最终定义。默认规则为数据包覆盖内置定义，KubeJS 覆盖同命名空间的脚本定义；跨来源冲突须记录明确错误，不能静默随机取值。
3. 动态定义只能变更静态配置，不能直接写入其他玩家的附件或世界状态。
4. 每个定义字段中涉及执行逻辑的部分使用固有类型的 `type` 和其 Codec 参数，或引用另一个数据包定义；不得把任意函数名字符串当作执行入口。
5. 热重载后，正在吟唱、渡劫、运行阵法的实例按 ID 重新解析；定义消失时安全中止并返还由配置标注为可返还的资源。**炼丹例外**：已开批次沿开炉时冻结的配方快照做完，不因 `/reload` 改账，也不退已投入的原料。

## 不应做成动态注册表的内容

- 附件字段、网络包、存档编码和服务端权限规则。
- 事件的生命周期顺序。
- 高频运行时实例，例如每个阵法、每次施法、每个灵宠契约。
- GUI 控件和可视化编辑器配置。
- 能力、动作、条件、触发器和状态组件的 `type`；它们是 Java 固有注册表条目，见 `05_技能系统与固有注册表.md`。
