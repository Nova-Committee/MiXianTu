# 集成测试场景矩阵

以下场景是后续测试数据包的候选集合。示例 ID、数值和名称均为测试专用，不能进入正式内容包。

| 场景 ID                     | 初始组合              | 操作                   | 预期结果                        | 主要覆盖            |
|---------------------------|-------------------|----------------------|-----------------------------|-----------------|
| `root_single_fire`        | 一条火元素灵根，无体质       | 在火偏向与水偏向区块各修炼一次      | 相同动作在两种环境按不同适配系数结算          | 元素、灵根、区块灵气      |
| `root_multi_conflict`     | 火、水两条灵根           | 学习仅允许火元素的能力，再学习水元素能力 | 两个能力各自通过/拒绝；不把灵根合并成一个虚构元素   | 多灵根、能力条件        |
| `physique_independent`    | 无灵根，剑骨体质          | 装备剑类物品并施放无元素能力       | 获得体质加成；元素克制和灵气适配不受影响        | 体质拆分、来源能力       |
| `physique_exclusive`      | 已持有骨骼类体质          | 尝试授予同互斥标签的第二体质       | 服务端拒绝或按测试定义替换，能力来源同步一致      | 互斥、附件迁移         |
| `technique_conflict`      | 两本带互斥标签的功法        | 先学其一，再学其二            | 第二次学习失败，不丢失第一本状态            | 功法冲突            |
| `ability_atomic_cost`     | `costs` 中任一资源低于主动能力成本 | 请求使用能力 | 不生成效果、不开始冷却、不扣任何资源；覆盖多资源数组与失败回滚 | 主动能力原子性 |
| `ability_multi_source`    | 功法与法宝都授予同一被动能力    | 依次卸下法宝、遗忘功法          | 第一次卸下后能力仍在；最后一个来源消失才清理状态    | 来源引用计数          |
| `curse_cross_source`      | 同一诅咒可由能力、物品和阵法施加 | 依次施加、叠层、净化，并重载其定义 | 统一按 `curse` ID 叠层和审计；净化/重载不留下孤儿实例 | 跨模块引用、生命周期、热重载 |
| `pill_toxicity`           | 可重复服用测试丹药         | 连续使用至丹毒阈值，再用解毒物      | 丹毒累积、爆发、清除和重登后数据一致          | 炼丹、持久化          |
| `artifact_owner`          | 已认主且充能的测试法宝       | 复制/掉落/由另一玩家尝试使用      | 归属与能量不被绕过；无权玩家被拒绝           | ItemStack 数据与校验 |
| `formation_chunk_cycle`   | 激活的持续消耗阵法         | 卸载再加载所在区块            | 恢复同一实例；消耗和范围不重复计算           | 阵法持久化、区块生命周期    |
| `contract_lifecycle`      | 主仆契约灵宠            | 主人传送、死亡、离线、解除契约      | 关系与召回状态按定义转换，无孤儿索引          | 契约、实体生命周期       |
| `tribulation_interrupt`   | 正在突破并进入三阶段劫数      | 断线后重连，或在第二阶段死亡       | 劫数状态只结算一次，附件和奖励不会重复         | 劫数状态机           |
| `relic_instance_exit`     | 多人进入限时测试秘境        | 一人死亡、一人超时、一人正常离开     | 成员、掉落归属和返回位置各自正确            | 实例/维度接口         |
| `cross_world_rules`       | 高阶测试境界与已激活能力      | 传送到灵气规则不同的测试维度后返回    | 附件、能力来源和物品状态保留；环境修正重新计算     | 跨维度、世界规则        |
| `registry_reload_missing` | 实体持有测试灵根、体质、能力和法宝 | 删除其中一个数据包定义并重载       | 未知 ID 被安全禁用且原始数据保留；其他定义照常工作 | 热重载、兼容          |

## 建议分层

1. 单元/编码测试：注册表解码、元素-灵根约束、体质禁用元素字段、成本与来源计数。
2. GameTest：实体附件、物品组件、事件取消、区块重载、传送与契约。
3. 数据包回归测试：加载上述场景的测试数据包，检查成功与预期失败均有清晰诊断。
4. KubeJS 集成测试：只验证通过公开 API 创建定义、监听事件和调用受校验方法；不允许脚本绕过固有 `type` 或服务端检查。
