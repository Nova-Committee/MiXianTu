# 注册表结构与引用关系图

本文汇总固有注册表、数据包注册表、原版扩展注册表与运行时状态的内容结构。箭头约定：

- `type`：数据包对象通过 `type` 字段由固有 `MapCodec` 分派。
- `ID`：一个具名数据包定义或固有行为被另一对象按完整资源 ID 引用。
- `状态`：静态定义在运行时创建、读取或解释 Attachment/Data Component 状态。

## 执行与状态引用

```mermaid
sequenceDiagram
    participant P as 玩家/实体
    participant D as 数据包定义快照
    participant A as Ability / 生命周期动作
    participant R as ResourceHolderData
    participant C as CurseHolderData
    participant S as 服务端事件与校验
    participant N as 客户端同步/HUD

    P->>S: 请求使用能力、锻打或触发事件
    S->>D: 按具名 ID 解析定义和固有 type
    D->>A: 构造动作、条件、NumberProvider
    A->>A: exp4j 计算业务数值
    A->>R: 计算 costs 并完整预检
    R-->>A: 全部可支付 / 任一项不足
    alt 成本可支付且条件成立
        A->>S: 可取消 Pre 事件
        S-->>A: 允许
        A->>R: 原子提交全部成本
        A->>C: apply_curse / remove_curse（可选）
        C->>S: 施加、叠层、到期或净化事务
        S->>N: 同步资源、诅咒、能力与显示快照
    else 不足、公式失败或事件取消
        S-->>P: 安全失败，不写入状态
    end
```

## 直接引用与 `type` 分派

```mermaid
flowchart LR
    subgraph REF["具名 ID 直接引用"]
        R1["ability: mxt_test:ember_orb"]
        R2["curse: mxt_test:soul_scorch"]
        R3["resource: mxt:spirit_power"]
        R4["forging_method: mxt_test:heavy_hit"]
        R5["固有行为: mxt:apply_forging_quality"]
    end

    subgraph TYPE["type + MapCodec 分派"]
        T1["ability.type = mxt:active"]
        T2["entity_action.type = mxt:apply_curse"]
        T3["curse.type = mxt:timed"]
        T4["amount = 字符串表达式\n-> mxt:expression (exp4j)"]
        T5["resource_bar.renderer.type\n= mxt:textured_bar"]
    end

    REF -->|"内容选择、授予、引用"| R1
    REF -->|"施加、条件、净化"| R2
    REF -->|"costs[].id"| R3
    REF -->|"蓝图允许方式"| R4
    REF -->|"固定代码路径"| R5
    TYPE -->|"结构与算法选择"| T1
    TYPE -->|"结构与算法选择"| T2
    TYPE -->|"结构与算法选择"| T3
    TYPE -->|"数值计算"| T4
    TYPE -->|"客户端绘制"| T5
```

数据包只能新增或覆盖具名定义，并选择已经存在的 `type` 与固有行为 ID；新的 Codec、渲染器、原版扩展类型和网络语义仍必须由 Java 在加载期注册。
