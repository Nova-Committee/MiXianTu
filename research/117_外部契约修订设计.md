# 外部契约修订

本稿记录 [外部开发接口与数据包审查](audit/外部开发接口与数据包审查.md) 中 A01、A03–A07、A09、A11 和 A13 的契约调整。A10 与 A12 保持当前行为。

## 载具渲染和灵气查询

载具渲染从同一次解析得到配对的定义与渲染器。客户端缺少对应实现时，以物品定义和物品渲染器组合回退。提取和提交使用同一组合。视觉物品清空时，绘制状态随之清除。

灵气解析完成时，生成包含只读池的快照。同一 tick 的查询可复用快照。调用方可复制单个池做临时计算。已加载的区块仍可在首次查询时补初始化，实际余额由维护和存取服务修改。

任意坐标的实际灵气和环境灵气查询均接收 `ServerLevel`，由服务端解析维度标签、区域覆写和区块存量。脚本保留 `MxtAura.get(level, pos)`，传入客户端世界时返回 `null`。依赖坐标查询的灵气条件在客户端判定为假。

客户端沿用现有的本地玩家同步包。Java 的 `AuraClientState.latest()` 与 KubeJS 的 `MxtAura.getLocal()` 返回最新原始采样，其中分别保留区域、实际灵气和环境灵气。已收到的空采样仍是有效结果。首次收包前、切换客户端世界或退出连接后的等待期没有采样。HUD、雾效和本地玩家的浓度提供器继续读取插值状态。

## 对外参考

Java 参考按 MiXianTu 与 Saturn 的所有权说明固有注册表、数据包注册表和扩展接口。读取定义时显式传入当前世界的 `HolderLookup.Provider`。数据包注册表随世界加载，`/reload` 重载配方、战利品表、进度、函数与服务端脚本。

通用脚本类型使用 `saturn:js`，MiXianTu 已登记的旧命名空间别名仍可用于兼容。费用示例明确区分模拟拒绝与实扣告警。详细支付接口需要包含相应实现的 Saturn 构件，示例使用当前发行依赖提供的接口。

## 支付编辑和脚本结果

原始账单按数组顺序存储事务。账户金额映射表示报价汇总。事件未改价时直接执行原账单；改价时按原条目金额占比分配新总额，各事务仍在原位置模拟并扣除。新增账户数值追加到末尾，设为零的数值条目被移除。账单仍执行重复目标诊断、逐条模拟和逐条实扣，实扣失败记录 WARN，处理继续。

Saturn 的结算结果保留已知的扣除凭据与有序的实扣问题列表。传统支付返回值沿用原有形状，详细结果和传统结果共享同一次结算。脚本通过 `getFailure()` 读取原始预检拒绝原因，需要实扣明细时调用 `consumeDetailed`。对单条费用可用 `checkResult` 获取预检结果。一次调用对应一次支付尝试。

## 事件数据

Java 事件的附件、阵法实例和物品堆 getter 返回发布时的独立副本。突破的进度、境界、资源表及灵魂体的状态提供读接口。费用的修改通过前置事件的 setter 表达。KubeJS 阶段名由转发处显式指定，保留已有字符串。灵气区事件提供世界和坐标，进出时还提供实体。诅咒后置事件提供结算后的层数和本次来源。

## 生物档案和公式引用

生物档案新增 `priority`，默认值为 `0`。候选按优先级降序排序，同分沿用 ID 路径、命名空间的升序。候选逐一判断，找到有效条目即应用。

生物档案、法器、热源和同层级静态灵气区共用此排序。灵气区先确定来源层级，方块自身的动态供热仍优先于热源数据表。作者可用 `/mxt match` 查询四类定义的实际选择。生物档案查询使用当前条件并记录选中前的回退原因，不会应用档案或执行生成动作。

公式可用 `caster_ID_<kind>_<hex>` 或相应的 `target_` 名称精确引用条目。`kind` 为 `resource`、`attribute` 或 `element`，`hex` 是完整 ID 的 UTF-8 十六进制。旧名在同一表内发生冲突时失效，日志给出每个条目的准确写法。各表通过类别区分精确名。

## 集成
