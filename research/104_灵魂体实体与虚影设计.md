# 104 灵魂体实体与虚影

## 范围

支持所有 `LivingEntity`，包括玩家。通过死亡事件、显式服务和管理员命令生成，死亡自动生成由默认开启的服务端配置控制。灵魂体保存生成瞬间的完整可序列化实体数据；不恢复身体、不移交物品、不执行复活。

## 数据与生命周期

- 复用 `mxt:soul` 实体和源实体的 `SoulAttachment`，不新增另一套魂体状态。
- `SoulSnapshot` 保存原类型、原始 NBT、玩家档案和外观尺寸。原始 NBT 包含名称、装备、背包、属性及可序列化附件；玩家惯用手与皮肤外层开关另存为外观设置，弥补原版玩家 NBT 不保存这些客户端选项的边界。不承诺原版实体存档之外的外部数据库、玩家统计和进度。
- 快照在 `SoulAttachment.activate` 之前取得，读写 NBT 都复制，避免保留原实体引用或让后续修改污染快照。
- `SoulAppearance` 只同步原版会同步的实体元数据、装备、玩家档案和尺寸；完整 NBT 不发送给旁观者。
- 存档重新加载时，用原始 NBT 构造一个不入世界、不 tick 的临时源，重新提取外观；临时源不恢复附件、队伍或乘客关系。未知类型和加载失败保留快照，显示通用虚影。
- 灵魂体不运行原生物 AI，不受伤、不掉落、无重力、不碰撞，不进入原版传送门，不强制加载区块；重载清除旧外观缓存并归零速度。
- 同一源实体存在活跃记录时拒绝重复生成。生成被取消或实体加入世界失败时，不激活源记录；服务拒绝客户端调用并防止事件重入。
- 回收沿用显式清理含义，不把快照倒灌回源实体。带有实体 UUID 的记录仅在该魂体已加载、来源匹配时回收，避免清空记录后留下卸载中的孤儿实体。

## 死亡生成与超时

服务端配置 `souls.spawn_on_death` 默认 `true`，`souls.lifetime_ticks` 默认 `6000`，范围为 0–2147483647，`0` 表示永久。前者只控制死亡入口，后者适用于所有灵魂体，并在运行时读取当前值。

死亡监听使用 `LivingDeathEvent` 的 `LOWEST` 优先级，跳过取消事件，经同一 `SoulService.transfer` 生成；快照在原版清理装备和背包掉落前取得，不改变死亡与掉落规则。已有有效关联时拒绝再次生成。

超时不引入调度器、后台线程、扫描表或额外存档字段。生成时把主世界游戏时间写入已有 `created_at`；`SoulEntity.tick` 在服务端比较当前主世界游戏时间与生成时间，到达保留时长就删除。区块卸载和玩家离线期间仍计时，服务器停机不计时；卸载中的魂体由重载后的首次 tick 清理。缺失时间戳的直接召唤实体在首次 tick 初始化时间。

到期时只按 UUID 清理已加载原实体上仍指向本魂体的记录，避免旧魂体抹掉新关联。未加载原实体在入世界、玩家登录或显式生成/回收时按同一时间规则清理，不强制加载实体或区块；玩家复活沿用附件复制行为。超时属于自动清理，不走可取消的回收事件，保存的快照随魂体删除，不回写物品。

## 虚影渲染

客户端为每个已加载魂体缓存一个外观代理；代理不加入客户端世界，也不调用 `tick`。每帧只更新位置、方向和视觉年龄，再通过原实体渲染器提取状态。

使用局部提交收集器把模型提交转换成同一套半透明、偏青白的虚影。普通生物主模型沿用自身纹理；附加模型及特殊渲染器的模型使用统一浅色轮廓。源渲染器保留缩放和模型变换，不修改共享模型、原版渲染器或原版管线。

阴影、火焰、名字、拴绳、独立粒子和物品提交不带入虚影，防止出现不透明装备或额外特效。装备数据完整保留，首期虚影以身体轮廓为主。完全自行绘制且不提交模型的第三方渲染器使用通用虚影；不声称兼容任意模组自定义 GPU 路径。

渲染状态只保存本帧代理提取后的状态，不把真实源实体放进跨帧全局缓存。代理缓存随魂体卸载释放，资源重载后重新查询当前渲染器。玩家使用保存的档案独立解析皮肤，不依赖原玩家在线。

## 显式入口

- `SoulService.transfer(entity, source)`：既有 Java 入口，返回是否成功。
- `/mxt soul create [targets]`：默认自己，2 级管理员权限。
- `/mxt soul reclaim [targets]`：默认自己，清除目标的已加载魂体与活跃记录。
