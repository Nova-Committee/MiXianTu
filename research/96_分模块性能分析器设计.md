# 96 分模块性能分析器设计

## 当前实施范围

已经实现 `util.profiling` 内的 profiling 核心，与 `LoggerDispatcher`、`LoggingLevel` 同包，并在此基础上接入服务端业务 Source、服务器生命周期、`/mxt debug` 命令、AUI 列表图表与 GUI 订阅。GUI 视觉效果与真实多人联机行为尚未实跑验证。

已实现：实例隔离、普通模式默认关闭且开发模式启动时自动开启、线程本地嵌套采样、集中提交守卫、有界批次队列、单消费者、每生产者最近 240 tick 原始窗口、按需不可变快照与统计、开关生命周期，以及固定 32 个服务端 Source 的接入。按用户要求不接入客户端渲染，也不为 Condition、Action、公式、Matcher 等高频基础调用建立独立 Source。

## 采集口径

- 每个服务器生命周期或独立诊断会话拥有自己的 `Profiler` 实例；构造不启动线程。集成服务器采集服务端线程，客户端渲染交给 spark，不建立客户端采样实例。
- 一个 source 表示一个命名采样点，由拥有者在初始化时调用 `profiler.sources().register(id)` 得到并缓存。同实例内相同 id 返回同一个对象，注册不在高频采样路径中发生。
- `System.nanoTime()` 测的是经过时间，包含调度等待与 GC 停顿，不是 CPU 时间。另一构造器允许提供单调的纳秒时钟，探针用它做精确数字断言。
- 同一线程的 scope 按栈语义嵌套，使用 try-with-resources 在异常出口配对。语言不会强制调用者使用这种写法，核心仍须处理漏关、重复关闭和乱序关闭。
- 每个 source 的耗时包含其嵌套子 scope。嵌套 source 的数值不能直接相加冒充本模组总耗时；将来需要总计时应单独选择不重叠的外层边界。
- `flushTick()` 的调用线程决定生产者身份；每次调用提交一个完整 tick，包括没有 span 的零样本。调用者必须在自己的 tick 边界调用一次，核心不猜测 MC 的事件时序。
- 多生产者各有独立 tick 序号与 240 格窗口；它们不自动对齐，也不能把并行线程耗时之和当作服务端 TPS。仅有 ThreadLocal 不等于已兼容任意多线程 tick 模组，实际接线仍需核实各线程的边界。

## 核心 API 与数据流

```java
try (Profiler profiler = new Profiler()) {
    ProfilerSource source = profiler.sources().register("example:work");
    profiler.setEnabled(true);
    try (var _ = profiler.scope(source)) {
        // Work runs on this producer thread.
    }
    profiler.flushTick();
    profiler.snapshot().thenAccept(snapshot -> {
        // Read raw samples or explicitly request statistics.
    });
}
```

示例说明核心用法；本体业务使用下文的 `ServerProfiling` 出口，不在调用点临时注册 Source。

### 线程本地采集

栈用 token 与开始时间两个 long 数组，关闭时按独立 token 确认仍为对应的栈帧。原始记录用 `int[] sourceIds` 与 `long[] durations` 两个并行数组，不创建逐条 Span、StartEvent 或 EndEvent。

开启时每个 scope 创建一个独立的小句柄，保证旧句柄、重复 close、开关切换后的 close 都不能关闭后来复用的栈位置。没有复用可逃逸的 AutoCloseable 句柄，也不声称开启路径零分配。关闭时直接返回共用 Noop，不创建线程本地采集状态。

采样上限：嵌套深度 128，单生产者单 tick 最多 16,384 条 span。超过预算只丢该部分并计数，该 tick 标为不完整，不让诊断功能中断业务。跨 tick 未关闭的 scope 在 flush 时废弃，随后旧 close 不能污染下一 tick。跨线程 close 不写原线程状态；调用者仍须在打开线程正确关闭。

### 集中提交与异步聚合

`flushTick()` 把一次完整 tick 的数组有效区复制成独立批次；采集数组随后继续复用。消费线程绝不持有仍在被采集侧修改的数组。

提交入口再次检查会话是否有效，关闭的会话直接丢弃传入内容。采样侧的快速返回只是降低开销，不能替代提交边界的守卫。队列通过原子容量预留限制为最多 64 个待消费批次，满时整批丢弃并计数，不在 tick 线程等待消费者。容量不足时不先复制数组，也不扫描队列计算 size。

每个已启用的实例有一个守护消费线程；空闲时 park，提交、查询和停止时 unpark，不做周期空轮询。消费线程独占所有可变窗口，消费只把同 source 的纳秒数和命中次数相加，不计算分位数、不格式化文本。

### 240 tick 窗口与按需查询

窗口固定 240 tick，未满时仅包含实际开始采集后的范围，不补齐虚构的启动样本。每格带真实 tick 序号，回绕使用取模；不能对 240 使用只适用于 2 的幂的位掩码。

无 span 但成功提交的 tick 是有效零值。队列丢批留下的序号缺口与部分丢弃的 tick 是不完整样本：图表应显示缺口，统计不把它们当零值。快照同时提供整批丢弃数、窗口内丢弃 span 数与每格完整标记。

`snapshot()` 返回 CompletableFuture：消费者在处理已排队的批次后复制当前原始窗口，再交出不可变快照。没有查询者时不构建快照，也不逐 tick 复制整个窗口。将来的集成服务器可以在同进程直接用此出口读取；不能在生产者 tick 上阻塞等待查询，更不能在消费者自己的回调里阻塞等待另一次查询。

快照仅暴露不可变元数据与逐格数值，不暴露内部可写数组；后续采集、注册新 source 或关闭会话都不会修改旧快照。新 source 对更早的有效 tick 读作零。

只有显式调用 `producer.statistics(source)` 才计算 min、avg、max、50%、95%、99% 与命中次数。统计基于有效的逐 tick source 总耗时，包含有效零值，不是单次调用耗时的分位数。分位数使用排序后的 nearest rank：索引为 `ceil(p × n) - 1`；零个有效样本返回样本数 0，上层应展示无数据。

### 开关与生命周期

实例默认关闭。开启建立独立代际的会话；关闭立即断开该会话，停止消费线程，未完成查询以空快照结束。每个线程下一次进入时自行识别代际并清理本地旧状态，不由控制线程跨线程改写 ThreadLocal 数组。

`releaseThread()` 可在生产者退出时移除其本地缓冲；批次只包含生产者编号和名称，不把 Thread、实体或世界对象传到消费者。拥有者停止时必须 `close()`，关闭后不能再次启用。

## 服务端接线与 Source

`ServerProfiling` 在 `ServerAboutToStartEvent` 为当前服务器创建实例，一次性注册固定 Source，并通过统一开关按 `MiXianTu.isDevMode()` 设置初始状态：开发模式自动开启，普通模式关闭。该判断包括开发启动环境与正式环境开启调试配置的情况；只在服务器会话启动时应用，`/mxt debug off` 后不会逐 tick 自动重开。通用 `Profiler` 构造仍默认关闭。在 `ServerStoppedEvent` 解除拥有关系并关闭实例，不同世界会话不沿用窗口、开关或 source 对象。

生产埋点只接纳当前服务器主线程：客户端渲染线程和后台工作线程直接返回 Noop，不提交无法确定 tick 归属的样本。核心的多生产者能力仍然保留，但这次接线不宣称支持并行维度 tick；要支持它必须另外验证各维度线程的完整 tick 边界。

在 `ServerTickEvent.Post` 的 LOWEST 优先级统一调用一次 `flushTick()`，不是每实体、每世界各提交一次。空闲 tick 仍提交有效零值，窗口表示最近 240 个已完成服务端 tick。没有包住整服 tick，因此不存在把原版或其他模组的全部 tick 误算为本模组总耗时的项目。

每个 Source 只累计当前调用栈中最外层的同名 scope，防止公共服务的多层包装与递归调用重复计算。子 Source 单独进入时自动打开父 Source，进入已有父 scope 时复用父范围。父子关系如下表所示，不依赖字符串前缀推断。父项与子项、不同业务模块的嵌套调用依然可能重叠，不能相加当总耗时。

去重状态随开关代际与 tick 边界清空；句柄保存自己的代际，旧句柄关闭不能清掉新范围的去重标记。所有业务范围使用 try-with-resources，原有返回值、失败路径与异常传播保持不变。

## 命令与 GUI

### 命令

- `/mxt debug on|off`：控制当前服务器实例的总开关，普通模式默认 off，开发模式启动时自动开启；整个 debug 分支要求 3 级管理员权限（`COMMANDS_ADMIN`），不改变其他命令的权限。
- `/mxt debug status [sources...]`：已接入，类似 `/tick query`，查询最近 240 tick；sources 省略时列出所有固定 Source，多项使用空格分隔，并提供补全。显示 min、avg、max、50%、95%、99%、调用次数、有效样本数与丢弃诊断。

status 标题只显示窗口与丢弃批次，不附带父子耗时相加的说明。耗时数字与图表共用阈值：低于 10 ms 绿色、10–50 ms 黄色、至少 50 ms 红色；窗口、调用次数与有效 tick 数用青色，丢弃计数为零时绿色、非零时红色，标签与单位保留默认颜色。
- 分位数仅在指令请求时现算；GUI 只在消费新快照或改变排序时按需计算 min / avg / max，不在 tick 或异步聚合循环中维护统计。
- 查询通过异步快照出口取得已完成 tick，回到服务器线程后重新检查玩家当前权限与连接归属，再计算和输出统计，不在 tick 线程等待消费者。尚未提交样本时显示无数据；不为本次查询额外 flush。
- `/mxt debug gui`：仅玩家可用，授权当前连接打开 GUI。打开界面不改变 profiler 开关。

### AUI 界面

使用现有 AuiScreen / AuiPages / AuiScrollList，资源放在 `assets/apricityui/apricity/mxt/profiler/`。界面以列表为主体：左侧为 source 名与 min / avg / max，右侧为对应的最近 240 tick 图表，柱形观感参考原版 F3+2 的 fps/tps 图表。界面不暂停集成服务器。

全部 32 个固定 Source 使用 `mxt.profiling.mxt.<category>` 翻译键，category 保留原路径中的下划线，将 `/` 转为 `.`，例如 `mxt.profiling.mxt.resource`、`mxt.profiling.mxt.aura.query`。采样与命令 ID 保持不变；未注册或缺少翻译的条目回退显示原 ID。可选择本地化名称、min、avg、max 排序并切换升降序，默认 avg 降序。

纵轴从零开始，避免把微小变化画成满幅波动。图表固定 240 × 32 px，与 Canvas 原始尺寸一致，每 tick 一列，不随窗口宽度拉伸。纵轴最大值以 `N ms` 标在图表左侧顶部，不在行上方重复显示范围。页面居中：宽窗口使用 504 px 面板、472 px 行宽和 38 px 行高；窄窗口使用 320 px 面板、288 px 行宽和 64 px 行高，将名称与摘要排到图表上方。缺失数据画空隙，保留有效零值。只更新可见列表行；不因为每帧渲染而重算统计或重建整个页面。

Source 区域独立竖向滚动，顶部标题、状态和排序按钮保持固定。行元素必须绝对定位，使 Java 写入的 top / left 生效；缺少定位会导致行内的绝对定位文本与 Canvas 共同锚定到列表根而重叠。滚动条复用 AuiScrollList 的条目与偏移，支持滚轮、点击轨道和拖动滑块；按整行对齐，只显示完整行，避免覆盖固定区，并确保最后一个 Source 能到达。

页面皮肤使用公共主题，图表使用 AUI Canvas；每个可见行只在切换条目或取得新快照后重画画布，不创建数千个柱形 DOM 节点。纵轴上限按本行最大值向上取整到毫秒、至少 1 ms；绿色 / 黄色 / 红色分别表示低于 10 ms、10–50 ms、至少 50 ms，紫色顶部标记表示不完整 tick。有效零值保留在零基线。不提供悬停提示，每行只显示一套 min / avg / max 摘要，分位数仍只在命令中计算。底部提示为“更准确的分析请使用 spark 模组”，不再放置紫色标记的说明。

画布每次重画先用 `AlphaComposite.Src` 完整替换 240 × 32 px 的半透明背景，再恢复 `SrcOver` 绘制当前样本；不能把半透明背景反复叠到旧图上，否则新快照、排序或滚动复用行时会留下逐帧变淡的旧柱子。栅格绘制关闭抗锯齿，坐标与柱宽保持整数。

最终纹理采样使用客户端 `ApricityCanvasMixin`：让 Canvas 尊重与 AUI 图片一致的显式 `blur="false"`，24 张 profiler 图表均使用该属性，最终 sampler 选择 `FilterMode.NEAREST`。没有显式关闭平滑的 Canvas 保留原行为。图表缓冲保持 240 × 32 px，画布内部的完整背景替换与关闭抗锯齿继续保留。

`image-rendering: pixelated` 的纯 CSS 对照方案已结束，按用户反馈与要求恢复 Mixin，并移除无效的 CSS 声明。隔离验证表明当前依赖 ApricityUI 1.2.8 的样式层没有实现该属性：普通样式表、`!important` 和内联声明都会将其作为不支持的属性忽略，并输出 `[AUI CSS] unsupported property ignored`；Canvas 的最终绘制固定传入 `blur=true`，没有读取这个 CSS 值。直接运行已安装 Jar 的真实 Style 解析与级联逻辑，并检查同一 Jar 的 Canvas 字节码，12 个隔离断言通过；只适配日志出口，没有启动游戏或 GPU。

### 数据读取

- 原版参考：`IntegratedServer.getTickTimeLogger()` 直接返回 `Minecraft.getDebugOverlay().getTickTimeLogger()`；服务端每 tick 写入同一份 240 格 `LocalSampleLogger`，`DebugScreenOverlay` 渲染 TPS 图表时直接读它，不经过远程样本包，也不受发包间隔影响。本模组沿用进程内共享读取的路径，但跨线程发布不可变快照，不让 GUI 直接遍历聚合器的可变窗口。
- 单人直读：仅未开放局域网的集成服务器走本地路径；GUI 已确认订阅时，每个服务端 tick 请求一次最新不可变快照，客户端每个渲染帧读取已发布引用，仅当序号变化才重算摘要与更新行，不受 5 tick 的发包周期或客户端 tick 取数时机限制。异步聚合最多保留一个在途请求，不阻塞 tick / 渲染线程，消费未完成时继续显示最近已发布快照。订阅确认 / 心跳 / 取消也直接排到服务器线程，不发送 profiling 快照数据包。打开 GUI 的小型控制消息仍使用现有网络通道。
- 多人订阅：专用服与已开放局域网的集成服务器均走网络路径（包括局域网房主）。每 5 个服务端 tick 共享一次异步快照；没有已确认订阅时不请求快照、不构造数据包。打开 GUI 后才确认开始，关闭时取消；客户端每 20 tick 续租，60 个服务端 tick 未续租则清除。5 tick 为当前实现值，后续可根据实测调整。
- 授权和清理：命令授予随机 token，绑定玩家 UUID、当前服务器会话与玩家连接对象；未确认的授权不发送数据。服务端每 tick、每次发布与异步完成时验证订阅、权限和连接；撤销权限时关闭界面。旧 token 的心跳、取消和快照不能影响新 GUI。单人服务器开放到局域网时重新授权并切换网络路径。
- 接收端只接纳当前 GUI、当前连接、相同 token、递增序号且拥有 3 级权限的数据。关闭后迟到数据丢弃；序号独立于采样开关，off / on 后不会复用旧窗口。开关修订号阻止异步旧快照在重启采样后回流。停用时只更新空窗口与关闭状态，不复制采样内容。
- 网络编码保留原始窗口与有效标记，解码后复用同一快照统计实现。限制 64 个 Source、4 个生产者、每生产者 240 tick、合计 16384 个 Source×tick 单元；字符串最多 128 字符，拒绝负数、重复 Source 和越界长度。固定 32 Source、单生产线程处于限制内。handler 位于解码之后，拒收不代表跳过解码。
- status 仍在服务端按指令计算并返回文本，不建立 GUI 订阅。
