# 鉴定镜设计

## 改造前的行为

鉴定镜右键遍历玩家物品栏，把首个可解析的 `mxt:identification` 物品堆替换成 `result` 指定的物品。它沿用原堆数量，但直接新建物品堆，没有校验结果的堆叠上限，也无法指定结果的品质、能力或功法组件。运行时代码和随包数据均未发放带鉴定组件的物品，鉴定镜仍在未完成物品表中。 [当前交互](../src/main/java/com/iafenvoy/mxt/item/IdentificationMirrorItem.java) · [当前组件](../src/main/java/com/iafenvoy/mxt/data/item/IdentificationComponent.java) · [早期清单复核](audit/早期模块清单实现复核.md)

## 玩家操作

玩家主手持鉴定镜，副手持待鉴定物品，对空气右键。每次鉴定一件，成功时在行动栏显示结果名称。副手只剩一件时，结果直接替换副手中的物品。副手多于一件时，鉴定后把结果放入物品栏，余下物品留在副手。物品栏没有可用空间时，保留整堆并提示腾出空间。

待鉴定物品的提示框显示「未鉴定」和使用提示。镜子可重复使用，首版鉴定免费。交互使用现有右键入口，服务端根据当次操作的双手物品执行结算。

## 组件和投放

沿用 `mxt:identification.result` 的物品 ID，新增可选的 `result_components`，复用原版的组件补丁格式。每个组件对应一件成品，成品使用自身的默认组件和显式补丁。封装载体上的名称和描述由内容包配置，成品的名称和品质等信息可写在补丁里。品质依旧通过 `mxt:quality` 及现有品质系统生效。

| 字段 | 含义 |
| --- | --- |
| `result` | 结果物品 ID。使用时在物品注册表里查询，已有只写 ID 的组件可以继续读取。 |
| `result_components` | 可选的结果组件补丁，例如 `mxt:quality`、`mxt:technique` 或 `minecraft:custom_name`。空缺时使用结果物品的默认组件。 |

内容包可以选任意普通载体，也可以使用本体的 `mxt:unidentified_item`，由内容包决定投放地点与成品。随机战利品使用原版战利品池生成载体，通过 `minecraft:set_components` 把各自的固定结果写到堆上。需要发放固定产物的配方或脚本也写同一个组件。随机选择发生在投放时，鉴定操作读取已经确定的结果，关游戏、再次鉴定或换人鉴定都沿用该结果。

下面是战利品表 `functions` 数组中的一个条目。示例给载体绑定一件已有损耗的铁剑。

```json
{
  "function": "minecraft:set_components",
  "components": {
    "mxt:identification": {
      "result": "minecraft:iron_sword",
      "result_components": {
        "minecraft:damage": 12
      }
    }
  }
}
```

## 结算与失败

1. 从副手读取组件，解析物品 ID，再将补丁应用到数量为 1 的成品。
2. 校验成品与组件组合。目标不存在、成品为空或成品仍携带鉴定组件时返回配置错误，保留输入。用于标明「未鉴定」的通用载体也应拒绝作为成品。
3. 副手只有一件时直接替换。副手有多件时，使用原版物品堆叠规则检查一个可用位置，确认一个成品成功放入后扣除一件。创造模式和生存模式执行相同的鉴定步骤，满包都返回失败。

首版的结果随物品组件同步到客户端，普通提示框只展示未鉴定状态。能够读取物品数据的客户端也能读到结果。若内容需要在客户端层面隐藏结果，应把投放时已决定的结果存在服务端，客户端只同步显示所需的标记。
