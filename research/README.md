# research/ —— 设计稿存档

**这里是本仓库放设计稿的地方——只有大改（新模块、换形状的改版、跨模块重构）或用户明确要求先设计时才写稿。**

代码只回答"现在是什么样"，`docs/` 回答"怎么用"，而**为什么这么设计、当时否掉了哪些方案、边界在哪里**
只活在这个目录里。所以真要做这类改动时先在这里落一份档；日常小改、修 bug、改名、拆包、加字段、文档同步
**不写稿**——结论留在代码注释（硬约束）与 `docs/`、[`AGENTS.md`](../AGENTS.md)（约定）里即可。没有留档的大改过一个版本就查不回来了。

**先看下面的[目录](#目录)。** 它按主题列出每份稿的一句话主旨与当前状态：**"这篇还能不能信"
看状态列；完成度永远以代码为准（两份 README 的「模块完成情况」表是汇总），不以研究稿为准。**

## 什么时候必须写

- **大改**：新增一个模块、注册表、系统，或对现有系统做**换形状**的改版（哪怕最后没做）。
- **用户明确要求先设计**（说"先写份设计稿 / 方案"就是）。
- 做出会影响数据包格式、公开 API 或运行时语义的决定——包括**推翻**以前的设计。
- 真做过一次系统普查式的审计（结论放 `audit/`）。

不需要写，也别为一个改动顺手补一篇：修 bug、改名、拆包、加字段、补一句 Javadoc、文档同步、纯结构调整这类日常改动。
它们的结论写进代码注释（硬约束）与 `docs/`、[`AGENTS.md`](../AGENTS.md)（约定）即可；**一次改动不等于一次审计**。

| 内容                    | 位置          | 命名                                                    |
|-----------------------|-------------|-------------------------------------------------------|
| 设计稿 / 方案 / 改版         | 本目录根下       | `NN_<主题>设计.md`，`NN` 取当前最大编号加一                         |
| 实现说明（已经落地的机制怎么跑）      | 本目录根下       | `<模块>实现.md`（如 `裂缝渲染实现.md`；`方块灵气实现.md` 沿用这个名字，内容是提案留档） |
| 审计与差距清单               | `audit/`    | 按模块或主题命名（`technique.md`、`formation.md`、`基座缺口审计.md`…） |
| 测试设定参考                | `测试设定参考/`   | 场景矩阵、常见设定与来源记录                                        |
| 研究用的脚本与配图             | 本目录根下       | 与它服务的文档同名（`aura_subchunk_value.py` / `.png`）          |
| 外部工程阅读（Immortal 等）    | `immortal/` | `<主题>.md`（如 `傀儡与符文编程.md`），**不占编号**                    |
| 清单 / 备忘 / 原始素材（不是设计稿） | 本目录根下       | 中文名说清是什么（`原始需求清单.txt`、`备忘录.md`），**不占编号**              |

写进去的稿子要能独立读懂：**基准**（对着哪份代码/文档写的）、**结论**、**与现状的差异**、**不做或推迟的部分**、**验证方式**
。设计被推翻时不要删旧稿，在原文上标注"已于 <日期> 被 <新稿/提交> 推翻"并写清新行为——旧结论同样是资产，`audit/` 里就是这么做的。

## 与其他目录的分工

| 目录                                                                 | 放什么                                              | 不放什么                                                   |
|--------------------------------------------------------------------|--------------------------------------------------|--------------------------------------------------------|
| `research/`（这里）                                                    | 设计意图、方案对比、审计结论、推翻记录                              | 面向使用者的字段说明                                             |
| `docs/`                                                            | 数据包 / KubeJS / Java 的用法文档，字段级权威在 `docs/数据包格式.md` | 未定稿的设想                                                 |
| 文档站仓库（[`IAFEnvoy/mxt-docs`](https://github.com/IAFEnvoy/mxt-docs)） | 玩家看的整理与教程（中英）                                    | 设计过程                                                   |
| `src/main/java`                                                    | 实现                                               | "为什么"（属于这里与 `docs/`；类注释只留结论与硬约束，见 `AGENTS.md` §4 注释三律） |

数据包字段一旦定稿，说明进 `docs/数据包格式.md`；玩家侧的说法进文档站；**设计过程留在这里**。仓库根目录的 [
`AGENTS.md`](../AGENTS.md) 有完整的开工约定。
