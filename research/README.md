# research/ —— 设计稿存档

**这里是本仓库放设计稿的地方：任何新设计、重构方案、系统改版，动手写代码之前（或同时）都要在这里留一份档。**

代码只回答"现在是什么样"，`docs/` 回答"怎么用"，而**为什么这么设计、当时否掉了哪些方案、边界在哪里**只活在这个目录里。没有留档的设计过一个版本就查不回来了，所以这条是硬要求，不是建议。

## 什么时候必须写

- 新增一个模块、注册表、系统，或对现有系统做改版（哪怕最后没做）。
- 做出会影响数据包格式、公开 API 或运行时语义的决定——包括**推翻**以前的设计。
- 一次审计得出了结论：现状与设计不符、字段没有消费者、某处实现与文档矛盾。

不需要写：改错别字、加断言、修单个 bug、补一句 Javadoc 这类局部改动。

## 放哪里、怎么命名

| 内容 | 位置 | 命名 |
| --- | --- | --- |
| 设计稿 / 方案 / 改版 | 本目录根下 | `NN_<主题>设计.md`，`NN` 取当前最大编号加一（现到 `23_法器数据重设计.md`，下一个是 `24_`） |
| 实现说明（已经落地的机制怎么跑） | 本目录根下 | `<模块>实现.md`（如 `方块灵气实现.md`、`裂缝渲染实现.md`） |
| 审计与差距清单 | `audit/` | 按模块或主题命名（`content-coverage-gaps.md`、`technique.md`…） |
| 测试设定参考 | `测试设定参考/` | 场景矩阵、常见设定与来源记录 |
| 研究用的脚本与配图 | 本目录根下 | 与它服务的文档同名（`aura_subchunk_value.py` / `.png`） |

> 编号 `24_` 曾用于 `24_护符槽位设计.md`（Curios 内置 `charm` 四格），该文档已于 2026-09-21 整体并入 [`23_法器数据重设计.md`](23_法器数据重设计.md) §11 并删除，所以 `24_` 这个号可以复用。

写进去的稿子要能独立读懂：**基准**（对着哪份代码/文档写的）、**结论**、**与现状的差异**、**不做或推迟的部分**、**验证方式**。设计被推翻时不要删旧稿，在原文上标注"已于 <日期> 被 <新稿/提交> 推翻"并写清新行为——旧结论同样是资产，`audit/` 里就是这么做的。

## 与其他目录的分工

| 目录 | 放什么 | 不放什么 |
| --- | --- | --- |
| `research/`（这里） | 设计意图、方案对比、审计结论、推翻记录 | 面向使用者的字段说明 |
| `docs/` | 数据包 / KubeJS / Java 的用法文档，字段级权威在 `docs/数据包格式.md` | 未定稿的设想 |
| 文档站仓库（[`IAFEnvoy/mxt-docs`](https://github.com/IAFEnvoy/mxt-docs)） | 玩家看的整理与教程（中英） | 设计过程 |
| `src/main/java` | 实现 | "为什么"（那属于这里，或类注释） |

数据包字段一旦定稿，说明进 `docs/数据包格式.md`；玩家侧的说法进文档站；**设计过程留在这里**。仓库根目录的 [`AGENTS.md`](../AGENTS.md) 有完整的开工约定。

> `audit/` 里的旧结论常引用 `docs/通用物品.md:23`、`docs/灵气环境数据包.md:84` 这类**当时**的文档行号作证据。那 5 篇迁移前的散篇已于 2026-09-21 从 `docs/` 删除（内容并入 `docs/数据包格式.md`、`docs/guide/**` 与文档站，清单见 [`docs/README.md`](../docs/README.md)），所以这些引用指向的文件已经不在了——**结论按当时的证据成立，不必回头改**，要复核就看代码与现行文档。
