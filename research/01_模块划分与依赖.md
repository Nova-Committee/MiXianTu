# 模块划分与依赖

## 工程模块

建议先按包拆分；规模扩大后可直接映射为 Gradle 子模块。模块只能依赖其下游模块，禁止反向依赖。

```text
core
├─ data                 数据包加载、热重载、注册表同步、标签
├─ builtin_registry     Java 固有类型注册表、Codec 分发及原版注册表接入
├─ attachment           实体/物品/区块/世界持久化数据与版本迁移
├─ event                可取消事件、后置事件与 KubeJS 转发
├─ network              客户端快照与服务端请求校验
└─ common               ID、数值、范围扫描、多方块、区域效果等工具

cultivation             境界、元素、灵根、体质、灵力、寿元、修炼动作、丹毒
resource                通用资源定义、资源持有者、消耗事务、资源条配置与 HUD 渲染协作
curse                   诅咒定义、实体/物品诅咒实例、叠层/持续时间、施加与净化事务
ability                 统一能力、触发器、动作/条件、状态组件、冷却、目标选择
artifact                法器/法宝、祭炼、灵力容器、储物、飞剑
forging                 锻打会话、数值条、末尾序列、最优步数与品质结算
alchemy                 灵药、丹方、炼丹流程、消耗品效果
formation               阵旗/阵盘、结构检测、活跃阵法与区块回调
creature                妖兽资料、内丹掉落、契约、灵宠协作
tribulation             劫数生命周期、区域威胁、心魔和业力
world                   灵脉、区块灵气、环境偏向、维度接入点
integration             Curios、救援/复活类模组及可选兼容
kubejs_bridge           包装器、构建器、脚本注册和事件桥接
client                  HUD、容器和渲染数据消费；不得保存权威状态
```

## 必要模块职责

| 模块 | 必须提供 | 不应承担 |
| --- | --- | --- |
| `core` | 生命周期、固有/数据包注册表、附件基类、网络、事件、数据迁移 | 任何具体修仙内容。 |
| `cultivation` | `SpiritData`、元素/灵根/体质管理、突破流程、灵气读取、修炼动作调度 | 打坐/闭关等具体收益公式。 |
| `ability` | 能力授予与撤销、触发器、主动使用、条件/动作组合、状态组件、冷却和资源校验 | 火球等固定能力定义，也不得为每个玩法另建技能系统。 |
| `artifact` | 祭炼、归属、充能、储物接口、飞行通用控制 | 固定法宝外观和属性。 |
| `forging` | 锻打动作校验、会话状态、目标区间/末尾序列判定、最优步数和品质结算 | 固定武器、锻打方式和品质阈值。 |
| `alchemy` | 炼丹状态机、丹方匹配、温度/失败回调 | 任意具体丹方。 |
| `formation` | 结构匹配、阵法生命周期、区域索引与资源消耗 | 聚灵/攻击效果的硬编码。 |
| `creature` | 妖兽资料读取、契约关系、跟随/召回通用命令 | 固定妖兽实体。 |
| `tribulation` | 劫数调度、难度计算、区域威胁抽象 | 雷击、幻象等特定表现。 |
| `world` | 区块灵气与灵脉再生、环境标签 | 具体地形和维度生成。 |
| `integration` | 可选依赖探测与适配器 | 核心机制的必经路径。 |
| `kubejs_bridge` | 稳定 JS API、事件转发、静态定义校验 | 注册 Java 类型、绕过服务端校验直接修改附件。 |

## 关键运行时数据

| 数据对象 | 挂载位置 | 内容 |
| --- | --- | --- |
| `SpiritData` | `LivingEntity` Attachment | 境界 ID/进度、灵力、神魂、寿元、业力、心魔、灵根列表、独立体质列表、已学功法、丹毒和修真状态。 |
| `ResourceHolderData` | `LivingEntity` Attachment | 按 `resource` ID 保存当前值、最大值计算快照、最后变更 tick 和来源审计；不保存 HUD 布局或渲染状态。 |
| `CurseHolderData` | `LivingEntity` Attachment | 按 `curse` ID 保存层数、到期 tick、来源、组件状态和定义版本；未知定义保留原文并停用。 |
| `CurseContainerData` | `ItemStack` Data Component | 物品固有诅咒及其层数/来源；装备、使用或命中时仅通过诅咒动作转移到实体。 |
| `AbilityHolderData` | `LivingEntity` Attachment | 按来源聚合的能力 ID、每个能力的组件状态、冷却、吟唱/引导和已装备槽位。 |
| `ArtifactData` | `ItemStack` Data Component/Attachment | 认主 UUID、温养、灵力容器、储物内容引用、定义版本。 |
| `ForgingSessionData` | 锻造台 Block Entity/世界持久化数据 | 蓝图 ID、当前锻打值、总步数、最近六步、预计算最优步数和输入物品。 |
| `ForgingResultData` | `ItemStack` Data Component | 蓝图 ID、最终锻打值、实际/最优步数、额外步数、品质 ID。 |
| `AuraChunkData` | `LevelChunk` Attachment | 灵气总量、再生参数、五行偏向、灵脉引用、活跃阵法索引。 |
| `FormationInstance` | 世界持久化数据 | 阵法定义 ID、中心、阵旗坐标、拥有者、运行状态和消耗缓存。 |
| `ContractData` | 宠物实体及主人索引 | 契约类型、双方 UUID、召回冷却、协同状态。 |
| `TribulationData` | `LivingEntity` Attachment | 当前劫数 ID、阶段、开始时间、难度种子、结算状态。 |

所有附件必须实现：编解码、版本字段、服务端变更标记、观察者同步策略和缺失定义的降级处理。删除或重命名注册表 ID 时，运行时应保留未知 ID 原文并阻止使用，而不是直接丢弃存档数据。

## 模块依赖规则

- `core` 不依赖任何修仙业务模块。
- 业务模块仅依赖 `core`，必要时可依赖 `cultivation` 与 `resource` 的公开 API；例如 `ability`、`artifact`、`forging`、`alchemy`、`formation` 均通过 `resource` 读取或原子消耗灵力等资源。
- `world` 只提供环境数据，不能直接修改玩家修为；`cultivation` 读取并解释环境。
- `kubejs_bridge` 依赖所有公开 API 模块，但其他模块不得依赖桥接层。
- `client` 只依赖同步 DTO 和公开查询接口，不发送未经校验的状态写入。
- 所有能力来源只向 `AbilityHolderData` 授予或移除能力 ID：功法、灵根、体质、头衔、法宝、宗门和外部模组不能直接订阅原版事件并各自执行技能。
- `core.builtin_registry` 只在模组加载期注册 Java 类型及 Codec；数据包重载与 KubeJS 不能修改其中的条目。
