# 前置抽取评估（ability / action / condition / … / hud / function）

> **用途**：把一批通用子系统从本体拆成独立前置（library）之前，先冻结"搬什么、留什么、接缝在哪、哪些必须先拍板"。
> **基准**：当前工作树（含 HEAD 之后未提交的改动，例如 `registry/cache/ItemMatcherCache` 与折行整理）。**只读代码**：本轮没有编译、没有跑 GameTest，所有结论都来自 `src/main` 的源码与 import 图。
> **口径**：证据只取 `src/main/java/com/iafenvoy/mxt/`（路径省略此前缀）；`src/test-mod` 只用来标注验证覆盖，不作设计证据。行数按文件总行数（含空行）统计，复现命令见 §12。
> **判定词**：
> - **直接搬**：出站依赖 ≤2 类，且都在"一起搬"的工具集里。
> - **切接口后搬**：形状不变，但把内容侧的类型换成契约（SPI）或参数化的注册表引用。
> - **拆分后搬一部分**：框架搬、具体条目留。
> - **留本体**：只服务于本体玩法的实现。

## 1. 口径与边界

- 只读 `src/main`；`docs/`、`research/`、`src/test-mod` 只作交叉证据。
- "框架"与"内容"不是按目录名判的：`builtin/` 里有通用的（`data/timeline/builtin/*` 全部、`data/matcher/builtin` 的 5 个 entry、`data/resourcebar/builtin/*` 的渲染数据与可见性），`builtin/` 外也有内容的（`data/ability/type/*` 14 个类型、`data/ability/render/*`）。**逐个域判定见 §4**，那里的"留"是逐类点名的。
- 三层归属：
  - **前置**：与任何玩法模块无关的机制、契约、求值、缓存、注册表骨架与 UI 框架。
  - **本体保留**：`attachment/`、`registry/MxtAttachments`、`MxtDataComponents`、`runtime/<玩法模块>` 服务、`event/` 对外事件、`command/`、`compat/jade|jei|geckolib`、内容 `failure` 枚举。
  - **两边都不放**：世界观内容（资源、灵气、境界、丹药、符箓……的定义与内置条目）——那是内容模组/数据包的事。

## 4. 逐域判定

### 4.1 `ability` —— 拆分后搬一部分，**最后搬**

- 框架（19 文件 / 837 行）：`Ability`（定义记录：`costs`、条件、动作）、`AbilityType` 接口、`AbilityEffect` / `ActionCarrier` / `TriggerSource` / `ChannelSource` / `CooldownSource`、`Togglable` / `ToggleContext`、`TargetSelector` + `TargetOrder` + 5 个选择器（`self`/`area`/`ray`/`cone`/`js`）。
- 内容（18 文件）：`type/` 下 14 个类型（`active`/`triggered`/`modifier`/`aura`/`interval`/`channelled`/`targeted`/`word`/`empty`/`mount`/`flight_control`/`storage`/`upkeep`）、`render/`（`MountRender` 及其 2 个内置）。
- 接缝最重：`AbilityContext` 直接持有 `AbilityAttachment`（`data/ability/AbilityContext.java:13`，附件属本体）；`AbilityType` 的 `storage`/`upkeep` 实现直接读 `data/storage/builtin/*`（4 类）；`Cost`（3）、`AbilityActivationService`（3）、`FlightService`/`ArtifactService`（各 1）。
- **改造点**：先抽出"能力宿主"契约——①谁存这份能力（`AbilityAttachment` → `AbilityHost` 接口 + 本体的附件实现）、②谁跑 tick 与通道（`AbilityActivationService` 属本体）、③`TargetSelector` 的候选来源（`runtime/ability` 的服务）。三者抽完，`Ability`+`AbilityType` 的形状才能进前置。

### 4.2 `action` —— **直接搬框架**，具体动作留本体

- 框架（26 文件 / 913 行）：`EntityAction`/`BiEntityAction`/`BlockAction`/`ItemAction` 四个接口（`codec()` + `execute(ctx)`）、`NoOpAction`、`SimpleActions`、四个 `*ActionContext`、19 个 meta 组合子（`sequence`/`random`/`chance`/`either`…）、通用 `send_message`。
- 内容（69 文件 / 2 710 行）：47 个 entity action、5 个 bi-entity、8 个 block、9 个 item——它们几乎全部 import 本体服务（`CultivationIdentityService`、`DamageCalculationService`、`CurseService`、`AbilityEventBridge`、`LifeSpanService`、`PillService`…）。
- 接缝：框架自身只有 `MxtRegistries.*_ACTION_TYPE`（4 处，`data/action/EntityAction.java:3` 等）+ `OptionalCodec` 的默认值 `NoOpAction`。
- **改造点**：`*_ACTION_TYPE` 四个 key 与 meta 组合子一起进前置；内容动作改为在前置注册表里注册（条目 id 用内容模组的命名空间，注册表 key 仍是 §7 D1 定的那个）。

### 4.3 `condition` —— 同 `action`，但要顺带把 `util.math` 提出来

- 框架（35 文件 / 959 行）：5 个接口（entity / bi-entity / block / item / damage）、`AlwaysCondition`、`NeverCondition`、`SimpleConditions`、五个 `*ConditionContext`、27 个 meta 组合子。
- 内容（119 文件 / 3 938 行）：entity 65、item 26、bi-entity 9、block 11、damage 8。
- 接缝：`util.math.Comparison`（31 处引用，贯穿内置条件）+ 13 个 `MxtResourceKeys` 引用 + `ItemMatcher` + `QualityRequirement`。
- **改造点**：`util/math` 必须先搬（3 文件 / 150 行，零依赖）；`mxt:quality`、`mxt:technique`、`mxt:realm` 这类读内容的条件留本体。

### 4.4 `context` —— **直接搬**

- 10 文件 / 385 行：`Context`（无类型扩展表 + `data()` + `copyTo` + `origin()`）、`action/` 4 个、`condition/` 5 个。
- 接缝：0（只依赖 `FormulaContext` 与原版 `Provider`/`Vec3`）。
- **注意**：`Context.ORIGIN = "mxt:origin"` 是写死的字符串（`data/context/Context.java:14`），D1 若改命名空间，这一处与所有 `get("mxt:…")` 键一起改；另有 266 个文件 import 它，改包名是本次最大的一次机械改动。

### 4.5 `cost` —— 先定 D2

- 框架（9 文件 / 942 行）：`Cost`（`codec()`/`test()`/`commit()`/`execute()`）、`Costs`、`CostPayment`、`CostTransaction`、`Debit`、`CostTarget`、`CostContext`/`CostOrigins`/`AuraCostSources`；内置 4 种 `resource`/`aura`/`item`/`js`（383 行，与框架一起搬，但前两种依赖 D2）。

## 7. 三个必须先拍板的决定

### D1 命名空间与模组 id

- **事实**：注册表 key 的命名空间与路径决定数据文件位置——文档写明 `data/<命名空间>/mxt/<注册表>/<条目>.json`（`docs/docs/datapack/overview.md:11`），实测本体自带 27 个文件在 `src/main/resources/data/mxt/mxt/`，测试包夹具 **392 个**在 `src/test-mod/resources/data/mxt_test/mxt/`。代码侧 17 处写死 `"mxt:` 字符串（含 `Context.ORIGIN`）与 4 处 `MiXianTu.MOD_ID`。
- **选项 A（保持 `mxt`）**：前置用 `mxt` 作命名空间/模组 id，本体改名。数据包、夹具、文档路径全部不动；但"本体"的玩家可感知名字要换，两份 README 与 `gradle.properties` 的 mod id 一起改。
- **选项 B（前置用新 id）**：前置用 `mxt_core` 之类。419 个 JSON 路径与文档站 80 页里的路径示例全部要改，但本体名字不动；且**旧数据包会静默失效**（目录名不匹配 = 条目读不到，只有注册表为空这一种症状）。
- **建议**：若这次拆分的目的是"给其它内容模组做公共基座"，选 A（`mxt` 留给前置），因为 A 的破坏面只在命名，B 的破坏面在**所有数据包文件路径**上。

### D2 `resource` / `aura` 去不去前置

- **事实**：`Cost` 简写 codec 直接解 `Resource`（`data/cost/Cost.java:36-43`）；`FormulaContext` 持有 `Holder<Resource>`（`util/formula/FormulaContext.java:33`）；`ResourceHolderAttachment` 被框架读 6 处、`resource` 域读 9 处；`Aura` 在框架里 6 处，`AuraAccess`/`AuraCostSource` 4 处。
- **选项 A（进前置）**：`Resource`/`Aura` 两个定义记录与它们的附件一起进前置 ⇒ `cost`/`resource`/`resourcebar`/`formula` 零改动搬走，但"修真资源/灵气"这套世界观语义就进了通用库。
- **选项 B（留本体）**：前置只提供"数值主体 + 存取通道"的抽象（`FormulaSubject`、`CostChannel`），`Resource`/`Aura` 由本体实现并在启动时注册 ⇒ 前置更通用，但 `cost`/`formula`/`resourcebar` 三处要改形状，且**简写 codec**（`{"id": …, "amount": …}`）与"资源条定义"要重新设计。
- **建议**：B 的目标形态更干净（`resource` 是典型的"内容定义"），代价是 `cost` 的简写语法与 `FormulaContext` 的字段要改；若目标是尽快拆出可用的前置，A 能少改 800 行左右，但前置从此带世界观。

### D3 `hud` 的客户端归属与配置

- **事实**：`screen/hud` 只 import `MiXianTu`（2 处）；编辑器把每个玩家的布局写进文件（`HudLayoutFile`，98 行）；`resourcebar` 依赖 `screen.hud` 的 `RenderBlock`/`HudAnchor`/`HudManager`/`ScreenBounds`；`MxtClientConfig` 的 `ResourceBarIconLayout` 是内容侧配置项。
- **要定的三件**：①布局文件落在哪个目录（前置自己的 `config/<id>/hud.json`？）；②`HudEditScreen` 的文案键前缀归谁（今天 `screen.mxt.*`，`lang` 里 231 条）；③内容注册 HUD 条目的 API 形状（`HudManager.register` 是否需要按"来源 id"多槽位，避免两个内容模组抢同一个槽）。

## 10. 代价与风险

| 项 | 数字 | 说明 |
|---|---|---|
| 受影响的 `src/main` 文件 | **732 / 1 361**（54%） | 只要 import 过这 19 域之一的文件都算 |
| 要移动的代码 | 200 文件 / 9 682 行 | 框架候选 |
| 要留下的内容 | 269 文件 / 10 570 行 | 具体条目 |
| 数据包文件 | 419 个（本体 27 + 夹具 392） | 仅当 D1 改命名空间 |
| 文档 | `docs/docs/datapack` 80 页（46 页 JSON 类型页）+ 两份 README + `AGENTS.md` 代码地图 | 每张注册表搬走，对应的字段页要跟着搬到前置的文档 |
| lang | 1 396 条（zh）；其中 `failure.mxt.*` 143、`mxt.profiling.*` 64、`mxt.registry.*` 17、`config.mxt.*` 254 | 前置带走它自己的 failure/profiling/registry 显示名 |
| 双向兼容 | 前置与本体必须同版本发布 | 前置的注册表 key、默认 id、枚举值都是硬契约 |

**风险点**：
1. **注册表默认 id 与数据包省略写法**：`no_op`/`always`/`constant` 这类默认值一旦换命名空间，所有"没写 type"的老数据包会失效（静默，注册表里只是少了一条）。
2. **`ItemMatcher.Entry.itemLevel()` 的缓存契约**：`ItemMatcherCache` 依赖"只有 item 级 entry 能按 item 缓存"（`util/matcher/ItemMatcher.java:92-96`）。前置若允许外部 entry 类型，这条约定必须写进前置的公开文档，否则第三个内容模组写的 entry 会污染缓存。
3. **`Context` 的 `mxt:origin`**：扩展表是无类型 `Map<String,Object>`，键前缀是约定不是类型；D1 若改前缀，跨模组的 `origin` 传递会断。
4. **客户端侧隔离**：`screen/hud`、`screen/resourcebar`、`data/resourcebar`（渲染数据）、`data/ability/render` 都只在客户端用；前置要保证服务端不加载它们（今天靠 `EventBusSubscriber(Dist.CLIENT)` 与包位置）。

## 12. 复现统计

```powershell
# 1) 每个域的文件数 / 行数：先归一化路径分隔符，再按目录聚合
$root = (Resolve-Path "src\main\java\com\iafenvoy\mxt").Path
$files = Get-ChildItem -Path $root -Recurse -File -Filter *.java | ForEach-Object {
  [pscustomobject]@{ Rel = ($_.FullName.Substring($root.Length + 1) -replace '\\','/')
                     N   = (Get-Content $_.FullName).Count }
}
$files | Group-Object { $_.Rel -replace '/[^/]+$','' } | ForEach-Object {
  [pscustomobject]@{ Dir = $_.Name; Files = $_.Count; Lines = ($_.Group | Measure-Object N -Sum).Sum }
} | Sort-Object Dir

# 2) 出站接缝：候选集内文件逐行抓 import，剔除落在候选集内的目标，按 "包::类" 计数
$candidateDirs = @("data/context", "util/formula", "registry/cache")   # 换成实际候选目录
$candidatePkgs = $candidateDirs -replace '/','.'
$seams = @{}
foreach ($f in ($files | Where-Object { $candidateDirs -contains ($_.Rel -replace '/[^/]+$','') })) {
  Select-String -Path (Join-Path $root $f.Rel) -Pattern '^import\s+(static\s+)?com\.iafenvoy\.mxt\.([\w.]+);' |
    ForEach-Object {
      $imp = $_.Matches[0].Groups[2].Value; $p = $imp.Split('.')
      $pkg = ($p[0..($p.Length - 2)] -join '.')
      if ($candidatePkgs -contains $pkg) { return }
      $k = "$pkg :: $($p[-1])"; $seams[$k] = 1 + $(if ($seams.ContainsKey($k)) { $seams[$k] } else { 0 })
    }
}
$seams.GetEnumerator() | Sort-Object Value -Descending | Select-Object -First 20
```

判据口径：
- "框架候选"＝域内除 `builtin/`（`action`/`condition` 的 meta 除外）与 `data/ability/type|render`、4 个内容变量、4 个内容缓存之外的全部文件。
- "入站文件"＝不在该域、且 `import` 命中该域任一包的文件数。
- 行数含空行（`Get-Content` 计数）：19 域 20 252 行里有 2 955 行是空行，非空行 17 297。与 `Measure-Object -Line` 那种"只数非空行"的口径对比时按 17 297 算。
