# 物品用途审计 —— 本体物品的「没用途」清单

> **基准**：`master` @ `f5c74ad5`（2026-10-02，`feat: new talisman model`）+ 本轮工作树。工作树里未提交的是画符台贴图 / 整方块模型与 AUI 页面路径合并，**与本清单无关**。
> **日期**：2026-10-03。**方法**：对 `src/main/java/com/iafenvoy/mxt/registry/MxtItems.java` 的 **39** 个非方块注册项逐个取「常量名」与「id 字符串」，在 `src/main`（Java 与**全部**资源）、`src/test-mod`、`docs/`、`research/` 里 grep 消费者；再反向核对 `assets/mxt/items` / `models/item` / `textures/item` 与两份 lang 有没有「有资源没注册」的孤儿。
> **口径**：注册行 + `assets/mxt/items/<id>.json` + 模型 + 两份 lang + 创造栏**不算**消费者——每件注册物品都有这五样（§3.1 已核）。「有用途」= 本体有一处代码读它、给它行为、或把它当输入 / 输出 / 载体。
> **数据包不算用途**：数据包能把任意物品 id 写进配方输入输出，也能用 `mxt:merge_components`（`data/action/builtin/item/MergeComponentsAction.java:12-18`，收任意 `DataComponentPatch`）写任意组件。所以「数据包可以给它赋义」**不构成有用途**，本文对这类一律注明。
> **用途**：只登记「现状 / 缺什么 / 可选接法」，不含实现、不含排期。后续按此逐条开工。
> **没跑**：实机（未开游戏、未跑 `runTestClient`）。全部结论只到「源码可判定」这一层——例如「灵戒装不进腰槽」是按两个 equipable 标签为空 + `charm` 槽按法器定义判的，没在游戏里试过装配。
> **补记（同日）**：普查时本体是 **39** 件非方块物品；当天后来按用户要求新增了第 40 件 **`mxt:physique`**（体质物品，与 `mxt:spirit_root` 同形：堆上组件指名定义、右键走 `CultivationIdentityService.grantPhysique`）。它一注册就带着用途，所以只影响下面写死的件数与 §3.1 的覆盖率，不影响任何结论。

## 3. 顺带核到的（不是缺陷，但影响"能不能玩到"）

### 3.1 资源与翻译没有缺口

用脚本逐项核对（物品 id ↔ `assets/mxt/items/<id>.json` ↔ 它的模型文件 ↔ `zh_cn` / `en_us` 的 `item.mxt.<id>` / `block.mxt.<id>`），**40 件非方块物品 + 22 件方块物品全部齐**（普查时是 39 件，缺口同样为零），缺口列表为空。反向检查 `assets/mxt/items` / `models/item` / `textures/item` 也**没有孤儿**：`textures/item/storage_bag.png` 被灵石袋模型用着（`models/item/spirit_stone_bag.json:1`）。`item.mxt.currency_value` 是 tooltip 文案键（`data/economy/CurrencyValueTooltipAppender.java:45`），不是物品，别当孤儿删。

### 3.2 本体只有 3 条物品配方

`src/main/resources/data/mxt/recipe/` 共 13 份：朱砂（红石 ×2 + 沙）、支票（纸 ×3 + 墨囊 + 羽毛）、灵石（灵石块 → 9）、灵石块（9 灵石）、6 张展示架、交易站 / 兑换站 / 支票台。也就是**物品侧只有朱砂 / 支票 / 灵石三件能合成**，其余 36 件只能从创造栏或数据包获得。这是框架的既定口径（`README-zh.md:8`：具体物品、方块和配方由数据包 / KubeJS / 内容模组提供），**不算缺陷**；但如果要"本体自带最低限度的可玩链"，符纸 / 符笔 / 符箓 / 丹药 / 契约卷轴 / 阵盘 / 令牌这一串是缺的。

### 3.3 彩蛋食物

`mxt:fried_dough_cake`（`MxtItems.java:92`）是普通原版食物 + 一行 tooltip，本体无配方。tooltip 自 2026-10-03 起不再单独写类：行数由 `item/EasterEggItem` 的构造函数给出，文案是 lang 里的 `tooltip.<命名空间>.<路径>.<i>`（`i` 从 0 起，这里就是 `tooltip.mxt.fried_dough_cake.0`），由 `item/EasterEggTooltipAppender` 统一生成。按房规第 9 条，它**不进两份 README、`docs/` 与文档站**，本文只登记状态、不写用法。

## 4. 已核事实与证据

### 4.1 判定为"零钩子"的核查方式

对每个候选 id 取**三种写法**（Java 常量名 `MxtItems.SPIRIT_RING`、id 字符串 `spirit_ring`、lang 键 `item.mxt.spirit_ring`）分别全仓 grep：命中集合只有 `MxtItems.java` 的注册行、`assets/mxt/items/<id>.json`、`models/item/<id>.json`、`textures/item/<id>.png`、两份 lang、创造栏（它遍历注册表），以及个别文档的**示例 JSON**。任一候选若有第四类命中，就落进 B 组（鉴定镜就是这样落进去的：它有真实读取点，只是没有写入点）。
