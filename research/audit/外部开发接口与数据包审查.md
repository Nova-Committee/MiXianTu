## P1

### ~~A01 载具渲染的回退定义与渲染器类型不匹配~~

`MountRenderers.resolve` 缺少对应渲染器时，强转并返回只接收 `ItemMountRender` 的 `ItemMountRenderer`。`FlyingSwordRenderer` 仍把原定义传给它。已检查编译产物，`extract` 的桥接方法确实先把输入转成 `ItemMountRender`。例如 `mxt:geckolib` 的 Codec 总会注册，客户端渲染器只在 GeckoLib 存在时安装，正好会走到此分支。第三方载具渲染器遗漏客户端注册也有同样结果。[Codec 注册](../../src/main/java/com/iafenvoy/mxt/registry/MxtMountRenders.java#L15) · [客户端注册](../../src/main/java/com/iafenvoy/mxt/registry/MxtRenderers.java#L47) · [回退](../../src/main/java/com/iafenvoy/mxt/render/mount/MountRenderers.java#L36) · [实际调用](../../src/main/java/com/iafenvoy/mxt/render/entity/FlyingSwordRenderer.java#L65)

解析结果应同时携带匹配的定义和渲染器，提取与提交都用这一对。验证可选渲染依赖缺席、第三方渲染器未安装以及物品渲染三种情况。

### ~~A02 `MxtLoot` 回调无法被战利品表派发~~

原脚本入口只能登记回调。原版战利品表从未注册相应的 `mxt:js` 或 `saturn:js` 条件与函数类型，无法调用这些回调。已移除脚本绑定、回调存储和重载清理，并同步更新双语文档与侧边栏。生物和方块的运行时掉落可以使用 KubeJS 的 `EntityEvents.drops` 与 `BlockEvents.drops`。 [KubeJS 事件](../../docs/docs-zh/mod/mxt/kubejs/api/events.md) · [战利品与进度条件](../../docs/docs-zh/mod/mxt/datapack/loot-and-criteria.md)

### ~~A03 事件观察会改变共享 Cost 的执行形状~~

技能发动、引导维护和境界突破会先把账单汇总为按数值 ID 键控的金额映射，再在事件返回后无条件调用 `replaceResourceAmounts`。本体突破入口与当前 Saturn 构件均已核对。替换操作保留非账户条目，把账户费用按 ID 汇总并移到后面。即便完全没有监听者，最终付款也会合并重复账户目标，原本位于两条账户费用之间的脚本或物品费用会先于它们执行。技能准备阶段仍会对原账单做预检，最终付款只看到改写后的计划。突破则在这次改写前只报价，没有机会对原账单做重复诊断。普通 `CostPayment.pay` 的两遍执行本身保留原序。[突破入口](../../src/main/java/com/iafenvoy/mxt/runtime/cultivation/CultivationService.java#L120) · [Cost 对外约定](../../docs/docs-zh/mod/mxt/datapack/types/shared_data_types.md#L62)

保持两遍执行、实扣失败写 WARN 的约定。事件提供只读汇总和显式改价操作，事件无编辑时继续执行原账单。有编辑时明确指定目标条目或定义汇总编辑如何分配到原条目。用同一份混合费用核对无监听、只读监听和改价三种情况下的扣除顺序与记录。

### ~~A04 客户端灵气查询访问未同步的注册表~~

`MxtAura.get(Level, pos)` 把查询原样转给 `AuraService.getPositionAura`。客户端分支进入 `staticZone` 后，每个灵气区的维度匹配都会先调用 `lookupOrThrow(Registries.LEVEL_STEM)`，即使该条目的维度选择为空。当前 Minecraft 源码将 `LEVEL_STEM` 放在维度生成注册表，正常远程客户端的注册表由内置表和网络同步表构成，该表不在其中。存在待匹配的灵气区时，客户端读取可能在得到群系结果前抛异常，与脚本文档承诺的本地查询不符。[客户端入口](../../src/main/java/com/iafenvoy/mxt/compat/kubejs/MxtKubeJsApi.java#L650) · [维度匹配](../../src/main/java/com/iafenvoy/mxt/runtime/world/AuraService.java#L242) · [脚本契约](../../docs/docs-zh/mod/mxt/kubejs/api/aura.md#L16)

公开区分服务端权威查询和客户端可用快照。客户端对直接 ID 可用当前维度判断，维度标签需要服务端解析后同步；最少也应为缺失注册表定义可预期的降级。远程客户端分别验证直接维度、标签维度、只有群系三种定义。

## P2

### ~~A05 公开灵气查询返回共享可变状态~~

默认启用缓存时，`AuraService.getPositionAura` 会保存 `AuraResult` 并把同一个对象返回给调用方，后续同 tick 的缓存命中返回相同引用。`AuraResult.aura()` 可以返回可变映射，`pool(...)` 返回的 `AuraPool` 也有公开修改方法。脚本从名义上的只读入口获取同一个对象。结果已经与实存池分开，但第三方对结果的修改仍会改变同 tick 后续读者看到的浓度。另有首次查询初始化区块池并标记保存的副作用，Java 页说明了初始化，KubeJS 页只称为只读。[缓存调用](../../src/main/java/com/iafenvoy/mxt/runtime/world/AuraService.java#L51) · [初始化](../../src/main/java/com/iafenvoy/mxt/runtime/world/AuraService.java#L118) · [结果形状](../../src/main/java/com/iafenvoy/mxt/runtime/world/AuraResult.java#L17) · [池可变性](../../src/main/java/com/iafenvoy/mxt/runtime/world/AuraPool.java#L93)

在创建缓存时生成深层只读快照，使公开读者共享同一快照。仅封装外层映射仍会泄漏池的修改方法。区块池初始化由既有加载路径负责，查询是否会补初始化应明确写入契约。

### ~~A06 KubeJS 付款缺少可用于分支处理的结果~~

`MxtResources.consume` 实际绑定 Saturn 的资源入口。当前发布构件的 `tryConsumeResources` 会把 `CostPayment` 的全部预检拒绝改成 `Failures.UNKNOWN`，客户端与错误的付款者类型也返回这一值。脚本文档却指向 `getFailure().get().resource()` 来定位缺少的数值。`MxtCosts.check/consume` 还把结果降成布尔值。成功后的返回值仅投影出已知账户扣款，调用方无法分清实扣完整或其中有一项告警。[绑定](../../src/main/java/com/iafenvoy/mxt/compat/kubejs/MxtKubeJsPlugin.java#L100) · [返回值文档](../../docs/docs-zh/mod/mxt/kubejs/api/resources.md#L21)

由 Saturn 的共同脚本入口保留预检的失败原因与资源 ID，并提供覆盖实扣告警和已知实际扣款的结果视图。保留现有布尔便捷入口时，应定义布尔值只回答哪个阶段。验证无效付款者、数值不足、条目不适用、实扣带告警和全额成功可以区分。

### ~~A07 事件的可读数据与可写范围不成体系~~

突破事件暴露可变的修炼附件与资源附件，灵魂体事件暴露可直接 `clear` 的存档附件。KubeJS 通用包装通过 `getEvent()` 原样返回这些 Java 对象，阶段字符串取原生类的简单名称，脚本需要依赖内部命名与附件结构。反过来，灵气区的专用包装只有来源、浓度和覆盖区等字段，未保留原事件的世界、坐标或进出实体，脚本没法只处理特定范围或玩家。诅咒的 `getStacks()`、`getSource()` 在 `Post` 阶段也会与写方法一样抛异常。[突破事件](../../src/main/java/com/iafenvoy/mxt/event/CultivationBreakEvent.java#L35) · [灵魂体事件](../../src/main/java/com/iafenvoy/mxt/event/SoulEvent.java#L16) · [灵气区 Java 事件](../../src/main/java/com/iafenvoy/mxt/event/AuraZoneEvent.java#L26) · [脚本包装](../../src/main/java/com/iafenvoy/mxt/compat/kubejs/MxtKubeJsEventDispatcher.java#L132)

为每个公开阶段定义稳定常量和只读字段，前置事件通过显式方法取消或修改指定参数。保留 Java 与 KubeJS 所需的实体、世界、坐标、ID 和变更结果。脚本包装可共享公共阶段信息，领域数据按事件暴露。

### A08 灵气与供热接口要求能够修改被接入的类

灵气脉冲从方块实体做 `instanceof AuraAccess`，灌注与展示架从物品类做 `instanceof ItemAuraAccess`，动态供热从方块类做 `instanceof AlchemyHeatSource`。这些接口能让第三方接入自己的类。若第三方要为原版或另一模组的现有类适配存储或根据状态供热，现有数据包映射无法表达外部库存与运行时状态，Java 也没有独立注册适配器的公开入口。[灵气脉冲](../../src/main/java/com/iafenvoy/mxt/entity/SpiritBurstEntity.java#L211) · [展示架](../../src/main/java/com/iafenvoy/mxt/item/block/entity/DisplayStandBlockEntity.java#L56) · [灌注](../../src/main/java/com/iafenvoy/mxt/runtime/spirit/SpiritChargeService.java#L155) · [供热](../../src/main/java/com/iafenvoy/mxt/runtime/alchemy/AlchemyHeatService.java#L16)

在 NeoForge Capability 层或一个统一解析入口提供外部适配，现有接口可由默认提供者桥接。沿用 `AuraAccess` 的小数、返回剩余量、`exact` 和 `simulate` 约定；动态供热和数据包供热应有明确优先级。验证一个不继承 MXT 类的外部方块和一个原版物品均可接入。

### ~~A10 缺失的进度配置在运行时默认可通过~~

### ~~A11 多包叠加缺少可预测的选中原因~~

生物档案已会跳过实体类型、条件或环境不符的条目，再尝试下一项。但排序只按完整 ID，`CreatureProfile` 没有 `priority`，因此独立包要让特定档案优先于通用档案，只能依赖 ID 排序或修改通用档案。其他相近的单选表也有不同的同分规则：静态灵气区按 ID 打破平局，法器与热源同分取注册表先遇到的条目。数据包覆盖同 ID 文件属于另一层规则，无法调整不同 ID 的候选顺序。[档案选择](../../src/main/java/com/iafenvoy/mxt/runtime/creature/CreatureProfileService.java#L35) · [档案排序](../../src/main/java/com/iafenvoy/mxt/registry/cache/RegistryCaches.java#L51) · [灵气区排序](../../src/main/java/com/iafenvoy/mxt/runtime/world/AuraService.java#L235) · [法器排序](../../src/main/java/com/iafenvoy/mxt/runtime/artifact/ArtifactService.java#L63) · [热源排序](../../src/main/java/com/iafenvoy/mxt/registry/cache/HeatSourceCache.java#L20)

给档案增加显式优先级，在现有排序缓存里计算，保持逐候选按需判断。为同类单选表统一并说明同分规则。提供面向作者的低频解析说明，给出选中的定义 ID、优先级和回退原因。

### ~~A13 公式变量的 ID 折叠无法区分部分合法条目~~

当前 Saturn 构件的 `FormulaNameCache` 用下划线拼接命名空间与路径，同时把 `/`、`.`、`-` 换成下划线。`example:fire-qi` 和 `example:fire_qi` 会竞争同一个变量名。缓存只保留先登记的条目，日志指出被忽略的一方；公式编译与调用端没有无歧义选项。MXT 对数值、元素和属性都建立了这类缓存。[缓存注册](../../src/main/java/com/iafenvoy/mxt/registry/cache/RegistryCaches.java#L47) · [公式变量命名](../../docs/docs-zh/mod/mxt/datapack/types/formula_variables.md#L67)

在作者校验中同时列出冲突双方与受影响的变量名。为新定义提供可逆的变量编码或显式变量别名，旧表达式在名称唯一时仍能解析。

### ~~A14 扩展注册缺少冲突诊断和明确时机~~

品质载体用静态列表登记，命中多个载体时取注册顺序中的第一个，品质由哪个附属先登记决定，也没有重复检查。脚本回调按类别与字符串 ID 登记，当前依赖的共同 Action 回调直接调用 `Map.put`，重名会覆盖先前注册，加载多个脚本后很难定位回调归属。KubeJS 的公共 Saturn 回调清理由 MXT 与 Saturn 各自发起，回调表与脚本生命周期的归属分散。[品质注册](../../src/main/java/com/iafenvoy/mxt/runtime/item/QualityService.java#L60) · [品质解析](../../src/main/java/com/iafenvoy/mxt/runtime/item/QualityService.java#L176) · [MXT 重载入口](../../src/main/java/com/iafenvoy/mxt/compat/kubejs/MxtKubeJsPlugin.java#L122) · [MXT 清理的公共回调](../../src/main/java/com/iafenvoy/mxt/compat/kubejs/callback/MxtJsCallbacks.java#L13)
