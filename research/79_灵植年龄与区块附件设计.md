## 2. 术语与单位

| 词 | 含义 |
| --- | --- |
| **药龄 / age** | 以「年」为单位的浮点数，**只增不减**，由 `growth_rate` 每 20 加载 tick 推进一次累积而来。今天叫 `progress`，本稿统一叫 age |

## 3. 新形状

### 3.1 区块附件 `mxt:herb_chunk`

`attachment/HerbChunkAttachment.java`，注册在 `MxtAttachments` 的 **Level 段**（挨着 `AURA_CHUNK`，`:58` 那一行的同一种写法）：

```java
public static final DeferredHolder<AttachmentType<?>, AttachmentType<HerbChunkAttachment>> HERB_CHUNK =
        REGISTRY.register("herb_chunk", () -> AttachmentType.builder(HerbChunkAttachment::new)
                .serialize(HerbChunkAttachment.MAP_CODEC).build());
```

- **不 `.sync(...)`**（拍板 ⑨）：客户端读不到，也不需要读——外观走 blockstate。
- 形状照 `AuraChunkAttachment`：`RecordCodecBuilder.mapCodec` + 每个可选字段 `lenientOptionalFieldOf`。
- **行存，不按坐标做 map 键**：`FormationWorldAttachment` 的类注释写着「keying by the packed position made saving a populated index fail outright」（`:19-20`），所以照它存 `CollectionCodecs.list(Stored.CODEC)`，一行一条：

```java
private record Stored(long position, Optional<Holder<SpiritHerb>> herb, double age,
                      long settledAt, ItemStack seed) { ... }
```

- **记录自己带 herb**：一行记录必须能在数据包把那条定义删掉之后**仍然说得出「我原来是哪种草」**（§3.6）——所以 herb 存在行里，而不是每格去问方块。方块只在野生植株（没有记录）那一侧开口。
- **`seed` 用 `ItemStack.OPTIONAL_CODEC`**：它是「空表示没有」的可选堆，而 `ItemStack.CODEC` / `STREAM_CODEC` 都拒收空堆（`AGENTS.md` §4）。
- 用 `CollectionCodecs.list` 是为了**一行坏掉只丢那一行**（同一个类注释的另一个理由）。
- 内存里是 `Map<Long, Plant>`；读档时同一个坐标出现两条就保留先到的那条并记一条 `Ignoring duplicate herb plant in the saved chunk` 警告。`plants()` 对外给 `Map<BlockPos, Plant>`。

### 3.2 gameTime 是唯一的时间基准

| 事实 | 出处 |
| --- | --- |
| 每个服务器 tick `+1`，由 `runs` 门控 | `ServerLevel.tickTime()` `:484-492`，调用点 `:384-386` |
| 只有主世界那份 `ServerLevel` 带 `tickTime=true`，其余维度 `false` | `MinecraftServer.java:439-441` / `:477-479` |
| 落盘在 level.dat 的 `Time` 键 | `PrimaryLevelData.gameTime` `:92` / `:136` |
| `/time set|add|pause|resume|rate` **动不了** gameTime（只动 `WorldClock`），只有 `/time query gametime` 读它 | `TimeCommand.java:131-135` |
| 客户端的是本地近似值 | `ClientLevel.tickTime():330-332`，服务端每 20 tick 用 `forceGameTimeSynchronization()` 推一次（`MinecraftServer.java:1134-1138,1201`） |

**用 gameTime 而不是墙钟**：它跟着存档走，备份回滚、换机器、改系统时间都不会让药龄跳变。

**它会停**：服务器关着、`/tick freeze`、专用服空置超过 `pause-when-empty-seconds`（默认 60）、单机暂停。这些期间药龄不涨——这正是「只在加载期间生长」想要的语义。

**它可能倒退**：硬崩丢档或回滚备份会退最多一个自动存档周期（`AUTOSAVE_INTERVAL = 6000` tick ≈ 5 分钟）。所以**时差一律 `Math.max(0, now - settled_at)`**，负数一律当 0（`AuraChunkAttachment.regenerateAuras:136` 对负数是直接抛异常的；这里不能照抄，附件是存档数据，倒退是正常现象而不是编程错误）。

### 3.3 结算

**加载期间**（`runtime/alchemy/HerbChunkTicker` 每 20 tick 调一次 `SpiritHerbGrowthService.settle`，**不是方块自己的 ticker**）：

1. 每 tick 判 `level.getGameTime() % PERIOD == 0`，然后遍历本维度已加载区块，**只处理已有记录的区块**（`getExistingDataOrNull == null` 直接跳过——只读查询不建附件，见 §3.5 与房规）。
2. 逐条记录：`level.getGameTime() - settled_at < PERIOD` 就跳过。
3. 回查那一格的方块；**已经不是灵植了就把记录删掉**（区块附件没有方块生命周期钩子，见 B1）。
4. 方块还在但**定义查不到了**（数据包删了这条 herb，或它没有 `growth`）：**记录保留、只把 `settled_at` 拉到当前时刻**——记录里还存着玩家的种苗，删了就等于吞掉它；拉到当下则让植株「暂停」而不是把整段空档攒到下次进场一次兑现。
5. `settled_at += PERIOD`（不是 `= now`：这样节奏不会因为一次卡顿而漂移）。
6. 求值 `condition` → 灵气 `costs` → `growth_rate`（用**当时的** age，拍板 ④），`age = min(max_age, age + amount)`。
7. 有改动才写回附件 + `chunk.markUnsaved()`（见 §3.5），并回调方块更新外观。

失败（条件不成立 / 灵气不够 / `growth_rate ≤ 0`）**只推 `settled_at`、不动 age**——与今天「暂停不死苗、不部分扣款」一致。

**采摘时**（`harvest`）：

1. 有记录 → 从记录出发；**没有记录（野生）** → 起点 `age = wild_age.roll()`、`settled_at = 0`（拍板 ⑤）。
2. `elapsed = min(max(0, now - settled_at), ticksPerYear)`——**上限 1 年**（拍板 ⑩，复用 `MxtServerConfig.INSTANCE.lifespan.ticksPerYear`，默认 24000 → 最多 1200 期）。
3. **逐期推进**：`periods = elapsed / PERIOD`，每期用**当时的** age 求一次 `growth_rate`（拍板 ④），`age = min(max_age, age + amount)`。
4. 产出 `harvest` 模板，写 `mxt:herb_age = floor(age)`，再过 `quality_by_age` 那一档（`QualityService.hasOverride` 为真时不覆盖）——**照抄今天 `harvestStack` 的语义**（`:182-192`）。
5. **移除植株**（拍板 ⑦）并清掉该格的附件记录。
6. **先潜行、后定义**：`emptyHand`（`:80-93`）把潜行分支排在 `growth` 查找**之前**——潜行是把种苗拉回来，只依赖记录里那只种苗，所以一条记录即使它的定义已经查不到也要能把苗拿回来；反过来若先查 `growth`，这种植株就永远拉不动了（`growth == null` 时直接 `PASS`）。野生植株没有记录、没有种苗，潜行**不接管**（回落原版），植株留在原地。

**跨卸载只算 `growth_rate`**（拍板 ②）：`condition` 与灵气 `costs` 卸载期间不补。这与灵气系统自身的口径一致——`AuraChunkTicker` 的 `aura.regenerateAuras(interval)` 本来也是**只按加载 tick** 走，卸载期间灵气不回复。

### 3.4 上限为什么是 1 年

野生的基准是 gameTime 0（拍板 ⑤），老服上就是几千万 tick；逐期推进必须封顶，否则一次采摘要跑上千万次公式求值。**上限 = `lifespan.ticks_per_year`（默认 24000）**，也就是**野生植株最多补算 1 年的 `growth_rate`**（默认 1200 期）。

- 为什么复用寿元那一项而不是新开一个配置项：两者的语义都是「多少 tick 算一年」，本就是同一个换算；新开一项会让同一个概念在配置里出现两次（拍板 ⑩）。
- 上限之外**不再另设**「最大期数」常量——`ticks_per_year / PERIOD` 就是它。
- `max_age` 仍然是真正的封顶：补算期间一旦到 `max_age` 就直接停（今天的 `settle` 也是这个口径，`:104`）。
- `growth_rate ≤ 0` 的植株**一期都不推进**（`SpiritHerbService.appliedGrowth:105-107` 对非有限/负数返回 0），所以不存在死循环。

### 3.5 必须调 `markUnsaved()`

区块附件与实体附件不同：`AttachmentType` 的类注释明写「**Modifications to attachments should be followed by a call to `ChunkAccess#markUnsaved`**」（`AttachmentType.java:53-56`）。`ChunkAccess.setData` / `removeData` 自己会调（`:511-521`），但**原地改**（`attachment.set(...)`）**不会**。

本仓库此前**没有任何 `markUnsaved` 调用**（grep 零命中），这是第一处。所以 `HerbChunkAttachment` 的每个写入方法都必须在调用方那一侧拿到 `LevelChunk` 并 `markUnsaved()`，或者由附件自己在写入时接受一个 `ChunkAccess`。

**选择**：服务是唯一写入点，服务持有 `level.getChunkAt(pos)`，写完后调 `markUnsaved()`。附件自己**不持有区块指针**（与 `DataStorage` 那条「值不持有宿主指针」的房规同精神）。

### 3.6 对外接口 `api/SpiritHerbPlant`

照 `api/Perchable`（本体只给接口、实现归附属）：

```java
public interface SpiritHerbPlant {
    /** 这一格长的是什么；空＝这里没有灵植，服务不该动它。state 由调用方传入：掉落事件跑在原版已经清掉方块之后。 */
    Optional<Holder<SpiritHerb>> herb(BlockState state, Level level, BlockPos pos);

    /** 药龄变了（播种 / 结算 / 补算）——方块自己把它翻成 blockstate 或渲染。默认什么都不做。 */
    default void growthChanged(ServerLevel level, BlockPos pos, double age) { }

    /** 植株被采走 / 拉走时怎么消失。默认原版移除，方块可以覆盖成别的（例如换成苗床）。 */
    default void removePlant(ServerLevel level, BlockPos position) { level.removeBlock(position, false); }
}
```

- **`state` 是入参而不是自己去读**：破坏掉落走 `BlockDropsEvent`，而此时方块**已经被移出世界**（NeoForge 类注释：`will either have already been removed from the world, or will be removed after the event terminates`），`level.getBlockState(pos)` 已经问不出东西了。
- **「我是哪种草」由记录优先回答**：`herbOf`（`:290-295`）先问该格的记录，记录里有 herb 就用它，否则才回落 `block.herb(...)`。播种出来的植株**在记录里带着自己的 herb**，所以即使数据包后来把那条定义删了、方块也改口了，它仍然知道自己是什么；野生植株没有记录，答案只能由方块给（拍板 ①⑧）。**这是接口存在的核心理由**。
- **不做统一管理**：本体不注册方块、不维护「哪些方块能种」的表、不提供基类。测试包自带夹具方块（照 `AlchemyTestHeatBlocks` 的写法，一个类带 `herb` 字段即可）。
- **外观归方块**（拍板 ⑨）：本体不再有渲染器，`Growth.texture` 随之删除。
- **节奏与掉落归本体，方块只管「长什么样、是什么」**：每 20 tick 的结算由 `runtime/alchemy/HerbChunkTicker` 统一驱动（遍历 `AuraChunkTicker.loadedChunks(level)`，只碰已有记录的区块），破坏掉落由同一个 ticker 监听 `BlockDropsEvent` 后调 `dropOnRemove`——**方块自己不用写 ticker、也不用覆写 `affectNeighborsAfterRemoval`**，实现 `SpiritHerbPlant` 就自动得到这两件事。
- 「这一格有没有记录」＝「它是不是播种出来的」：附件有记录就是播种的，没有就是野生的。**两者不需要额外的标记位**。

### 3.7 `Growth` 字段变动

```java
public record Growth(List<Entry> seeds, int matureAge, int maxAge, NumberProvider growthRate,
                     BlockCondition condition, List<Cost> costs, ItemStackTemplate harvest,
                     NumberProvider wildAge) {          // 原来是 Identifier texture
```

- **删 `texture`**（外观归方块），连同 `textureResource()` 与 `validate` 里那一句 `growth.texture must name a texture`（`:145-146`）。
- **加 `wild_age`**：可选 `NumberProvider`，默认常量 0；**必须可用 Random 求值**——本仓库的 `NumberProvider` 就是干这个的（`util/formula/NumberProvider.evaluate(FormulaContext)`，`Uniform.evaluate:23` 读 `context.random()`）。
- JSON 键名不变的部分照旧（`seeds` / `mature_age` / …），所以**老包里写着 `texture` 的那一行会静默失效**——`RecordCodecBuilder` 不认识未知字段（`AGENTS.md` §4），字段变动必须同步测试包与文档站。

## 4. 边界与坑

| # | 边界 | 怎么办 |
|---|---|---|
| B1 | **区块附件没有方块生命周期钩子**：方块被挖掉/炸掉/替换时没人通知附件，会留下死记录 | 只在 `settle` 里回收：那一格的方块已经不是 `SpiritHerbPlant` 就删记录（§3.3 第 3 步）。所以**死记录最多留到下一次性结算的 20 tick 内**；它只是浪费一点存档，不会长出东西。不靠方块自己回调——那要求每个实现都记得写 |
| B2 | **一次解码失败丢整行** | 用 `CollectionCodecs.list`（逐行容错），不要用裸 `Codec.list` |
| B3 | **gameTime 会倒退**（崩档/回滚，最多约 5 分钟） | `max(0, now - settled_at)`，负数当 0；**不抛异常** |
| B4 | **补算要有上限** | §3.4，复用 `ticks_per_year` |
| B5 | **必须 `markUnsaved()`** | §3.5；这是本仓库第一处 |
| B6 | **`ProtoChunk` → `LevelChunk`**：附件在提升时拷贝，但提升前写入的记录要注意时机 | 只在服务端、只在已加载的 `LevelChunk` 上写；`level.getChunkAt(pos)` 已保证 |
| B7 | **播种不继承种子药龄** | 拍板 ⑪：起点恒为 0，堆上的 `mxt:herb_age` 不跟着走（与今天、与 `research/57` 一致） |
| B8 | **物品侧的年龄不变** | 堆上的药龄仍是「组件优先、否则 `default_age`」，**永不自己增长**；只有 `harvestStack` 写 `mxt:herb_age` |
| B9 | **`preRemoveSideEffects` 会消失** | 它跟着 `SpiritHerbPlotBlockEntity` 一起删（调用点只有 `LevelChunk.java:307-315`）。破坏掉落改由本体在 `BlockDropsEvent` 上补：`dropOnRemove` 把收成与种苗塞进那一份**已经捕获好的 `getDrops()` 列表**（`Block.beginCapturingDrops` 抓的是入世前的实体集），而不是在方块里自己 `popResource`——**这样爆炸、活塞、`/setblock` 都一样有掉落**，方块不用覆写任何移除钩子 |
| B10 | **土床的挖掘标签与掉落表** | `data/minecraft/tags/block/mineable/shovel.json` 里那一行、`loot_table/blocks/spirit_herb_plot.json`、`blockstates` / `items` / `models` 三份 JSON 与两条 lang 键、`incomplete/unfinished.json:7` 一起删。**`shovel.json` 整个文件只剩那一行，所以整份删掉**（挖不动的土床不存在之后，那份标签就是空的） |
| B11 | **破坏掉落跑在原版已经清掉方块之后** | `BlockDropsEvent` 的类注释写明方块「已经被移出世界，或在事件结束后被移出」。所以 `herb()` **收 `BlockState` 当入参**（§3.6），服务不能在这条路径上回头 `level.getBlockState(pos)` |
