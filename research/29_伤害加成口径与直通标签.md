# 伤害管线：无归属伤害的加成口径与 `mxt:no_bonus` 直通标签

## 基准

- 对着写的代码：`runtime/damage/DamageCalculationService.java`（两层结算的唯一出口）、
  `runtime/damage/DamageEventBridge.java`（第二层的挂点）、`runtime/damage/DamageElements.java`（这一击是什么元素）、
  `runtime/ability/AbilityService#withAbilityScaling`（把 `damage_multiplier` / `element_modifier` 写进施放上下文）、以及四个发伤害入口（
  `mxt:damage`、`mxt:damage_target`、阵法 `attack`、`mxt:explode`）。
- 对着写的文档：[`docs/数据包格式.md`](../docs/数据包格式.md) 的「伤害结算」一节。
- 起因（用户要求）：**深度检查伤害系统的实体上下文传递**；把"有攻击者就算攻击者加成、没有就不算，然后再算被击者"这条规则钉死；并新增一个
  **直通标签**，默认收虚空伤害。

## 一、检查结论：上下文传递本身是通的

| 环节        | 结论                                                                                                                                                                                                                                                 |
|-----------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 攻击者 → 第二层 | **通**。`deal` 把攻击者记成 `DamageSource` 的 causing entity（`new DamageSource(type, attacker)` → `direct == causing == attacker`），第二层在事件里用 `DamageElements.strike(source)` 的兜底 `source.getEntity()` 把它读回来。所以"没有显式声明元素"的一击，元素身份就是靠 `DamageSource` 传播的。      |
| 第二层的挂点    | **正确**。`LivingEntity#hurtServer` 在无敌/已死/抗火这些"本来就不产生伤害"的提前返回之后 push `DamageContainer`，随即经 `CommonHooks#onEntityIncomingDamage` 发 `LivingIncomingDamageEvent`——在护甲/附魔减免**之前**、每段伤害序列**恰好一次**。`Player` 与 `ServerPlayer` 都 `super.hurtServer`，所以玩家也覆盖。 |
| 两层是否重复    | **不重复**。第一层只在发伤害处乘，第二层只在事件里乘。                                                                                                                                                                                                                      |
| 四个入口的归属   | `mxt:damage_target` → 施加者；`mxt:damage` → 施法者**除非它打的正是自己**（自伤无归属）；阵法 `attack` → 按 `attribute_to_owner` 决定；`mxt:explode` → 施法者。                                                                                                                      |
| 绕过管线的路径   | `ConsumeHealthItemAction` 直接 `hurtServer(magic)`（只有第二层）、方块版 `mxt:explode` 用 `explosion(null, null)`（无归属）。两者都是"没有攻击者"，符合下面的新口径。                                                                                                                     |

## 二、要修的差异：**无归属时第一层仍然读了元素关系**

`outgoing` 原本无条件乘四个因子：

```
amount × masteryMultiplier(context) × elementMultiplier(context)
       × physiqueMultiplier(attacker, true) × overcomeMultiplier(elements, target)
```

`attacker == null` 时，前两项照旧生效（**这是有意的**，见下），`physiqueMultiplier(null, …)` 本来就是 `1.0`，但 *
*`overcomeMultiplier(elements, target)` 不是**：只要这一击带着一个被元素认领的伤害类型（`element` / `damage_type` 声明过），
`elements` 就非空，于是**自己灵根之间的克制关系会被乘进自伤**。

这与文档已经写下的口径矛盾——`docs/数据包格式.md` 的「被收拢进来的发伤害路径」第一条写着 `mxt:damage` "默认**没有归属**
，因此不吃元素关系……`damage_multiplier` 是另一回事：它是'这次施放值多少'
，只要这次伤害是由一次带水平的施放打出的就照样生效（功法越强，反噬越重）"。也就是说：**文档说的是"关系不算、施放加成照算"
，代码实现的是"关系也算"**。这是一处实现与文档不一致，不是设计变更。

### 定案（用户 2026-09-22 拍板）

- **没有攻击者 → 不读"体质（打出）"与"元素克制"，但保留上下文里的 `damage_multiplier` 与 `element_modifier`。**
- 有攻击者 → 四个因子照旧，与从前完全一致。

也就是说只有 `attacker == null` 这一支发生变化，且只少一项（`overcomes`）。自伤/反噬的数值因此变成"基础值 × 施放加成"
，不再叠加自己的克制关系。

## 三、新增：`mxt:no_bonus` 直通标签

```text
data/mxt/tags/damage_type/no_bonus.json
```

```json
{
  "replace": false,
  "values": [
    "minecraft:out_of_world"
  ]
}
```

- 这是**原版 `damage_type` 注册表**上的标签（不是模组自己的动态注册表），所以路径是 `tags/damage_type/`，`mxt`
  命名空间由模组自己提供默认内容。
- **默认内容只有虚空伤害 `minecraft:out_of_world`**（常量名是 `DamageTypes.FELL_OUT_OF_WORLD`，`LivingEntity` 掉出世界时每
  tick 4 点那个）。内容包可以用同一个标签路径**追加**自己的类型（原版标签默认合并，`replace: false`），写 `"replace": true`
  则整体替换掉默认值。
- **语义：整条管线直通。** 命中标签的一击
    1. 不过第一层：不乘 `damage_multiplier`、不乘 `element_modifier`、不读攻击者体质、不读元素克制；
    2. 不过第二层：不读受击者的 `adapted_to`、不读受击者体质；
    3. **也不在受击者身上留下元素**（`ElementReactionService` 不参与）。
       数值原样交给原版，之后**原版自己的减免照旧**（护甲、附魔、抗性、吸收、无敌帧），我们只是不碰它。
- 判定点是**伤害类型**（`DamageSource#is(tag)`），所以它对所有来源一视同仁：模组自己的 `mxt:damage`
  、别的模组打过来的、原版的环境伤害，只要类型在标签里就直通。
- 三个执行点，同一份判定（`DamageCalculationService#bypasses`）：`deal`（发伤害处的第一层与整条直通）、`DamageEventBridge`
  （第二层与元素附着）、`ExplodeAction` 的伤害计算器（爆炸的第一层）。

### 为什么默认是虚空伤害

掉出世界的每 tick 伤害是**纯粹的处决**：它由位置决定、无攻击者、也没有任何"谁更强"
的含义。任何一个按比例放大/减免的口径在这里都会让"被虚空杀死"这件事变得可被体质或功法左右，所以它默认直通。

## 四、不做 / 推迟

- **不动 `mxt:explode` 的自我归属。** `mxt:damage` 会在"打的正是施法者自己"时把归属清空，`mxt:explode`
  不会——这是它自己的类注释里写明的差异（"爆炸归因于施法者，不像 `mxt:damage`"），本轮不改。副作用是自爆仍会读一次自己的克制关系，已记在「开放项」。
- **不给标签加配置项开关。** 标签本身已经是数据包口径：不想要就 `replace: true` 写空表。
- **不把标签做成"元素免疫"或"伤害免疫"。** 它只声明"这一击不参与加成结算"，不拒绝伤害、不改归属、不影响击杀统计。

## 五、验证方式

- 编译：`./gradlew compileJava compileTestModJava --console=plain`。
- 探针：`/mxt_test damage` 新增两条腿（另见 [`docs/模块实现审计.md`](../docs/模块实现审计.md) 的探针行）——
    - **无归属腿**：带攻击者灵根的火攻击者在 `attacker = null`、伤害类型声明为火认领的 `minecraft:magic` 时，第一层应等于"
      基础值 × 施放加成"（**不含** 1.5 的克制），实机掉血再乘第二层的 0.5；
    - **直通腿**：给双方都挂上 `probe_body` 体质（打出 ×1.5、受到 ×0.5），用默认标签里的 `minecraft:out_of_world` 打 10
      点——过管线会是 `10 × 1.5 × 0.5 × 0.5 = 3.75`，直通必须是 **10.0**；同一行同时断言标签真的装上了（
      `bypasses(out_of_world)` 为真、`bypasses(magic)` 为假），否则标签文件放错位置不会有任何东西报错。
- 未实跑的部分照例写明。
