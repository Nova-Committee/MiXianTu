# 阵法灵气吸收范围：球体与立方体的边界段开销

一句话：**同一个 `radius` 参数下立方体的边界段是球体的 1.28～1.34 倍，但那个半径下立方体覆盖的方块也多 1.9 倍；把覆盖量拉平（等体积，立方体半边长 `0.806r`）之后反过来——立方体的边界段只有球体的 0.80～0.85 倍，渐近 0.834。**

这个目录是那份建模脚本与九张图，不是设计稿。数据由 `section_cut.py` 现算，运行一次约 5 秒。

## 被建模的成本

`runtime/world/BlockAuraService.java:118` 的 `groundInSphere` 对每个 16³ 子区块只有三种去向：

| 分支 | 判定（代码原样） | 代价 |
| --- | --- | --- |
| 够不着 | `sphereReaches`：段内**最近**的方块中心在球外 | 跳过，一格都不读 |
| 完全包住 | `sphereCovers`：段内**最远**的方块中心在球内 | 调色板 `count()`，一次 O(调色板项) |
| 其余（边界段） | 两个判定都不成立 | **4096 次逐格判定** |

第三种是唯一按块计的成本，也是唯一跟着「边界」而不是「体积」走的成本。本目录数的就是它。

## 模型怎么和代码对上

- **按方块中心判定**：`static` 的边界判定是 `center.distToCenterSqr(x+0.5, y+0.5, z+0.5) > radiusSquared`。`BlockPos.distToCenterSqr` 把接收者当方块中心，所以量的是「阵心方块中心」到「被查方块中心」的距离。改成 `index = block - 阵心方块` 的整数偏移后，判据就是 `a² + b² + c² ≤ r²`，没有浮点尾数问题。
- **中心位置只有 16³ 种**：阵心永远在一个方块的中心上，世界坐标再连续，子区块格子能感受到的只有 `阵心方块 mod 16` 那三个 0..15 的余数。半径为公式值时可取任意实数，本脚本扫整数 1..128（脚本里 65 以上隔一取一）。
- **对称约简**：把三个轴同时反射后，偏移 `m` 与 `15 - m` 的计数相等（`m` 是阵心方块在自己段内的位置）。因此扫 8³ 个偏移即可，全 4096 个偏移的均值、极值、直方图与它逐项相等。脚本开头就把这件事跑一遍校验。
- **立方体对立面**：`|a| ≤ r ∧ |b| ≤ r ∧ |c| ≤ r`，用同一套「最近/最远方块中心」三分支。不另设一个更聪明的立方体实现——比较的是形状，不是实现。
- **校验**：`validate()` 做三路对照——8³ 对称约简 vs 全 4096 格、闭式最近/最远距离 vs 逐格暴力循环（`r = 1 / 7.5 / 12 / 16 / 33`，偏移 `(0,0,0) / (3,5,7) / (2,9,14)`，球与立方体各一遍），全部一致才继续。

## 等体积（拉平覆盖量）

以球体半径为基准，取**体积相同**的立方体。立方体半边长 `h` 的体积是 `8h³`，令 `8h³ = 4/3πr³` 得 `h = r·(π/6)^(1/3) = 0.806r`，边长 `2h = 1.612r`。（把「边长」当成范围参数会得到一个体积 8 倍的立方体——这个坑我第一版就踩了，见文末「修正」。）

| radius（球体） | 立方体半边长 | 球体边界段 | 等体积立方体边界段 | 立方体 ÷ 球体 | 球体覆盖方块 | 立方体覆盖方块 |
| --- | --- | --- | --- | --- | --- | --- |
| 8 | 6.45 | 6.30 | 5.36 | 0.850 | 2,109 | 2,197 |
| 16 | 12.90 | 19.15 | 15.38 | 0.803 | 17,077 | 15,625 |
| 32 | 25.79 | 71.93 | 58.80 | 0.817 | 137,065 | 132,651 |
| 64 | 51.58 | 283.82 | 234.76 | 0.827 | 1,097,917 | 1,092,727 |
| 128 | 103.17 | 1,131.52 | 943.15 | 0.834 | 8,782,785 | 8,869,743 |

**结论翻转：覆盖量相等时立方体反而省 15～20%（渐近 0.834）。**

- 「同一个 `radius` 参数」下球体更省（1.28～1.34 倍），**原因是立方体覆盖了 1.9 倍的地**，不是它效率低。
- 一旦按等效范围比较，球体那种斜穿格子的边界反而更贵。

原因在「解析对照」：成本跟着 `∫(|n_x|+|n_y|+|n_z|) dA` 走，轴对齐的平面在这套度量下最便宜，斜的球面最贵。

**阵心位置的敏感性**（同一半径下最坏偏移 ÷ 最好偏移）：

| radius | 球体 | 立方体 |
| --- | --- | --- |
| 32 | 1.34 | 1.61 |
| 64 | 1.17 | 1.78 |
| 128 | 1.05 | 1.88 |

立方体的波动来自它的面能不能正好落在子区块边界上——对齐时整层边界段直接消失，所以曲线是「台阶 + 每 16 格掉一截」（图 6）。球面永远斜穿格子，没有这种对齐，波动随半径反而收敛。

## 解析对照

数字和几何估计对得上，说明模型没跑偏。一个面穿过的 16³ 格子数 ≈ `∫(|n_x|+|n_y|+|n_z|) dA ÷ 16²`：

| 形状 | `∫Σ\|n_i\| dA` | 边界段 ≈ | 实测（`r=128`） |
| --- | --- | --- | --- |
| 球体，半径 r | `6πr² = 18.85r²` | `0.0736 r²` | `0.0691 r²` |
| 立方体，半边长 r（同半径） | `6(2r)² = 24r²` | `0.0938 r²` | `0.0887 r²` |
| 立方体，半边长 0.806r（等体积） | `6(1.612r)² = 15.59r²` | `0.0609 r²` | `0.0576 r²` |

- 同半径比 `0.0938/0.0736 = 1.27`，实测 1.28～1.34。
- 等体积比 `0.0609/0.0736 = 0.827`，实测 0.834。
- 关键不是表面积而是「按轴分解后的表面积」：等体积立方体的面积（15.59r²）其实**比球面（12.57r²）还大**，可它的每个面元都在竖直或水平地穿格子，`∫Σ|n_i|` 反而更小。球面每个面元都斜着走，同样面积要多穿 1.5 倍（`6π/4π`）的格子。
- 实测普遍比估计低 5～8%：相邻面元穿到同一段会重复计数，反过来对齐的段又会互相抵消。

## 没建模的东西

- **只算已加载区块**：`AuraDistributionService.ground` 里 `hasChunk` 为假直接跳过，不加载。两种形状同样被削，不影响比较。
- **空段不计**：`hasOnlyAir` 与 `maybeHas` 不成立的段根本不到边界判定。本模型把每个段都当作有发射器，是**最坏情况**。
- **垂直上限**：`getHighestFilledSectionIndex()` 以上的段直接跳过。实际地表的阵法，上半球往往整段是空气，真实数字会明显低于表里；两种形状同样受益。
- **区块枚举范围**：方形 chunk 环对两者相同，不计入差异。
- **完整段也不是免费**：调色板 `count()` 一次 O(调色板项)，本目录只给段数，不给加权成本。
- **每格还有一次哈希查表**（`RegistryCaches.BLOCK_AURA`），两形状常数因子相同。
- **`drawsEnvironment` 打开时的额外一段**：阵心所在整段的解析环境灵气（`AuraDistributionService.ambientSupply`）与 `radius` 无关，两种形状一样多一段，不参与比较。

```bash
python section_cut.py
```

需要 `numpy` 与 `matplotlib`（图表用 Microsoft YaHei 画中文）。脚本先打印三路校验，再打印同半径与等体积两张表，最后覆盖九张 PNG。

## 对设计的含义

1. **「哪个形状更省」取决于口径**：同 `radius` 参数比，球体省 1.28～1.34 倍；同样覆盖量比，立方体省 15～20%。前者是因为立方体多覆盖了 1.9 倍的方块，不是它效率低。
2. **等体积下球体是更贵的那个**：它的边界斜穿格子，同样面积要多扫约 1.5 倍。要换形状就得同时改 `radius` 的语义（半个边长而不是半径），否则玩起来范围会缩到 0.8 倍、还多付一块成本。
3. **立方体省得不稳**：它的成本随阵心在段内的位置在 1.6～2.5 倍之间跳（面与段边界对齐时掉一整层），球体只 1.04～1.34 倍。省的那 17% 是均值，单个阵法可能落在更差的位置上。
4. **真正还能压的是算法，不是形状**：边界段成本固定是「段数 × 4096」。段数 ≈ `∫Σ|n_i|dA/256`，换形状只能在这条式子上挪 20%；想再降一个数量级，只能让边界段不整段扫（例如再切成 4³ 的小块先判），那是另一件事。

## 修正

本文第一版把「等体积立方体的**边长** `1.612r`」当成了模型里的范围参数（也就是半边长），算出来的是一个体积 8 倍的立方体，于是得出了「等覆盖量要 3.3 倍」的错误结论。正确做法是 `h = r·(π/6)^(1/3) = 0.806r`（边长 `1.612r`），比值也因此从 3.3 变成 0.83。`section_cut.py` 里的 `EQUAL_VOLUME` 就是 `(π/6)^(1/3)`，表里的立方体覆盖方块数（`(2⌊h⌋+1)³`）与球体一列对得上，可以直接当校验用。
