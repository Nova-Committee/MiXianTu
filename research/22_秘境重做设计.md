## 0. 结论摘要

1. **现状**：`realm_instance` 只有 5 个字段（`dimension`/`duration_ticks`/`max_members`/`enter_action`/`exit_action`
   ），主资源里连一条默认定义都没有；"实例"其实是**挂在关卡附件上的一份共享状态**，`max_members`
   只是这份共享状态的并发人数上限；入口落点写死在目标维度的 `(0.5, height, 0.5)`。
2. **重做的实质不是加字段，而是换模型**：从"某个已存在维度上的一份共享状态"改成**"
   按需创建、可并存多份、用后销毁的实例维度"**。只有这样，`max_instances`（第 2 点）、`owned`（第 7 点）、边框（第 1 点）、结构（第 5
   点）才有意义；否则多份实例会挤在同一个维度里互相踩。
3. **9 点需求的落点分布**：第 1/2/3/6/7/9 点基本是定义层（JSON + 现有服务里的分支）；第 4/5 点需要新机制——运行时维度构造（
   `RuntimeDimensionService` 现在**全仓无调用者**，是备用件）与 NBT 结构放置（现仓库完全没有 `StructureTemplate` 相关代码）。第
   8 点沿用现有的两个 `EntityAction` 槽位。
4. **向 ResourceWorld 借四件事**：`LevelStem` 直取 / 超平坦两种生成方式（外加我们要补的空世界与"直接用已有维度"）、运行时
   `ServerLevel` 构造（本模组的 `RuntimeDimensionService.load` 已经是它的精简版）、**每维度种子覆写**、**每维度边框强制 + 广播
   **。它还有"从模板文件夹复制 region 文件"的第五种方式，见 §3.1。
5. **一条现成的整合路径**：`AuraService.matchesDimension` 拿 `aura_zone.dimensions` 的**标识符**去比对关卡维度 id（
   `RegistryCodecs.matchesKey`），所以只要实例维度键可预测，数据包就能用 `aura_zone` 给秘境铺灵气，不需要新字段。

## 2. 新 JSON 结构

文件位置不变：`data/<namespace>/mxt/realm_instance/<path>.json`。

### 2.1 完整示例

```json
{
  "generation": {
    "type": "mxt:void",
    "biome": "minecraft:the_void",
    "dimension_type": "minecraft:the_end"
  },
  "seed": 0,
  "border": {
    "center": [0.0, 0.0],
    "size": 256.0,
    "warning_blocks": 5,
    "damage_amount": 0.2
  },
  "max_instances": 2,
  "max_members": 4,
  "owned": true,
  "duration_ticks": 12000,
  "structures": [
    { "nbt": "mxt:trial/arena", "pos": [0, 64, 0] },
    { "nbt": "mxt:trial/pillar", "pos": [32, 64, 0], "rotation": "clockwise_90", "integrity": 0.8 }
  ],
  "entry": {
    "pos": [0.5, 65.0, 0.5],
    "yaw": 0.0,
    "pitch": 0.0,
    "random_center": [0.0, 0.0],
    "random_radius": 64.0,
    "spread": 3.0
  },
  "enter_condition": [
    { "type": "mxt:has_spirit_root", "spirit_root": "mxt:fire_root" }
  ],
  "enter_denied_message": "realm.mxt.trial.denied",
  "enter_action": { "type": "mxt:apply_effect", "effect": "minecraft:night_vision", "duration_ticks": 12000 },
  "exit_action": { "type": "mxt:heal", "amount": 4 }
}
```

最小定义（只有第 4 点必填的维度生成）：

```json
{ "generation": { "type": "mxt:stem", "stem": "minecraft:the_end" } }
```

### 2.2 字段总表

| 字段                     | 类型                       | 默认                | 说明                                                                                                                                                                               |
|------------------------|--------------------------|-------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `generation`           | 生成参数对象                   | **必填**            | 第 4 点。写实例维度的生成器与维度类型，见 §3。                                                                                                                                                       |
| `seed`                 | Long                     | `0`               | `0` 表示每个实例随机一个种子；非 0 则所有实例共用。                                                                                                                                                    |
| `border`               | 对象，可空                    | 无（原版默认边界）         | 第 1 点。`center`（`[x,z]`，默认 `[0,0]`）、`size`（直径，默认原版默认值）、`warning_blocks`、`warning_time`、`damage_amount`、`damage_buffer`。缺省 = 不写该维度的 `WorldBorder`，并把它设回原版默认值（**不继承主世界**，理由见 §4.6）。 |
| `max_instances`        | Integer ≥1               | `1`               | 第 2 点。同一定义同时存在的实例上限。                                                                                                                                                             |
| `max_members`          | Integer ≥1，可空            | 无（不限）             | 第 3 点。**每个实例**的同时在场人数上限。                                                                                                                                                         |
| `owned`                | Boolean                  | `false`           | 第 7 点。实例是否有主，见 §4.5。                                                                                                                                                             |
| `duration_ticks`       | Long ≥0                  | `0`               | 沿用旧字段。`0` = 不过期。                                                                                                                                                                 |
| `structures`           | 数组，可空                    | `[]`              | 第 5 点。实例创建时放置的 NBT 结构列表，见 §4.7。                                                                                                                                                  |
| `entry`                | 对象，可空                    | 无（随机落点）           | 第 6 点。`pos`/`yaw`/`pitch` 给定则固定落点；缺 `pos` 则按 `random_center`+`random_radius`（默认边界中心 + 边界内）随机，见 §4.8。                                                                             |
| `enter_condition`      | `EntityCondition`（单个或数组） | `mxt:always_true` | 第 9 点。对进入者求值，公式上下文为玩家自身；不成立则拒绝进入。                                                                                                                                                |
| `exit_condition`       | `EntityCondition`        | `mxt:always_true` | 第 9 点。**只约束主动离开**（令牌右键、`/mxt realm_instance exit`）；过期与强制遣返绕过它，否则数据包能把玩家永久锁死。                                                                                                     |
| `enter_denied_message` | `Component`（字符串=翻译键）     | 无                 | 条件不成立时发给玩家的提示；缺省则退回到现有的 `item.mxt.realm_token.enter_failed` + 失败名。                                                                                                               |
| `exit_denied_message`  | `Component`              | 无                 | 同上，作用于退出条件。                                                                                                                                                                      |
| `enter_action`         | `EntityAction`           | `mxt:no_op`       | 第 8 点。沿用旧字段，作用于进入者，时机在传送落位之后。                                                                                                                                                    |
| `exit_action`          | `EntityAction`           | `mxt:no_op`       | 第 8 点。沿用旧字段，作用于离开者，时机在传送回原位置之前（沿用现状）。                                                                                                                                            |

`Component` 用现成的 `MiscCodecs.TRANSLATABLE_COMPONENT`（裸字符串 = 翻译键，对象 = 完整组件），与其它定义侧文案一致。

### 2.3 校验

**加载期（同一个文件内的自洽性，安全）**：

- `structures[].integrity` ∈ `[0,1]`，`pos` 三元素必需；`entry.yaw/pitch` 有限。
- 若同时写了 `border.size` 与坐标（`structures[].pos`、`entry.pos`），坐标必须落在边界内，否则 `DataResult.error`。
- `max_instances ≥ 1`、`max_members ≥ 1`（写了的话）、`duration_ticks ≥ 0`、`seed` 任意。

**不做加载期跨注册表读取**：`generation` 里的 `stem`/`dimension`/`biome`/`dimension_type`/`template` 与
`structures[].nbt` 都只在**实例创建时**解析。理由与 `research/21` §E1b 记录的一致：数据包注册表并行加载，加载期拿不到已绑定的
holder；而且 `dimension_type`/`level_stem` 属于动态层，定义解码时未必可用（`RegistryCodecs.keyOrTagList`
的注释就是为这个场景写的）。解析失败 → 实例创建失败并记一次日志（§4.10 `GENERATION_FAILED` / `MISSING_STRUCTURE`）。

## 3. 维度生成参数（`generation`）

用 `MapCodec` 分派，注册表键 `mxt:realm_generation_type`，与 `MxtRegistries.ENTITY_CONDITION_TYPE` 同构（
`MxtRegistries.create("...", MxtResourceKeys.REALM_GENERATION_TYPE)`）。

### 3.1 五种方式与 ResourceWorld 的对照

| `type`         | ResourceWorld 对应                                                | 含义                                                          | 参数                                                                                                                                                                                                          | 必需性         |
|----------------|-----------------------------------------------------------------|-------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-------------|
| `mxt:stem`     | `type` / `mirror`（两者都是 `LEVEL_STEM.getOrThrow(key)`，本模组合并为一个名字） | 取某个已注册 `LevelStem`（生成器 + 维度类型）当模板，开一份**新维度键**的实例            | `stem`（`ResourceKey<LevelStem>`）                                                                                                                                                                            | 核心          |
| `mxt:flat`     | `flat`                                                          | 超平坦：层串 + 生物群系                                               | `preset`（`"1*minecraft:bedrock,2*minecraft:dirt,minecraft:grass_block;minecraft:plains"` 语法，`FlatGenerateOption.createFromString` 可原样移植）、`dimension_type`（默认 `minecraft:overworld`）、`structures`（默认 `true`） | 核心          |
| `mxt:void`     | 无（新增）                                                           | 空世界：无层、单生物群系、不生成结构。秘境最常见的地基                                 | `biome`（默认 `minecraft:the_void`）、`dimension_type`、`structures`（默认 `false`）                                                                                                                                  | 核心          |
| `mxt:template` | `template`                                                      | 从**存档目录**里的模板复制 `region`/`entities`/`poi` 到新维度文件夹后再加载       | `template`（`[A-Za-z0-9_-]+`，根目录 `<server>/mxt_realm/<name>/`）、`stem`                                                                                                                                        | 可选（见 §9 Q2） |
| `mxt:existing` | 无（旧 `dimension` 语义）                                             | 不创建维度，直接用已存在的维度（含数据包 `dimension/` 条目）。`max_instances` 只能是 1 | `dimension`（Identifier）                                                                                                                                                                                     | 可选（见 §9 Q2） |

`mxt:template` 与 `mxt:existing` 之外的三条都要求实例维度是**新造**的，因此各自的区域文件天然隔离在
`dimensions/<ns>/realm/<path>/<n>/` 下。

### 3.2 维度键、种子与解析时机

- **维度键**：`<定义命名空间>:realm/<定义路径>/<序号>`，序号从 `0` 起且**始终存在**（只能开一份的定义也带 `/0`
  ）。用定义自身命名空间是为了让 `aura_zone.dimensions` 能直接写出来（`matchesDimension` 只比标识符），也让 `/execute in` 可读。
- **种子**：`seed != 0` → 所有实例同种子；`seed == 0` → 每个实例 `RandomSource` 取一个随机 long，**存进实例记录**
  （这是实例状态必须持久/可查的原因之一）。落地方式移植 ResourceWorld 的 `ServerLevelMixin`：`@ModifyExpressionValue` 拦
  `ServerLevel.<init>` 里的 `WorldOptions.seed()`，查询"正在构造的维度 → 该实例的种子"；同时 `getSeed()`
  返回同值，保证特性/结构放置使用同一种子。构造期需要一张 `正在构造的维度键 → 种子` 的临时表（`ThreadLocal` 或构造前后
  set/remove 的 Map，`RuntimeDimensionService.load` 里包一层）。
- **维度类型**：`flat`/`void` 从 `Registries.DIMENSION_TYPE` 取（默认 `minecraft:overworld`）；`stem` 从被引用的 stem 里取；
  `existing` 用原维度的。
- **解析时机**：全部在实例创建时，`server.registryAccess()` 已在手，不再有并行加载问题。

## 4. 运行时模型

### 4.1 实例身份

一个实例 = `(定义, 序号)`，具体化为一个维度键（§3.2）。**实例身份用维度键表达**，超时/销毁/查询都靠它，不再需要"
关卡附件里那份状态"这种模糊身份。

### 4.2 实例记录与存储

```java
record RealmInstanceState(Holder<RealmInstance> definition, int index, ResourceKey<Level> dimension,
                          long seed, @Nullable UUID owner, List<UUID> members,
                          long startedAt, long expiresAt, boolean ready) {}
```

- 存放在新的服务端全局表 `runtime/world/RealmInstanceRegistry`（与 `ServerCache` 同样挂在服务器生命周期上的内存表），**不跨重启
  **（见 §9 Q5）。
- 删除 `attachment/RealmInstanceAttachment.java` 与 `MxtAttachments.REALM_INSTANCE`（旧存档里的数据会被 NeoForge
  当未知附件丢弃，可接受：模组未发布，且旧语义已被取代）。`RealmTravelAttachment`（玩家侧回程坐标）保留不动。
- `ready` 表示"维度已建好、结构已放置"，避免半成品实例被选进。
- 启动时清扫：扫描 `dimensions/*/realm/` 下遗留的实例目录并删除（崩溃残留），保证"不跨重启"是干净的。

### 4.3 生命周期

| 阶段     | 动作                                                                                                               |
|--------|------------------------------------------------------------------------------------------------------------------|
| 创建     | 解析 `generation` → 构造 `LevelStem`（带实例种子）→ `RuntimeDimensionService.load` → 设边框 → 放置 `structures` → 登记为 `ready`    |
| 进入     | 选定实例 → `EnterPre`（可取消）→ 加成员 → 传送落点 → `EnterPost` → `enter_action`                                                |
| 离开（主动） | `exit_condition` 校验 → 传送回 `RealmTravelAttachment` 记录的精确坐标 → 移除成员 → `Exit` 事件 → `exit_action` → 实例空则销毁            |
| 过期     | `duration_ticks` 到期，逐成员遣返（**跳过 `exit_condition`**），销毁实例                                                          |
| 销毁     | 传送出所有成员 → `RuntimeDimensionService.unload` → 删除整个实例目录（只清 `region`/`entities`/`poi` 不够：`data/` 里存着关卡与附件数据）→ 从表里移除 |
| 离线     | 沿用 `RealmTravelEventBridge#returnIfOrphaned`：登录时若其所属实例已不存在，送回原点                                                  |

### 4.4 实例选择、人数与实例上限

进入时的选择顺序（伪码）：

```
候选 = 该定义的全部 ready 实例
若 owned：候选 = 候选.Where(主人 == 玩家)
可加入 = 候选.Where(玩家已是成员 || max_members 未满)
若 可加入 非空 → 取最早创建的（FIFO，保证 "max_instances=1 时大家进同一份" 与旧行为一致）
否则若 计数(owned ? 该主人的实例数 : 全部实例数) < max_instances → 新建实例后进入
否则 → 失败 NO_FREE_INSTANCE
```

- `max_members` 缺省 = 不限（内部用 `Integer.MAX_VALUE`）。
- 已满且未达实例上限 → 建新实例；达上限 → `NO_FREE_INSTANCE`。
- 计数口径在 `owned` 下按主人分（见 §9 Q3）。

### 4.5 主人（`owned`）

建议语义（**待拍板，§9 Q1**）：

- `owned: true` → 首个进入者成为主人并写进实例记录。
- 实例**按主人分组**：主人只能进自己名下的实例；`max_instances` 按主人计数，于是"每人最多 N 份自己的秘境"。
- 主人身份向数据包暴露：`enter_action`/`exit_action` 的公式上下文与 `mxt:in_realm_instance` 条件可判定 `role: owner`
  ，将来挂"主人专属奖励/权限"不用再改定义。
- 与 `max_members` 配合 = 主人带队刷本；`max_members` 缺省时主人可以带无限人。
- 实例不因主人离开而立刻销毁（否则队长掉线全队被踢），只在**成员清空**或**过期**时销毁。

### 4.6 边框（`border`）

- 实例维度建好后对 `ServerLevel#getWorldBorder()` 设 `center`/`size`/`warning`/`damage`，并向该维度玩家广播
  `ClientboundInitializeBorderPacket`（ResourceWorld 的 `WorldBorderMixin` 做法）。
- **缺省 `border` 时**：运行时维度的 `DerivedLevelData` 会把主世界的边框设置带进来（ResourceWorld 正是为此写了 config
  版），所以"无限制"要**显式**设成原版默认值（`29999984`），而不是"什么都不做"。这一点写进文档，免得当成 bug。
- 不做逐 tick 重推（我们没有可变的边框配置）；若将来要"缩圈"，加 `border.shrink_to`/`shrink_ticks` 两个字段即可，无需改结构。

### 4.7 结构放置（`structures`）

| 字段                  | 类型             | 默认      | 说明                                                                                            |
|---------------------|----------------|---------|-----------------------------------------------------------------------------------------------|
| `nbt`               | Identifier     | **必填**  | `data/<ns>/structure/<path>.nbt`，走原版 `StructureTemplateManager#get(Identifier)`，因此资源包/数据包都能覆盖 |
| `pos`               | `[x,y,z]`      | **必填**  | 实例维度内的绝对坐标（`relative_to_entry: true` 时相对入口落点）                                                 |
| `rotation`          | 枚举             | `none`  | `none`/`clockwise_90`/`clockwise_180`/`counterclockwise_90`                                   |
| `mirror`            | 枚举             | `none`  | `none`/`left_right`/`front_back`                                                              |
| `integrity`         | Double `[0,1]` | `1.0`   | 结构完整度（配合随机 → 废墟感）                                                                             |
| `relative_to_entry` | Boolean        | `false` | 坐标是否相对入口落点（`entry` 缺省时以实际随机落点为基准，故"随机入口 + 相对结构"会成为每次不同的组合）                                    |
| `ignore_entities`   | Boolean        | `false` | 是否跳过结构里的实体                                                                                    |
| `keep_liquids`      | Boolean        | `true`  | 是否保留结构自带流体（对应 `StructurePlaceSettings` 的流体处理）                                                 |

放置时机：**实例创建时、任何玩家进入之前**。实现用 `StructureTemplate#placeInWorld`（`BlockPos` 偏移 +
`StructurePlaceSettings`），逐个结构前确保目标区块已加载（`level.getChunkAt(pos)`），缺 `nbt` → 创建失败 `MISSING_STRUCTURE`
并记日志（不静默跳过，避免"进去发现是空世界"）。

### 4.8 入口落点（`entry`）

- `pos` 存在 → 所有进入者落到同一点（`yaw`/`pitch` 可选，缺省沿用玩家自身角度）。
- `pos` 缺省 → 随机：在 `random_center`（默认 `border.center`，再默认 `[0,0]`）为中心、`random_radius`（默认取
  `border.size/2 * 0.8`，无边框则 `64`）为半径的圆内取点，用 `MOTION_BLOCKING_NO_LEAVES` 高度图找地面；同一批进入者按
  `spread`（默认 3.0 格）错开，避免叠在一起。
- 取点失败（例如落在虚空上）→ 退回到该维度 `(0.5, height, 0.5)`，并记一次 WARN。
- 落点确定后 `structures` 里 `relative_to_entry` 的结构才放得下，所以顺序是：**创建维度 → 定入口 → 放结构 → 传送首个玩家**
  （首个玩家的落点作为实例的"入口锚点"存进实例记录，之后的成员按 `spread` 围绕它分布）。

### 4.9 条件与行为

- `enter_condition`：`EntityCondition#test(player, FormulaContext.of(player))`，进入前求值；不成立 → `CONDITION_NOT_MET` +
  `enter_denied_message`。
- `exit_condition`：同上，**只在主动离开时**求值；不成立 → `CONDITION_DENIED_EXIT` + `exit_denied_message`。
- `enter_action` / `exit_action`：沿用 `EntityAction#execute(player, FormulaContext.of(player))`
  ，语义与现状一致（进入在落位后，离开在传送回原位置前）。
- 公式上下文额外注入实例变量（`MxtFormulaVariables` 新增）：`realm_instance_members`、`realm_instance_limit`（`max_members`
  ，无限时为 `-1`）、`realm_instance_elapsed`（tick）、`realm_instance_duration`、`realm_instance_index`、
  `realm_instance_is_owner`（1/0）。**注意命名**：`realm`/`realm_rank` 已被"境界"占用（`MxtFormulaVariables.RealmVariable`
  ），因此实例一律用 `realm_instance_*` 前缀。

### 4.10 失败枚举

保留现有 9 个（`DISABLED`/`OTHER_INSTANCE`/`FULL`/`CANCELLED`/`NOT_MEMBER`/`MISSING_DIMENSION`/`ALREADY_TRAVELLING`/
`NOT_TRAVELLING`/`MISSING_ORIGIN`），语义微调并新增：

| 失败                  | 触发                                        |
|---------------------|-------------------------------------------|
| `MISSING_DIMENSION` | 仅 `mxt:existing`：目标维度不存在（其它方式不再依赖已存在维度）   |
| `GENERATION_FAILED` | 维度构造/加载失败（生成参数非法、`LevelStem` 键不存在、模板目录缺失） |
| `MISSING_STRUCTURE` | `structures[].nbt` 解析不到                   |
| `NO_FREE_INSTANCE`  | 已达 `max_instances` 且没有可加入的实例              |
| `CONDITION_NOT_MET` | 进入条件不成立                                   |
| `EXIT_DENIED`       | 退出条件不成立                                   |
| `OTHER_INSTANCE`    | 已在另一份实例里（沿用）                              |

`RealmTokenItem` 的失败提示沿用 `result.failure().name()` 拼法；有 `enter_denied_message` 时优先显示定义里的文案。

### 4.11 事件、脚本、公式、条件

- `RealmInstanceEvent` 的 `EnterPre`/`EnterPost`/`Exit` 载荷补上"实例身份"：`definition` 之外加
  `ResourceKey<Level> dimension`、`int index`、`Optional<UUID> owner`。新增 `Create`/`Destroy` 两个事件（数据包/脚本用得上，成本极低）。KubeJS
  的 `realmInstance` 通道随载荷自动带上。
- 新增 `mxt:in_realm_instance` 实体条件（
  `{ "type": "mxt:in_realm_instance", "definition": <可选 HolderOrTag>, "role": "any|owner|member" }`）：这是 `owned` 与"
  成员"概念在数据包里的可查询出口，也让 `enter_condition`/`exit_condition` 能写出"只有主人能带人进"之类的组合。
- **灵气整合（可选，见 §9 Q7）**：`aura_zone.dimensions` 只比标识符，数据包写 `["<ns>:realm/<path>/<n>"]` 即可命中第 n
  份实例；多份实例逐个写太啰嗦。若要让"所有实例都算"，最小改动是让 `AuraService.matchesDimension` 在实例维度上**额外**比对该实例
  `generation` 里引用的 stem 标识符（约 2 行），这样 `dimensions: ["minecraft:the_end"]` 能一次盖住真实末地与所有末地型秘境。
- 管理命令 `/mxt realm_instance list|info|enter|exit|destroy`（管理员权限），用于测试与运维；`/mxt_test realm` 探针依赖它，见
  §7。

## 8. 拍板结论（2026-09-20）

| #  | 问题                              | 结论                                                                                      |
|----|---------------------------------|-----------------------------------------------------------------------------------------|
| Q1 | `owned: true` 的语义               | 用户：**可以被认领**；认领后**没人时维度卸载但不删除**，地形与结构留着，主人下次进来接着用。不做主人独占，也不因主人离开而销毁。                    |
| Q2 | `mxt:template` 与 `mxt:existing` | **都要**（模板复制用于手工搭图，`existing` 用于固定秘境维度）。                                                 |
| Q3 | `max_instances` 计数口径            | 用户：**所有实例全加起来**，不看 `owned`。                                                             |
| Q4 | 随机落点范围与多人分布                     | 以 `border` 内切 80% 为默认半径、`random_center`/`random_radius` 可覆写；同批进入者按 `spread` 错开（默认 3 格）。 |
| Q5 | 实例是否跨重启                         | **认领实例跨重启**（记录持久化在主世界附件，维度按需重新加载、不重复布置结构）；非认领实例不持久化，启动时连同地形一起清扫。                        |
| Q6 | `/mxt realm_instance` 管理命令      | 已实现（`list`/`info`/`enter`/`exit`/`destroy`）。                                            |
| Q7 | 灵气整合                            | 已实现：`aura_zone.dimensions` 可写实例维度 id、它的 `stem` 或定义 id。                                  |

用户另外追加的两点也已落地：`structures[].chance`（默认 `1.0`，每份实例独立掷一次）与 `entry` 的加权列表（单对象语法保留）。
