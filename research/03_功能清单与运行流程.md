# 功能清单与运行流程

## P0 基础能力

### 数据、同步与扩展

- 为实体、物品、区块、世界提供版本化附件，定义变更后只同步需要的字段。
- 统一资源 ID、标签、数据包加载、校验报告、热重载和客户端注册表快照。
- 在 Java 加载期注册能力类型、动作类型、条件类型、触发器类型、状态组件类型，以及 Loot Function/Condition 等原版扩展点；这些固有注册表提供 JSON 的 `type` 分派和 `MapCodec`。
- 提供可取消的前置事件和不可取消的后置事件；事件载荷必须包含定义 ID、实体/方块位置、原始数值和可修改数值。
- 提供 `/mxt` 调试命令：查询/设置附件、重载检查、列出注册表、模拟施法/突破。
- 提供 KubeJS 包装器与构建器，但所有写操作必须经服务端 API 和权限校验。

### 资源与属性

- 通用资源：以 `resource` ID 区分灵力、神魂、寿元、护盾等；提供最大值、当前值、回复、原子消耗、来源追踪和不足提示。所有配置中的资源消耗统一写为 `costs` 数组，单项为 `{ "id": "namespace:resource", "amount": number }`。
- 通用资源条：`resource_bar` 只定义 HUD 展示，资源可没有显示条；展示条可由数据包配置锚点、可见性、排序和已注册的渲染器参数。
- 通用诅咒：`curse` 是可被所有生命周期动作引用的具名数据包定义；实体和物品仅保存诅咒实例状态，施加、叠层、到期和净化均由服务端事务处理。
- 修为与境界：进度、阶段、突破前置条件、成功/失败结算。
- 元素/灵根：`element` 定义元素关系；每个灵根绑定唯一元素，多灵根实例共同决定元素修炼和法术适配。
- 体质：独立于元素的属性修正、被动能力和互斥规则；不参与元素克制或灵根修炼倍率计算。
- 神魂、寿元、业力、心魔、丹毒：提供通用数值容器、阈值触发和效果钩子。
- 通用属性修饰器：来源为功法、丹药、装备、环境、阵法或临时状态；定义优先级、叠加、刷新和互斥规则。

## P1 最小修仙闭环

### 修炼与环境

- 区块灵气：浓度、元素偏向、再生速度、灵脉引用；允许方块、结构和阵法修改。
- 修炼动作管理器：一名实体同一时刻一个主动作；统一处理开始、tick、暂停、打断、结束和冷却。
- 突破事务：预检条件 -> 触发可取消事件 -> 扣除资源 -> 执行成功率/脚本判定 -> 成功、失败或进入劫数。
- 寿元耗尽事件只负责通知和结算入口，实际死亡/转生/保命玩法由内容定义决定。

### 功法和统一能力

- `Ability` 是唯一的技能承载体：功法被动、术法、神通、秘术、灵根的元素相关效果、体质的独立被动和法宝效果均授予能力 ID；功法仅负责学习条件、冲突和能力集合。已学习功法全部同时生效。
- 能力状态机：来源激活 -> 通用条件 -> 目标校验 -> `costs` 全部资源预检 -> 吟唱/引导 -> 再校验 -> 执行动作 -> 原子提交全部扣费、组件状态和冷却 -> 结束事件。
- 能力数值公式：`Ability` 及其嵌套动作、条件、组件中的业务数值统一使用 `NumberProvider`；JSON 数字是常量简写，JSON 字符串是固有 `mxt:expression`（exp4j）表达式简写，对象形式用于其他带参数的 Provider。伤害、治疗、范围、冷却、吟唱时间、触发概率、资源成本和资源回复均可依使用者/目标上下文计算。
- 首批固有能力类型应覆盖主动、事件触发、属性修正、周期光环、持续引导和组合能力；具体参数由 JSON 表达，复杂物理或世界行为由新的 Java 类型实现。
- 动作和条件使用类型化组合：例如伤害后触发 + 双实体条件 + 实体动作；不要为“命中后火球”“受击回灵”等每种组合注册新的能力类。
- 秘术/神通使用通用资源成本与状态组件，如寿元、神魂、修为、生命、业力、冷却、充能和开关，不为每类代价写特殊分支。

### 物品与经济

- 法宝祭炼：认主、解除、温养、损坏反馈和灵力容器。
- 储物法宝：服务端容器、槽位和访问权限，禁止直接信任客户端库存包。
- 灵石统一实现 `ISpiritEnergy`，作为阵法、法宝、灵脉和交易可互通的能量媒介；品质换算由配置控制。
- 原版装备、Curios 槽位和自定义修真物品可通过标签接入属性修饰器。

## P2 扩展功能

| 功能 | 框架行为 | 内容层责任 |
| --- | --- | --- |
| 炼丹/灵食 | 炉子状态机、配方匹配、温度、时长和失败回调 | 丹方、产物、炸炉和效果。 |
| 阵法 | 多方块检测、持久化实例、区块加载管理、资源消耗 | 结构、半径、聚灵/护盾/伤害效果。 |
| 飞剑与飞行 | 挂载、移动安全检查、消耗与下马清理 | 外观、速度、攻击和解锁条件。 |
| 妖兽/灵宠 | 生物资料、契约、跟随、召回、协战命令 | 刷新权重、技能、掉落和契约代价。 |
| 天劫/心魔 | 劫数阶段、难度缩放、区域威胁和结算 | 雷击、风火、幻象、惩罚及奖励；效果通过统一能力动作接入。 |
| 锻造 | 锻打会话、数值条、目标区间、末尾 1-6 步校验、最优步数和品质结算 | 锻打方式、蓝图、成功区间、末尾序列和品质曲线。见 `06_锻造系统设计.md`。 |

## P3 内容扩展

- 宗门：成员层级、贡献货币、任务、兑换和领地权限；依赖 `title`、经济和阵法。
- 头衔：可作为成就、宗门职位、世界事件奖励的统一被动载体。
- 秘境、洞天、维度/位面：先实现传送目标与实例接口，再决定独立维度或预生成区域方案。
- 灵魂形态：死亡/濒死状态转移接口，便于救援模组通过丹药复活或改为神魂继续行动。
- 言出法随：应实现为受权限、冷却、资源和白名单限制的高阶 `Ability` 固有类型，不能提供任意命令执行。
- 装饰、服装、圣火等：作为物品/方块内容包接入标签和属性修饰器，不进入核心框架。

## 关键事件

| 事件 | 可取消 | 用途 |
| --- | --- | --- |
| `CultivationBreakEvent.Pre/Post` | Pre 是 | 突破条件、资源、成功与失败结果。 |
| `ResourceConsumeEvent.Pre/Post` | Pre 是 | 对一组 `{id, amount}` 资源成本进行修改、拒绝、审计和最终结算；不提供灵力专用扣费路径。 |
| `CultivateActionEvent.Start/Tick/Stop` | Start/Tick 是 | 自定义打坐、闭关、吞服修炼。 |
| `TechniqueLearnEvent` | 是 | 学习功法、冲突判定和奖励。 |
| `AbilityUseEvent.Pre/Post` | Pre 是 | 主动能力限制、成本修改和特效。 |
| `AbilityTriggerEvent.Pre/Post` | Pre 是 | 被动/事件触发能力的过滤、修改和审计。 |
| `CurseApplyEvent.Pre/Post`、`CurseRemoveEvent.Pre/Post` | Apply/Remove Pre 是 | 诅咒的施加、叠层、到期、净化与来源审计；取消时不写入实例状态。 |
| `ArtifactRefineEvent` | 是 | 认主、温养、充能、解除。 |
| `AlchemyCraftEvent` | 是 | 投料、控温、成丹、炸炉。 |
| `FormationEvent.Activate/Deactivate/Tick` | Activate/Tick 是 | 阵法生命周期与效果。 |
| `SpiritContractEvent` | 是 | 签订、解除、召回和契约违约。 |
| `TribulationEvent.Start/Stage/End` | Start/Stage 是 | 劫数生成、阶段效果和结算。 |
| `LifeSpanEndEvent` | 是 | 寿元耗尽的替代处理。 |

## 推荐开发顺序

1. 整理 `core`：复用并补齐固有类型注册表、热重载数据包注册表、附件编码、同步、事件和调试命令。
2. 实现 `cultivation` 与 `world` 的最小版本：灵气区块数据、`SpiritData`、境界/元素/灵根/体质、修炼动作和突破事务。
3. 实现 `ability`：固有能力/动作/条件/组件类型、能力持有者、状态机和事件桥。
4. 实现 `artifact`：灵力容器、祭炼、储物法宝；此时可完成最小闭环测试。
5. 逐项接入炼丹、阵法、飞剑、劫数、灵宠和锻造，均复用现有资源、事件和注册表。
6. 最后处理宗门、秘境、维度、死亡/灵魂及第三方联动；在实际目标模组存在时编写兼容适配器。
