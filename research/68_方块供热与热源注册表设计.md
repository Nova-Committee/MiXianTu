# 方块供热与 heat_source 注册表设计

2026-10-04，基于 Minecraft 26.1.2 / NeoForge 26.1.2.99 / Java 25。用户原话要求三件事：**把 `AlchemyHeatSource` 改成给方块用的**、**取消把异火放入 GUI 的设定、直接改放炉子下面中心的那一格**、**添加 `heat_source` 注册表负责指定方块的热量，`AlchemyHeatSource` 用于更高级的方块热源控制、不是必须**。本稿取代 [58](58_丹炉部件分工与异火供热设计.md) 的第三节（异火是核心界面里的一件物品），结构部分沿用 58 的追记与 [结构改版](#与前一轮结构改版的关系)。58 的其余章节（部件分工、批次冻结、Pre/Post 协议）仍然有效。

## 一、定案

1. **供热源从物品变成世界里的一格方块**，位置是**底层正中央那一格**（本地 index 4，`AlchemyFurnaceStructure.HEAT_INDEX`）。它在上一轮结构改版里刚好是「底层五格完全不校验」中的一格，所以：不参与成型、不被认领、不看区块加载，玩家在那里放什么、放不放都不影响结构；炉温上限只按那一格的方块算。
2. **核心不再有异火槽**。`AlchemyWorkstation` 删掉 `fireContainer` / `canPlaceFire` / `canTakeFire` / `fireTemperatureLimit`，加 `heatSourcePos` 与 `heatTemperatureLimit`；`AlchemyFurnaceBlockEntity` 删掉整个 `SimpleContainer fire` 与它那套 `loading` 守卫、NBT 的 `fire` 键、拆核心时掉异火那一步。**监控页因此没有机器槽**（`View.MONITOR` 的机器槽数 1 → 0）：`machine` 容器仍在 `SlotLayout` 里占位但容量 0，页面上不再有那个 `<container>`，输入框补回它让出的 18px。
3. **新数据包注册表 `mxt:heat_source`**（第 39 张）：`blocks`（方块或方块标签）+ `max_temperature` + `heating_per_tick` + 可选的 `priority`。一个方块一格热量，重叠时 `priority` 高的赢、同分按注册表顺序取先出现的——与 `ItemMatcher` 的排序口径一致。索引按方块注册表实例开键，`ServerCache.onDatapackLoaded` 里 `invalidate()`（标签会随数据包变，不能只靠实例键）。
4. **`AlchemyHeatSource` 降为可选的方块接口**，签名改成 `double maxTemperature(BlockState state, ServerLevel level, BlockPos pos)` 与 `heatingPerTick(...)`，`pos` 是供热格自己（不是核心）。**实现了接口的方块以它自己的回答为准，忽略表里给它写的条目**——这是「更高级的控制」：数值可以随方块状态（点着的火）或周围环境变，而数据包只能写常数。
5. **本体不提供热源方块、不内置岩浆/火这类数值**（铁律 9：具体内容归数据包 / 测试包）。测试包注册三个测试方块：`mxt_test:alchemy_test_fire`（150 / 40，走方块标签条目）、`mxt_test:alchemy_weak_fire`（80 / 10，走 `priority: 5` 的条目，用来验证优先级压过标签）、`mxt_test:alchemy_advanced_fire`（实现接口，表里故意写 999 以证明接口优先）。

## 二、为什么是「底层正中央那一格」

- 上一轮把底层五格放开，是为了让四角模型拼出完整底面；那一格正好因此成为「可以自由放东西、又不破坏成型」的唯一位置——**结构规则不用再为供热开口子**。
- 位置随外壳旋转（`AlchemyFurnaceStructure.heatSource` 与其它格走同一套四分之一转），探针里把四个朝向的偏移硬编码了一遍，防止用同一个 helper 自证。
- 选中它而不是「整座结构正下方一格」由用户拍板（两者差一格，代码只差 `.below()`）。

## 三、行为边界

- **没有热源 = 可设上限 0**：`maximumTemperature() = min(18 块炉壁最低耐温, 供热格的最大温度)`，任一侧为 0 就返回 0，`setTargetTemperature` 全部拒绝、开炉以 `TEMPERATURE` 被拒且不扣料。
- **活动中把那一格换掉或挖掉不中止批次**：加热速率立刻变 0，炉温按 `cooling_per_tick` 回落，走原来那条「越界累计到 `max_bad_ticks` 才判废」的路。**不再有「活动批次中不能取换」这条锁**——方块不是槽位，框架没有（也不该有）阻止玩家挖方块的口子；这是本轮唯一放松的约束，特此写明。
- **供热方块不消耗、不跟着核心掉落**：它是独立的一格方块，拆核心只掉核心与已生成待输出。
- **只读、只在服务端、只在该格已加载时读**：`AlchemyHeatService` 先 `level.isLoaded(pos)` 再取方块状态，绝不为读一格热度去加载区块；未加载时按「没有热源」处理，与炉壁缺格同一口径。

## 四、与上一轮结构改版的关系

结构本身（底层只校验四角、上面两层填满、18 块炉壁、22 个校验格）一字未改。本轮只是**给那五格自由格中的正中央一格赋予了用途**，因此：

- `docs/数据包格式.md`、教程与文档站里「底层五格完全不校验」的说法仍然成立，只是补了一句「其中正中央那一格是供热格」。
- 上一轮记录的「玩家在那五格自放的方块不会被认领、保留完整方块模型」的观感问题照旧，供热方块就是那一格的正常用法。

## 五、验证

- **已做**：`./gradlew compileJava compileTestModJava processResources` 通过；`processTestModResources` 把新的 `heat_source`  JSON、方块 tag、方块与物品定义刷进 `build/resources/testMod`；两份 lang 键集合一致（主包 1091、测试包 329）；旧的 `AlchemyTestFireItems` / `AlchemyTestFireItem`、`fireContainer`、`fireCount` 等引用全仓零命中。
- **探针（未实跑）**：`AlchemyProbes.heatSources` 新增「供热格位置 = 底层正中 / 底层正中不被校验 / 标签条目 150 与 40 速率 / 非热源方块 = 上限 0 且开炉温度不足 / 优先级条目 80 / 接口方块 250 且墙 200 更紧 / 熄灭的接口方块 = 0」；`orientations` 四朝向硬编码偏移；`menuOwnership` 改成「活动批次中可以挖掉供热方块，炉温随即回落」；`callbackFailures` 的「开炉回调里撤走热源」由取走物品改成挖掉方块；`limitsAndParts` 的「拆核心掉异火」改成「拆核心不掉热源方块、那一格还在」。
- **未做**：实机（`runTestClient` / `runTestServer`）与 `/mxt alchemy` 探针未跑；本轮没有人工验证那五格自由格里放方块时的观感。

## 六、遗留与开放项

1. **旧存档**：本轮不写兼容处理（未发布）。老世界里的丹炉在核心槽里的异火物品会随 `fire` 键一起不再读取（存档里那个键静默失效），需要玩家自己在底层正中央放一个热源方块。
2. **热源方块的「火」表现**：本体不提供，任何发光/燃烧表现要内容包或方块自己实现（`lightLevel` 之类）。
3. **测试方块的美术**：三个测试方块直接借原版贴图（岩浆 / 地狱岩 / 岩浆流体），只为让实机看得见，不是要发布的资源。
