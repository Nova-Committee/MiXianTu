# 59 - 丹药定义与绑定拆分设计

> **基准**：本仓库工作树（`PillBinding` 仍把"绑到哪些物品"与"药效"写在同一份定义里）。
> **状态**：**已落地**（用户拍板三个口径，见下）。
> **起因（用户原话）**：「把 `mxt:pill_binding` 拆分一个 `mxt:pill` 出来，其中 `mxt:pill` 存储丹药信息，`mxt:pill_binding` 只负责绑定到已有物品，然后添加一个 `mxt:pill` 的 attachment，仅用于内置的丹药，用于赋予丹药作用，优先级高于 binding」。
> 三个口径由用户拍板：①「attachment」＝**物品组件**（就是既有的 `mxt:pill` 组件，挂在具体那一堆丹药上，直接装 `Holder<mxt:pill>`）；② 药效全归 `mxt:pill`，但 `max_uses` / `cooldown` 留在 `pill_binding`，**次数与冷却仍按 `Holder<PillBinding>` 记账**；③ **直接不兼容**（binding 里的旧内联药效字段删除，写了静默忽略）。

## 1. 拆分前的形状

- `mxt:pill_binding` 一份定义同时干三件事：`items`（认领物品，`ItemMatcher`）、全部药效（`on_consume` / `toxicity_gain` / `toxicity_threshold` / `on_overdose` / `toxicity_after_overdose` / `conditions`）、用量与冷却（`max_uses` / `cooldown`）。
- 物品组件 `mxt:pill`（`PillComponent`）：`binding`（可选 `Holder<PillBinding>`）+ 五个药效覆写；`applyTo(PillBinding)` 产出一份覆写后的 `PillBinding`。
- 解析（`ItemBindingService.resolvePill`）：组件指名 binding 就**只**用它（不查 `items`）；否则按 `items` 匹配；都没有就"只有覆写"的组件剂量（无上限无冷却）。
- 记账：`mxt:pill_usage` 附件的键是 `Holder<PillBinding>`。

## 2. 拆分后的形状

| 注册表 | 装什么 | 字段 |
| --- | --- | --- |
| `mxt:pill`（新） | **丹药信息**（这一份丹药是什么作用） | `name`、`description`、`color`、`on_consume`、`toxicity_gain`、`toxicity_threshold`、`on_overdose`、`toxicity_after_overdose`、`conditions` |
| `mxt:pill_binding` | **只负责绑定到已有物品**，外加这件物品的用量与冷却 | `name`、`description`、`items`、`pill`（**必填**，`Holder<pill>`）、`max_uses`、`cooldown`、`priority` |

- 文件位置：`data/<命名空间>/mxt/pill/<路径>.json` 与 `data/<命名空间>/mxt/pill_binding/<路径>.json`。
- 组件 `mxt:pill`（"挂在那一堆丹药上的数据"）：`pill`（可选 `Holder<pill>`）+ 五个药效覆写；**不再有 `binding` 字段**。`ofPill(holder)` 是内置丹药给通用载体 `mxt:pill` 写作用的那条路。
- `mxt:pill` 成为第 24 张自带 `name` / `description` 的注册表；数据包注册表总数 37 → 38。

## 3. 解析规则（唯一出口仍是 `ItemBindingService.resolvePill`）

1. **作用（effects）**：组件指名的 `pill`（再叠组件覆写）**优先于** binding 指名的 `pill`（同样叠组件覆写）；只有覆写、两边都没指名时，`Pill.defaults()` 加覆写（旧 `component-only` 剂量）。
2. **身份（identity，次数与冷却）**：只有 `items` **匹配到的 binding** 才有身份。组件**不会**创造身份——这是与旧形状唯一的表达力损失（旧写法允许组件指名一个 binding 从而给未认领的物品加上限），换来的是"binding 管这件物品、组件只管这一口是什么作用"的一刀切。
3. **被选中的那份 `pill` 引用失效**（键还在、值没了 → `Holder.isBound()` 为假）→ `unbound`，拒绝这一口，**不回退**到别的 binding 或默认值。**在定义里**指名一份当前包里没有的 `pill`（文件被删或 `neoforge:conditions` 挡掉）不走到这条判定：那会让 `mxt:pill` 注册表冻结失败，整个数据包加载不了（`Unbound values in registry … mxt:pill`），世界开不起来、`/reload` 也起不来。
4. 记账与冷却仍按 `Holder<PillBinding>`（`mxt:pill_usage` 附件的键），所以**同一份丹药绑到两件物品各算各的**（各 binding 一套计数），而同一 binding 认领的一族物品共用一套。
5. 检查顺序不变（`PillService.check`）：`unbound` → `conditions`（现在读 `Pill.conditions()`）→ 上限 → 冷却。

## 4. 与旧形状的差别（不兼容清单）

- `pill_binding` 里的药效字段全部删除：写了既不报错也不生效（与全仓未知键同一口径）；`pill` 必填，缺失 = 加载期报错。
- 组件的 `binding` 字段删除，改叫 `pill`；旧写法（`{"binding": "..."}`）写了不报错，但那份丹药不会被指名。
- 通用载体 `mxt:pill` + 组件的那条路（炼丹产出、创造模式给的那颗）**没有上限与冷却**；要上限就给承载它的物品写一条 binding。
- 测试夹具与探针跟着改：夹具拆成"`mxt:pill` 定义 + 认领真实物品的 binding"，探针的限次腿改用被认领的物品（不再是"组件指名 binding"）。`disabled_ref`（被条件挡掉的丹药）**不许被任何定义指名**——那样注册表冻结会失败（见 §3.3）；`unbound` 那条腿改为在探针里现造一个"有键无值"的 `Holder` 来验。

## 6. 不做

- 不改记账身份（不按 pill 记）：同一份丹药绑到多件物品各算各的是**有意**的（用户拍板）。
- 不给"组件剂量"自动配上限：内置丹药的作用与用量本来就是两件事，用量属于物品。
- 不再开第二个组件或第二张分派表（`research/57` 的结论继续有效）。
