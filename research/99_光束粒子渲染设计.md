## 外观与参数

一份 `mxt:light_beam` 粒子承载整根沿世界 Y 轴的气流柱。短线长短、粗细、亮度与柔和程度各异，彼此留空；每根使用一种 ARGB 颜色。每段都具有立体截面，相机不决定截面朝向。

| 参数 | 默认值 | 语义 |
| --- | --- | --- |
| `x` / `z` | `0` | 相对生成点的横向偏移 |
| `y_min` / `y_max` | `0` / `8` | 竖直范围，后者必须大于前者 |
| `color` | `#FFFFE8A8` | 整根颜色，最高字节参与整体透明度 |
| `width` | `0.18` | 局部短线粗细与长度尺度，范围 `0.001–64` |
| `radius` | `0.5` | 截面分布半径，范围 `0.001–64` |
| `density` | `16` | 每平方格截面的流道数量，范围 `0.001–1024` |
| `spread` | `false` | 关闭为闭合等半径圆柱；开启为展宽、拉长、两端收尖 |
| `filled` | `true` | 开启时短线中心填充分布在圆盘内；关闭时仅分布在整根柱体表面 |
| `glow` | `false` | 在竖直柱体内部绘制同色、静止的柔光 |
| `bottom_effect` / `top_effect` | `false` | 独立开启下端、上端平面流动 |
| `flow_direction` | `up` | `up` 或 `down` |
| `flow_speed` | `1` | 流速倍率，范围 `0–100`，零为静止 |
| `lifetime` | `40` | 寿命，范围 `1–1200` tick |

流道数为 `clamp(ceil(π × radius² × density), 1, 1024)`，两种分布模式使用同一数量口径。流道是发射频率基准，不是固定横向轨迹。`filled=true` 时，每段按稳定种子在圆盘内取 `r = radius × sqrt(U)`；`filled=false` 时取 `r = radius`。两者均取 `angle = 2πV`；正在流动的段保持落点，后续新段各自重新选点。这里只改变整根光束的分布，单条短线仍为立体形状。

固定随机属性来自粒子种子、流道、候选格编号与属性盐。纵向尺度 `scale = max(width × 8, 1)`，位移为 `age × flow_speed × direction × 0.24 × scale`，年龄包含 partial tick。展宽模式的格频乘 `0.62`，格内长度与宽度共用随机量，使较宽的段也更长；截面半径乘 `4t(1−t)`，避免短菱形轮廓。内层亮芯、外层柔光共用一条渲染管线。

内层粒子对象的布尔 `spread` 与外层效果的三维散布数组同名、层级不同。服务端只发送整根参数，不发送逐段网格；不同客户端不保证每个随机落点完全一致。

## 静止柱内柔光

`glow` 独立于 `filled`，也不改变短线自身的局部柔光。开启时，每根在普通候选生成前提交一个 `channel=-1` 的整柱实例；半径等于 `radius`，高度为 `y_max-y_min`，仅使用原色和整根寿命渐隐，不依赖年龄流动位移、phase、随机样本、`spread` 或终端路径。寿命渐隐之外没有动画，不向水平终端铺开。

柔光复用两层闭合模板：内层反转绕序供柱内观察，外层供柱外观察；片段端依据相机是否在柱内只保留对应一层，避免同一柱体重复叠加。用视线与有限圆柱的解析交段固定做 4 次中点采样，径向密度为 `(1-r²/R²)²`，上下两端平滑渐隐，再按光学厚度换算透明度。无需时间 uniform、额外纹理或第二套绘制管线。

这是一种有界体积外观近似。基础变体仍按代理表面参与深度测试和逐实例透明排序；启用并取得场景深度时，柔光改为按不透明深度截断积分，代理采用始终通过的只读深度测试，以保留墙前、代理出口之前的有效体积。短线另做 0.12 格接触淡出。相邻短线和柔光记录可切换 pipeline，但保持原全局顺序，UBO 布局不变。地形之外的透明交错与相机贴近裁剪面时仍不保证精确遮挡；极短且极宽的柱体可能低于透明度丢弃阈值。宽柱重叠仍会增加片段计算与透明填充开销。

## 终端连续路径

两个终端对应 `y_min`、`y_max` 水平面，不读取方块或地形法线。同一段沿圆弧在竖直轨道与径向水平线之间转向，截面随切线旋转。

| 流向 | 下端 | 上端 |
| --- | --- | --- |
| `up` | 平面收拢后向上 | 向平面转弯后发散 |
| `down` | 向平面转弯后发散 | 平面收拢后向下 |

设柱高为 `H`，外扩 `R = max(0.75, radius × 1.5, width × 4)`，弯曲半径 `b = min(H / 4, R / 2)`。距端面 `b` 格处开始四分之一圆转弯，转完后沿平面继续行进，最终径向位移为 `R`。

沿弧长 `s` 的转角 `θ = min(s/b, π/2)`，径向位移为 `b(1−cosθ) + max(0, s−bπ/2)`，距端面高度为 `b(1−sinθ)`；上端按 `H` 镜像。一端额外路径长度 `E = R + (π/2−2)b`，下端启用则路径起点扩至 `−E`，上端启用则终点扩至 `H+E`。最外侧 `0.3R` 路径渐隐。

终端与竖直部分共用候选、预算、随机属性与同一弧长速度。径向方向来自横向落点，落点近轴时用稳定随机角度。裁剪后中点不保证恒速，流向测试必须选择未裁短的完整段。

## CPU 与 GPU 分工

`LightBeamParticleShape` 保存参数、流道常量和最多 4096 项的固定随机样本缓存；直接映射冲突只淘汰缓存，不改变结果，不随候选格编号无限增长。原 CPU 网格出口保留给几何探针与离屏对照，生产绘制不再调用。

`LightBeamParticleFrame` 先做整根 AABB 剔除，再按距离分配配额，在生成候选前执行稳定流道/候选格抽样；每段用包含光晕的保守 AABB 再剔除。距离排序键只计算一次，所有光束的短线一起按远到近排序。

`LightBeamParticleGroup` 将排序结果连续切为每批 64 条，禁止为相同光柱或模式重新分组。固定顶点/索引模板只上传一次；每帧每个短线或柔光实例写 6 个 vec4，共 96 字节：

| vec4 | 内容 |
| --- | --- |
| `origin` | 已减相机的横向落点与柱底、柱高 |
| `path` | 相对柱底的路径起点、长度、亮芯与光晕半径 |
| `shape` | 归一化径向方向、模式（0 等径 / 1 展宽 / 2 整柱柔光）、局部尺寸 |
| `ends` | 两端开关、外扩、弯曲半径 |
| `tint` | RGBA |
| `style` | 寿命透明度、柔和程度、裁剪后的路径上下界 |

先用 double 减相机再转 float，不能上传绝对大世界坐标。裁剪上下界直接保存局部路径坐标，避免从归一化进度还原时，大长度与极短柱高相减放大误差。

顶点 shader 用 `gl_InstanceID` 读取记录，完成截面环、圆弧、旋转、展宽、端盖与渐隐。片段 shader 保留表面柔光、明确端盖标记、弯曲表面导数法线和实际位置的原版雾效。基础与短线使用 LEQUAL，深度增强的柱内柔光使用 ALWAYS_PASS 并由采样深度截断；深度写入均关闭、背面剔除开启。透明排序仍是逐段近似，交叠壳体不保证严格正确。

UBO 每批声明 6144 字节，绑定范围覆盖整个数组，末批补零；偏移按设备要求对齐。CPU 暂存与三帧 ring buffer 复用；客户端世界卸载或游戏退出时释放六个模板/索引缓冲、实例 ring 和原生暂存，下次需要时重建。没有新增图形依赖。

`render()` 由原版在已经打开的 `RenderPass` 内调用，只能绑定资源和提交绘制。`MappableRingBuffer.rotate()` 会通过命令编码器创建 fence，放在这里会触发 `Close the existing render pass before performing additional commands`。绘制只标记待轮换，下一次 `prepare()` 在写入之前执行轮换；此时上一轮 pass 已关闭，fence 排在之前的绘制之后，三帧循环复用与等待语义仍成立。没有后续绘制时无需轮换，卸载直接关闭资源。

## 资源生命周期

已移除 `LightBeamParticleBuffersMixin` 及其注册，改用 **NeoForge 生命周期事件 + 惰性资源槽**。`util/CloseableResources` 实现不依赖客户端或 GPU 的资源所有权，内部嵌套 `Slot<T extends AutoCloseable>`；`util/ClientRenderResources` 只负责客户端事件、渲染线程检查、世界有效性和异常日志。拆开核心与平台入口，使无头探针也能执行真实的资源槽逻辑，不需要加载客户端类型。

业务只声明工厂并使用资源，首批提供世界级生命周期，不增加生命周期枚举、后台清理线程或通用任务队列。光束的接入方式：

```java
private static final CloseableResources.Slot<Buffers> BUFFERS =
        ClientRenderResources.world(Buffers::new);

// In prepare(): acquire only when this frame actually needs a draw.
var buffers = BUFFERS.get();
if (buffers == null) return null;
buffers.prepare(entries, camera);
```

`world(factory)` 只登记工厂，不分配原生内存或 GPU 对象；固定模块声明固定数量的槽，不为每个粒子、实体或世界另行登记。`get()` 在有效世界的渲染阶段惰性创建或复用资源，没有世界或已进入退出阶段则返回 `null`。`peek()` 只读取已有实例，供后续 `render()` 使用，缺失时跳过绘制；`release()` 释放当前实例，下次有效的 `get()` 可以重新创建。`Buffers` 仍实现 `AutoCloseable`，业务不再另存一份静态资源引用，也不对每帧绘制使用 try-with-resources。

统一触发点已对照当前 NeoForge 与 Minecraft 源码：

| 触发点 | 处理 | 依据与边界 |
| --- | --- | --- |
| 首次实际绘制光束 | `get()` 创建一套 `Buffers`，随后复用 | 创建和使用均在渲染线程 |
| `LevelEvent.Unload`，且 level 是 `ClientLevel` | 对所有世界级槽调用 `release()` | `Minecraft.setLevel()` 与断开连接路径均发出，覆盖换维度、换服务器和退出世界；过滤服务端事件，避免单人游戏的服务端卸载误清客户端资源 |
| `GameShuttingDownEvent`，只在 `Dist.CLIENT` 注册 | 先设置终止标记，再同步释放全部槽 | 事件明确保证此时 GL 上下文仍有效；退出后拒绝新建，防止关窗所在 tick 继续绘制而重新分配 |
| 同一世界单独清空粒子 | 保留缓冲缓存，不分配新实例 | 缓冲容量有上限、不持有世界或粒子引用，后续可直接复用；这是与当前 Mixin 的明确行为差异 |

卸载事件发出时，`Minecraft.level` 可能仍指向旧世界，随后才同步替换并清空粒子引擎。因此卸载处理只释放，不在事件回调中依据这个字段重新获取资源；业务只允许在实际绘制的 `prepare()` 中调用 `get()`。创建、获取与释放统一校验渲染线程，退出时直接关闭，不能仅投递一个依赖后续帧才能执行的关闭任务。

槽位强持有资源是有意的：缓存应一直复用到所属生命周期结束。`WeakReference<Buffers>` 被清除后已经无法取回对象执行 `close()`；`Cleaner` 的执行时机不确定，而且其线程不能直接删除 GPU buffer。这里的 owner 就是客户端世界生命周期，平台已经提供确定的事件，不需要再建立依赖 GC 的第二套所有权。

释放边界如下：

- **重复释放**：槽先取走当前实例并置空，再执行 `close()`；资源自身也增加关闭保护，原生 staging 只能 `memFree` 一次。普通 `release()` 可重建，工具的退出终止状态不可重建。
- **部分构造失败**：工厂成功返回后才缓存。`Buffers` 将已取得的模板、索引、ring 与 staging 按取得顺序登记，创建中途失败时倒序释放，再传播原始失败并附上关闭失败；临时网格数据也受 finally 保护。槽无法替一个尚未构造成功的对象补做关闭。
- **关闭失败**：`Buffers.close()` 尽力关闭各子资源并保留失败信息；工具记录关闭异常，继续释放其他槽，避免一个资源阻断整个清理流程。此处处理的是资源故障，不是常规玩法控制流。
- **重入**：关闭期间禁止同槽重新获取，批量释放期间禁止整个作用域重新获取；退出先置终止状态。构造期间若发生释放，通过比较槽的 `generation` 使本次获取失效，刚创建的资源随即关闭，不发布到缓存。

固定几何与实例缓冲没有缓存 shader 对象，本次不将资源重载额外绑定成销毁事件；后续若某类资源确实依赖重载内容，再由业务显式调用其槽的 `release()`。

资源托管的 4 组 GameTest 已实跑通过，覆盖惰性创建、复用、重复释放、释放后重建、构造失败重试、关闭异常隔离、重入、构造期间失效、退出终止与线程限制；7 组光束回归也通过，实例化探针补充真实客户端字节码的 RenderPass 调用约束。实际世界切换和显存释放仍需客户端实机检查，无头测试不能替代这一层。

## 数量与距离预算

每根最多 1024 流道、2048 实例，整帧最多 8192 实例、128 批。柔光每根占一个实例，包含在这两个上限内；极端配额仅剩一份且开启柔光时，只保留柔光。先按光柱完整边界到相机的最近距离排序，最多接纳 8192 根；接纳的每根保留一份配额，余量按 `1/(1+distance/32)` 加权，单根仍封顶 2048。配额内使用稳定候选编号抽样，不先遍历全部候选再截断。

预算不足时远处通常更稀；配额未用满、段被剔除或处于寿命渐隐时不会重新分配剩余量。超过 8192 根时更远的整根可能没有配额。这是有界降级，不承诺任意参数下都维持请求密度。

| 距离 | 截面边数 | 终端纵向区间 | 模板顶点 / 索引 |
| --- | ---: | ---: | ---: |
| 小于 32 格 | 8 | 16 | 346 / 1632 |
| 32～96 格 | 6 | 8 | 158 / 648 |
| 96 格及以上 | 4 | 5 | 84 / 288 |

批次采用其中最近短线的质量，避免为 LOD 打乱透明顺序。弯曲区间保持下水平、下圆弧、中部、上圆弧、上水平的采样锚点；直线仍使用原五环轮廓，多余模板环退化。所有档位保留立体截面，没有 billboard 回退。距离阈值暂未设置滞回。

整帧实例记录最多 0.75 MiB，另计设备对齐、静态模板和三帧存储。实例化降低 CPU 与上传压力，近距离宽光晕和重叠透明像素仍会消耗 GPU 时间，数量上限不能保证所有显卡都达到固定帧率。

## 发包与剔除

统一边界出口为 `LightBeamParticleOptions.bounds`：水平半径 `radius + width×0.7`，任一终端开启再加 `R`；竖直包含完整柱体，并在开启端外侧补 `width×0.7` 光晕边距。

`ServerLevelParticleMixin` 及其注册已按要求移除。服务端恢复原版发送规则：同维度，玩家所在方块中心到生成点的距离小于普通/force 的 32/512 格；半径、偏移、竖直范围和终端不参与距离判断。完整 AABB 的服务端发包策略留待后续处理，不在其他入口补做替代。

类型 override limiter 仍避免客户端在创建前按生成点丢弃已收到的长光柱。客户端完整 AABB 视锥判断与逐段剔除继续保留。客户端边界正确并不保证服务端已发送：生成点在发送范围外时，即使中段或顶部靠近玩家也收不到粒子。

高斯散布包无法预知每个客户端随机出的生成点。精确放置使用 `count=1`、外层散布为零，不同位置分别发送。自发光不照亮环境，不实现流体物理或环境光散射；场景深度增强只提供不透明场景截断的体积外观近似，不是物理体积光照。

## 隔离性能对比

同一机器、JDK 25、固定种子/位置/相机，每场景预热 24 帧、测量 24 帧取中位数。默认高度 8、半径 0.5、局部尺寸 0.18、密度 16；大半径场景高度 12、半径 1。旧路径实写 `BufferBuilder`，新路径实写实例记录；新 CPU 时间还包含每段边界计算，但视锥谓词统一放行。两者均不含 GPU 上传、绘制、世界渲染及实际游戏 FPS。

| 场景 | 平均短线数 | 旧 CPU ms | 新 CPU ms | 旧顶点 / 新实例数据 MiB |
| --- | ---: | ---: | ---: | ---: |
| 1 根直线 | 55 | 0.196 | 0.064 | 0.483 / 0.0059 |
| 10 根直线 | 582 | 2.897 | 0.251 | 5.115 / 0.0586 |
| 50 根直线 | 2942 | 11.536 | 1.575 | 25.813 / 0.2710 |
| 10 根双端 | 662 | 7.605 | 0.234 | 10.072 / 0.0645 |
