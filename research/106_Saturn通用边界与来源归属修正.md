# Saturn 通用边界与来源归属修正

## 目标与归属

本稿落实 [Saturn 边界审查](audit/Saturn边界与残留审查.md) 的修复方案。Saturn 保留数据驱动的通用运行机制，MiXianTu 拥有修炼、阵法、天劫、灵气与物品玩法的类别、信号和诊断名称。两边继续使用同一套来源账本、付款、触发分发和 tick 排序机制。

| 内容 | 归属 |
| --- | --- |
| 来源账本、通用来源工厂、自动授予重算 | Saturn |
| 灵根/功法/体质等来源类别、阵法来源构造 | MiXianTu MxtSources |
| 通用付款与能力/通道/脚本的诊断标签 | Saturn |
| 业务付款标签与世界灵气子区块身份 | MiXianTu CostSources / AuraSection |
| 旧 mxt:aura_pulse 存档的读取兼容 | MiXianTu AuraPulse / MxtDataStorages |
| 有序阶段执行与库内阶段 | Saturn |
| 资源回复、修炼进度与裂隙阶段顺序 | MiXianTu MxtTickStages |
| 通用信号发布 | Saturn |
| 突破/进度信号常量及其触发时机 | MiXianTu |
| 通用计时窗口与库自身采样项 | Saturn |
| 物品与自定义实体采样项和翻译 | MiXianTu |

只移动代码归属不会重写既有账本来源、被动属性或业务信号字符串。扩展装备来源改用中性的 EQUIPPED 名称，仍写旧存档 ID。Profiler 的物品/实体 source 则改为 mxt:item、mxt:entity，因为它们描述的是 MiXianTu 的运行工作；窗口不属于持久化玩法状态。

AuraPulse 虽然在 Saturn 自身没有消费者，但 MiXianTu 既有注册点仍将它映射为 mxt:aura_pulse。因此将类迁回消费方并保留 next_tick Codec，不能根据库内零引用直接删除兼容职责；真实存储分派的往返由 ownership 探针覆盖。

## 显式来源所有权

仅靠命名空间或 grant/ 前缀无法实现通用的授予收集。新方案允许收集事件使用任意 Identifier，并在能力附件里保存 managed_sources：

1. 收集各模块此刻声明的“来源 → 能力集合”。声明意味着该来源的完整集合由收集器管理，直接授予应使用独立 ID。
2. 计算本次管理范围：上次保存的受管来源、旧框架前缀来源，以及本次声明的来源。
3. 先增加全部新来源，再按范围逐个释放不再需要的授予。这样把能力从一个来源移到另一个来源时，不会暂时失去最后一个来源而清除充能等运行状态。
4. 将本次声明的来源集合写回附件；即使重启后贡献模块不再声明它，也能回收旧授予。普通直接授予不会进入范围。

managed_sources 是新增的可选存档字段；缺失时为空。旧 saturn:grant/... 前缀继续视作框架管理范围，用于接续既有存档。附件 copy 同时复制这份管理关系，避免草稿和真实附件共享可变状态。

不采用“取消所有过滤然后对全账本重算”：它会误收回脚本、物品和阵法的独立授予。也不为每个玩法模块复制一份重算器。

## 时间线与默认注册表

通用时间线只计算 duration × scale。MiXianTu 创建天劫上下文时统一计算 difficulty_scale × max(0, 1 + aura_tribulation_modifier)，验证、前摇与逐拍执行共享这一计算；条件等待的 deadline 保持不缩放。

默认注册表工厂统一生成完整的 saturn: 默认 ID，触发器默认项使用实际存在的 tick。验证既覆盖默认键归属，也覆盖真实注册后的缺失 ID 和越界数字 ID 回退。

## 多提供者 AbilityHooks

按 owner Identifier 注册不可变的提供者快照，相同 owner 只替换自身，null 只移除自身。运行时通过缓存后的组合实例读取，不在每次技能查询时重新构造列表。

- 伤害倍率相乘；无提供者为 1。
- 技能与物品许可必须全部通过；拒绝后可以短路。
- 成功提交时依注册顺序调用所有提供者。
- 技能结果取去重并集；装备按 ItemStack 对象身份去重，数值相同的不同堆叠仍保留。
- 旧 set 方法只操作一个兼容槽位，不能覆盖具名注册；MiXianTu 使用自己的 owner 注册。

实现留在运行时，api 包只暴露接口。没有额外加入世界规则、依赖或原版注入。

## 验证与当前限制

独立 Java 验证已实跑：通用框架 44 项、player-view 84 项，共 128 项通过。5/5 组 verify/saturn GameTest 已通过，45 条腿全部 OK，覆盖真实附件持久化、自动来源切换、24 个已注册默认值、装备合并、天劫倍率、profiler 归属与旧灵气存储分派。两仓主代码及 MiXianTu 测试源编译、中英文文档构建均通过。

当前实现与验证结果详见审查报告的修复记录。客户端界面效果、真实旧世界整体升级与其他 GameTest 未实跑；存储 Codec 往返不能代替完整升级验收。
