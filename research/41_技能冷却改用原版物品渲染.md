# 技能冷却改用原版物品渲染（删掉左上角那一行）

> **状态：已落地（2026-09-23，同日第三次变更）。** 触发原话：「这个去掉，是不必要的，因为选中的技能有面板显示，冷却可以加一下和原版物品一样的渲染」。本文记录这次收缩：删掉
`AbilityCooldownEntry`，把冷却画到轮盘格的格子上。
>
> **基准**：`41_能力与法器能力合并设计.md` 落地后的工作树——`screen/hud/AbilityCooldownEntry.java`、
`screen/wheel/WheelSelectionEntry.java`、`screen/wheel/content/{AbilityWheelEntry,AuraWheelEntry}.java`、
`api/WheelMenuEntry.java`。MC 26.1.2 / NeoForge 26.1.2.99。

## 0. 一句话

左上角那一行「技能冷却」（`41` 那次合并的配套）**整个删除**；冷却改为**画在轮盘格的格子上**，用原版物品冷却那一层白幕——盖住图标的剩余比例、随时间从上往下退。

## 1. 为什么删

- 它回答的问题是"按 `V` 会放什么、能不能放"，而这件事**轮盘格已经在回答**
  ：选中的那一格是金框、类型与状态在底边那条色条上，那块面板本来就常驻屏幕左侧。一行字只是把同一个事实说第二遍。
- 一条独立 HUD 元素的固定成本不低：一套语言键（3 条 × 2 份）、每帧一次文本测量、一个要纳入布局与 `/hud`
  的元素、一处和轮盘中间那行字"必须永远一致"的额外约束。换来的信息量等于格子上的一层遮罩。
- 它唯一独有的信息是**剩余秒数**（精确到一位小数），而这在轮盘中间那一行本来就有——打开轮盘就能看到，而且那才是你要决定按不按下去的时刻。

## 2. 冷却白幕（照原版抄）

原版 26.1.2 的写法（`net/minecraft/client/gui/GuiGraphicsExtractor#itemCooldown`）：

```java
float cooldown = player.getCooldowns().getCooldownPercent(stack, partialTick); // clamp(remaining / (end - start), 0, 1)
int top = y + Mth.floor(16.0F * (1.0F - cooldown));
int bottom = top + Mth.ceil(16.0F * this.cooldown);
this.

fill(RenderPipelines.GUI, x, top, x +16, bottom, Integer.MAX_VALUE);     // 0x7FFFFFFF = 50% 白
```

本模组照抄这条算式，只改三处：

1. 盖的是 22×22 格子里那个 **16×16 图标框**（`IconRenderer.ICON_SIZE`），底边那条类型色条在框外，不会被盖住；
2. 分母来自 `cooldownLength`（见 §3），不是物品的 `CooldownInstance`；
3. partial tick 取自 HUD 那一帧的 `DeltaTracker`（`getGameTimeDeltaPartialTick(true)`），所以与原件一样是**每帧移动**
   ，不是每刻跳一格。

两条边界：

- **白幕只给冷却中的格子**：其它原因不可用（`usable() == false` 而剩余为 0）仍然压原来那层暗色 `UNUSABLE_WASH`
  ，两个遮罩不会叠在同一格上。
- **不动的地方**：轮盘环上"不可用的扇区变暗"与轮盘中间那行「冷却中 4.3s」（`wheel.mxt.cooldown`
  ）都保留——环上的暗色是选的时候看的，中间那行给的是准确秒数。

## 3. 全长从哪来：`WheelMenuEntry#cooldownLength`

剩余 ticks 一直有（`cooldownTicks`），要画比例还缺一个分母。新增 `api/WheelMenuEntry#cooldownLength`（默认 `0`），只有
`WheelSelectionEntry` 一条算式读它：

| 条目       | 全长                                                | 为什么是它                                                                                                                               |
|----------|---------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------|
| 技能       | `CooldownDataStorage.duration()`                  | 上一次**实际拿到**的长度。声明字段 `cooldown` 可能被 `mxt:cooldown` 存储覆盖，只有付款那一刻知道真数——`CooldownDataStorage` 的字段注释本来就写着 `duration` 是"display 用来画的那个长度" |
| 灵气       | `SpiritBurstService.FIRE_INTERVAL_TICKS`（10 tick） | 一次发射的间隔是常量，附件里只存结束 tick                                                                                                             |
| 其它 / 答不出 | `0`                                               | 协议默认值：**画满整块**，只说"在冷却"、不说"还差多少"。既然 `cooldownTicks` 说在冷却，画一层满的白幕仍比什么都不画诚实                                                            |

## 4. 删掉的东西与副作用

- `screen/hud/AbilityCooldownEntry.java` 整个删除；`MiXianTuClient#init` 去掉 `AbilityCooldownEntry.register()`；两份语言键各删
  `hud.mxt.ability_cooldown` / `.none` / `.ready` 三条（**743 → 740 键**）。
- 玩家 `config/mxt/mxt-hud.json` 里可能还留着 `ability.cooldown` 那一条：没有元素登记它，因此**不再被读**，也不需要迁移（
  `/hud` 里不会再列出来）。
- 合并之后（`41`）"每个技能都有冷却"这个事实仍然成立，只是它的显示出口从"一行字"变成"格子上的遮罩"。

## 5. 顺带修掉的两处文档不实

- 本仓库 `docs/guide/**` 与文档站一直写着这一行"可以在 HUD 布局界面里关掉 / 拖动或隐藏"。**编辑器里没有隐藏开关**：
  `HudEntry#setVisible` 在接口与 `AbstractHudEntry` 之外**零调用点**，编辑器只有"左键拖 + 方向键 + `/hud <布局键> reset`"
  。本次把措辞改成"界面里目前只能移动，要隐藏得改客户端配置 `config/mxt/mxt-hud.json` 里 `hud.layout_v2` 那一条的第三段"。
- `docs/guide/java/screens.md` 里"第六个元素"整段随元素一起删除；`docs/guide/play/commands.md` 的 `/hud` 输出示例把
  `ability.cooldown` 去掉。

## 7. 开放项

1. **隐藏开关没有实现**（§5）：要不要给 HUD 布局编辑器补一个"隐藏/显示"切换，属于玩家入口，留给用户拍板；补的话 `setVisible`
   已经写好、只差接线。
2. 格子上只给了**比例**，没有把剩余秒数写进格子。tooltip 里现有「冷却：x.x s」那一行说的是**总长**，要不要再加一行"还剩 x.x s"
   待定（加了就等于把删掉的那行字挪进 tooltip）。
3. 环上的扇区没有用白幕（用的是整扇变暗）：环是弧形、图标是 16×16 的方块，白幕在环上要不要对齐图纸面还没试过；要的话再加。
