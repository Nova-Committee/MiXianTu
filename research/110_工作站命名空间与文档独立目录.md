# 工作站命名空间与文档独立目录

状态：命名空间、资源与独立文档目录已落地，四工程编译和打包、53 组定向 GameTest（115 次执行）、26 项文档站测试与双语构建通过；附属配置归属补充的 5 种安装组合与画符回归共 7 次执行通过。客户端未实跑。承接 109 的附属拆分与通用热源归属修订，本轮按用户要求直接切换命名空间，不提供旧 ID 别名或存档迁移。

## 1. 注册边界

| 所属 | 命名空间 | 自有内容 |
| --- | --- | --- |
| MiXianTu 本体 | `mxt` | 通用热源、共享工具与材料、丹药、符箓、灵植、品质等通用规则 |
| 炼丹工作站附属 | `mxt_alchemy` | 丹炉部件、方块物品、方块实体、菜单、炉型/炉壁注册表、工艺组件、炼丹配方、炼丹进度触发器与网络类型 |
| 锻器工作站附属 | `mxt_forging` | 锻造台及其方块物品/方块实体/菜单、蓝图/方式/绑定注册表、工艺组件与网络类型 |
| 画符工作站附属 | `mxt_talisman` | 画符台及其方块物品/菜单、画符配方与网络类型 |

不仅修改注册表声明，还要修改物品组件、配方类型、模型/纹理、战利品、标签成员、语言键、AUI 页面路径和测试夹具中的对应引用。原有共享标签 `mxt:workstations`、`mxt:talisman_paper` 与 MiXianTu 创造栏继续由本体提供，附属只追加自有条目。

数据包文件使用注册表命名空间，例如炉型放在 `data/<namespace>/mxt_alchemy/alchemy_furnace/<entry>.json`。条目自己的命名空间由数据包作者决定；测试包中的 `mxt_test:*` 定义引用不因注册表改名而整体替换。`mxt:heat_source` 继续使用本体的路径与接口。

## 2. 文档边界

中英文文档均在 MiXianTu 目录下建立 `addons/alchemy/`、`addons/forging/`、`addons/talisman/` 三个独立目录。MiXianTu 侧边栏依次显示“炼丹工作站附属”“锻器工作站附属”“画符工作站附属”，每个分类单独容纳安装、使用、数据包与扩展说明；“工具”分组放在三个附属之后，位于 MiXianTu 侧边栏最下方。

本体保留通用符箓定义、丹药服用、灵植、药性、符笔颜料与通用热源。工作站专用页面迁入对应附属目录；混合页面拆分所属内容，保留必要的跨目录链接。页面移动同时重写两种语言中的相对链接、编辑器独立页入口及侧边栏引用，不复制出第二套文档。

## 3. 验证

四工程编译、测试编译、资源处理与打包；检查旧 ID 残留、资源引用、两语语言键与 Jar 内容。既有注册归属探针扩展为同时验证新 ID 和旧 ID 不存在，保留创造栏检查及工艺回归。文档站按自身协作规则验证侧边栏、测试与双语构建。

游戏测试仅运行已获授权的工作站与通用回归范围。客户端实机验证不在当前授权中。

## 4. 实施结果

### 4.1 注册与资源

三个附属的方块、BlockItem、方块实体、菜单、自有物品组件、配方与序列化器、炼丹进度触发器、网络类型和 JEI 标识均已改用所属 mod ID。模型、纹理、战利品、语言键、AUI 页面与测试数据同步迁移；AUI 继续引用本体共享主题，画符配置分类使用自己的翻译键。没有增加旧 ID 别名或迁移逻辑。

| 附属 | 数据包注册表 | 原版配方类型 |
| --- | --- | --- |
| 炼丹 | `mxt_alchemy:alchemy_furnace`、`mxt_alchemy:alchemy_wall_material` | `mxt_alchemy:alchemy` |
| 锻器 | `mxt_forging:forging_method`、`mxt_forging:forging_blueprint`、`mxt_forging:tool_binding`、`mxt_forging:blueprint_binding` | 无 |
| 画符 | 无 | `mxt_talisman:talisman_drawing` |

主代码、夹具和文档的旧具体 ID 与翻译键残留检查通过。861 份资源 JSON 可解析，7 对中英文语言文件键集合一致，463 处模型/纹理引用和 12 处 AUI 样式引用存在。三个发布 Jar 包含迁移后的资源，没有旧命名空间的实际资源文件。共享标签仍使用本体命名空间，`mxt:heat_source` 仅由本体提供，附属物品仍只加入本体创造栏。

### 4.2 文档

两种语言的工作站字段、工艺教程、使用说明、组件、专用接口、界面、网络与事件说明分别归入三个 `addons/` 目录，画符笔画编辑器和判分说明也归画符附属。本体总览保留通用规则及必要的附属链接，不再把工艺表、工艺组件与教程混列为本体内容；本体符笔与颜料、丹药、灵植、药性及通用供热仍留在原模块。

侧边栏按用户指定名称与顺序排列三个附属，“工具”分组移至最下方。导航测试覆盖附属目录隔离、页面完整覆盖、中英文路径/顺序一致及独立编辑器隐藏；26 项站点测试和双语生产构建通过，没有断链或锚点警告。构建保留既有 Browserslist 数据过旧与 `vscode-languageserver-types` 动态 require 提示。

## 5. 附属配置归属补充

用户确认：通用配置留本体，工作站专属配置归附属。`MxtServerConfig` 当前的 5 项相关配置分别由灵植生长、丹药服用、符箓发动与符笔蘸料读取；这些功能单独安装本体也需运行，因此不迁到附属。锻器当前没有本体配置项可迁移。

三个附属将 Jupiter 从 `compileOnly` 改为显式的 `implementation`，并在模组元数据中声明双端必需依赖，不内嵌第二份 Jupiter。每个附属在自己的构造入口调用 Jupiter 注册服务端配置，配置身份为 `<附属 mod ID>:server`，读取与修改统一使用 `IS_OPERATOR` 权限。

| 附属 | 文件 | 当前配置内容 |
| --- | --- | --- |
| 炼丹 | `config/mxt/alchemy-workstations.json` | 空对象；炉型、炉壁与配方参数仍由数据包定义 |
| 锻器 | `config/mxt/forging-workstations.json` | 空对象；蓝图、方式与绑定参数仍由数据包定义 |
| 画符 | `config/mxt/talisman-workstation.json` | `drawing` 下原有的 8 项会话限制与单笔颜料结算参数 |

保留画符现有配置路径与字段，不增加旧配置复制、双写或本体反向依赖。附属 README 与中英文配置页说明依赖和归属，本体配置页补齐灵植补算上限；画符判分说明分别链接本体共享物品配置和附属绘制配置。

新增 `verify/workstations/config` 探针，按实际安装组合检查附属配置与文件处理器注册、权限、JSON/NBT 往返、8 项画符配置和本体 5 项通用配置的隔离。四工程编译、测试代码编译、资源处理与打包通过，4 对语言键一致；三个发布 Jar 的依赖声明和配置类检查通过。26 项文档站测试与双语构建通过。
