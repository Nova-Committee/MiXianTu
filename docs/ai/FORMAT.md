# FORMAT

## 文件格式

- 使用 Markdown 和 Docusaurus front matter。
- 每个页面只描述一个模块或一个紧密相关的开发主题。
- 文件名使用小写英文或稳定的中文 slug；链接使用相对路径。
- 页面开头包含 `title`，必要时包含 `sidebar_position`、`description`。

## 内容顺序

1. 模块定位和适用范围。
2. 当前完成状态。
3. 数据结构或 API。
4. 最小可运行示例。
5. 与其他模块的联动。
6. 服务端/客户端边界和限制。
7. 测试与故障排查。

## 语言和风格

- 使用简体中文，API、注册表、字段名、类名和命令保留英文原文。
- “action”统一翻译为“行为”，“condition”统一翻译为“条件”，“resource”统一翻译为“资源”。
- 不写营销式夸张描述；明确“已完成”“制作中”“预留”。
- 示例只使用当前代码中存在的字段；不确定的字段必须标注“以当前 Codec 为准”。
- 代码块注明语言；JSON 使用合法 JSON，不写注释。
- 表格字段保持短而可扫描，长解释放到表格后正文。

## Docusaurus 约定

- 目录页命名为 `index.md`。
- 分类使用 `_category_.json`。
- 页面间使用 Markdown 相对链接，不写本机绝对路径。
- Mermaid 只用于表达模块关系、事件顺序或数据流，不用来代替字段表。
- 每个模块页应能脱离 README 独立阅读。

## 变更审计

新增或修改字段时，至少同步：

- Definition/Codec 页面；
- KubeJS 或 Java API 页面（如果公开）；
- 测试数据包示例；
- README 的模块完成度；
- `research/` 审计状态（如设计边界发生变化）。

删除字段时不保留兼容性说明，除非用户明确要求；项目未发布阶段以当前 Codec 为准。
