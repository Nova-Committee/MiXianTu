# 货币 JSON 格式

货币由 `mxt:currency` 动态注册表定义。任意已注册物品都可以作为货币；支票桌、兑换站和结算服务读取同一份注册表。

## 文件位置

货币文件位于数据包的 `data/<namespace>/mxt/currency/` 目录。例如：

```text
data/example/mxt/currency/iron_coin.json
```

其定义 ID 为 `example:iron_coin`。

## 字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `item` | 物品 ID | 必填。该货币对应的物理物品。 |
| `value` | 长整数 | 必填，必须大于 `0`。用于支票与通用结算。 |
| `exchanges` | 兑换数组 | 必填，可为空。兑换站在放入 `item` 后显示其中的全部条目。 |

## 兑换条目

`exchanges` 中的条目按数组顺序显示在兑换站的切石机式选项列表中：

| 字段 | 类型 | 说明 |
|---|---|---|
| `cost` | 整数 | 必填，范围 `1` 到 `99`。从输入槽的当前货币物品中消耗的数量。 |
| `result` | Item Stack | 必填。成功兑换后产生的物品栈。 |

`result` 使用原版 Item Stack 形状：

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `id` | 物品 ID | 无 | 必填。输出物品。 |
| `count` | 整数 | `1` | 输出数量，范围 `1` 到 `99`。 |
| `components` | 对象 | 无 | 可选的原版数据组件补丁。 |

## 示例

铜币同时提供升值与找零以外的单向兑换选项：

```json
{
  "item": "mxt:copper_coin",
  "value": 1,
  "exchanges": [
    {
      "cost": 10,
      "result": {
        "id": "mxt:iron_coin"
      }
    }
  ]
}
```

铁币可提供多个选项。它们在界面中按数组顺序排列：

```json
{
  "item": "mxt:iron_coin",
  "value": 10,
  "exchanges": [
    {
      "cost": 1,
      "result": {
        "id": "mxt:copper_coin",
        "count": 10
      }
    },
    {
      "cost": 10,
      "result": {
        "id": "mxt:gold_coin"
      }
    }
  ]
}
```

兑换是单向的。若要允许反向兑换，必须在目标货币的 `exchanges` 数组中显式定义反向条目。

带组件输出的示例：

```json
{
  "item": "minecraft:emerald",
  "value": 100,
  "exchanges": [
    {
      "cost": 4,
      "result": {
        "id": "minecraft:diamond",
        "components": {
          "minecraft:custom_name": "{\"text\":\"宗门凭证\"}"
        }
      }
    }
  ]
}
```

没有兑换选项的货币仍必须写入空数组：

```json
{
  "item": "minecraft:emerald",
  "value": 100,
  "exchanges": []
}
```

## 兑换站行为

兑换站采用切石机式界面：输入槽接受带有非空 `exchanges` 的货币物品；右侧显示该货币的所有兑换条目；选中条目后，输入数量达到 `cost` 时才会在结果槽显示输出。取走结果会扣除 `cost` 个输入物品。

列表和结果都由服务器端菜单确认。客户端仅使用同步后的动态注册表展示相同的兑换选项。

## 禁用标签

货币注册表的禁用标签路径为 `data/mxt/tags/mxt/currency/disabled.json`：

```json
{
  "replace": false,
  "values": [
    "mxt:copper_coin"
  ]
}
```

被禁用的货币不会参与兑换、支票或结算，但仍可被其他数据定义引用。

## 校验与重载

- `value` 必须是正整数。
- `exchanges` 必须存在；不提供兑换时使用 `[]`。
- 每个 `cost` 必须位于 `1` 到 `99`。
- `result` 必须是有效的 Item Stack。
- 使用 `/reload` 或重启服务器后，定义会重新校验并同步给客户端。
