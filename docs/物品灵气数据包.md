# 物品灵气数据包

`mxt:item_aura` 将已有物品定义为修炼期间使用的灵气燃料。文件位于：

每个条目必须填写 `type`，它是该物品提供/消耗的单一元素灵气类型（例如 `mxt:common`）。灵气传输接口一次只处理一个元素类型；需要多种灵气的配方或行为应分别调用接口。

```text
data/<命名空间>/mxt/item_aura/<路径>.json
```

```json
{
  "items": ["mxt:spirit_stone", "#example:spirit_fuel"],
  "aura": 100,
  "consume_speed": "0.5 + level * 0.05",
  "release_speed": "1 + level * 0.1",
  "exhausted_action": {
    "type": "mxt:apply_effect",
    "effect": "minecraft:fire_resistance",
    "duration_ticks": 40
  }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `items` | `ItemMatcher` | 必填。单个物品 ID、物品标签，或两者的混合数组。 |
| `aura` | `NumberProvider` | 必填。首次处理一组普通物品时，每件物品的灵气总量会乘以堆叠数量后写入其 `mxt:item_aura.remain`；对实现 `SpiritItemAccess` 的物品作为每件物品的充能上限。必须在实际运行时求得正数；灵石存储以整数单位计，小数部分不计入容量。 |
| `consume_speed` | `NumberProvider` | 必填。燃料条每游戏刻消耗的灵气量，按当前堆叠数量叠加。这样一组物品的总消耗时间与逐件消耗相同。必须在实际运行时求得正数。 |
| `release_speed` | `NumberProvider` | 必填。燃料条每游戏刻向当前境界绑定的资源条释放的灵气量，按当前堆叠数量叠加。必须在实际运行时求得正数。 |
| `result_stack` | `ItemStackTemplate` | 可选。普通燃料彻底耗尽时，向玩家物品栏加入该物品堆；未配置时只移除原物品。实现 `SpiritItemAccess` 的物品会保留自身并被抽空，此字段不参与处理。 |
| `exhausted_action` | `EntityAction` | 可选，默认无操作。当前装入的灵气被耗尽时对修炼者执行。 |

灵气燃料值是隐藏的服务端状态。开始处理时，系统从玩家物品栏取出整组匹配物品，放入实体 `mxt:float_holding_item` 附件；随后仅在该物品堆上写入 `mxt:item_aura` 组件，组件只有 `remain` 一个字段。每个服务端 tick 使用该次匹配的定义按 `consume_speed × 堆叠数量` 扣减 `remain`，并按 `release_speed × 堆叠数量` 向当前境界绑定的资源条充能，资源条仍按自身上限截断。因此总消耗时间不因堆叠数量改变。

附件为空时，玩家物品栏中带有 `mxt:item_aura` 组件的有效物品优先恢复处理，且总是选择 `remain` 最小的一组；没有半耗尽物品时，才按主手、再副手、再背包取出整组新的匹配物品并将按堆叠数量计算的 `aura` 写入组件。修炼中断、玩家登出或死亡时，附件中的物品组会原样归还；`remain` 耗尽时，`SpiritItemAccess` 物品会以空充能状态整组归还，其它物品则移除并按原组数量给予可选的 `result_stack`，最后执行 `exhausted_action`。

`float_holding_item` 可供其它机制暂存物品。灵气燃料服务只会消耗同时带有 `mxt:item_aura` 组件且仍匹配有效 `item_aura` 定义的物品；不符合条件的附件物品不会被移动、修改或删除。客户端目前不渲染燃料条，也不自行扣除或消耗物品。和其他数据包注册表一致，可通过 `data/mxt/tags/mxt/item_aura/disabled.json` 停用条目。
