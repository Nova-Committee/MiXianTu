# 灵气环境数据包

`mxt:aura_zone` 是原版同步的数据包注册表。文件位置为：

```text
data/<命名空间>/mxt/aura_zone/<名称>.json
```

环境解析优先级固定为：群系绑定 < 维度绑定 < 永久人工区域 < 活跃阵法。后一级替换前一级的灵气类型、元素值、规则和显示模板。普通区块的可消耗灵气仍保存于区块附件，因此同一位置所有系统共享同一份灵气库存。

```json
{
  "base_aura": 120.0,
  "regen_per_tick": 0.05,
  "element_aura": {
    "example:fire": 0.4,
    "example:water": -0.2
  },
  "aura_kinds": ["example:aura_kind/fire"],
  "dimensions": ["minecraft:the_nether"],
  "biomes": ["minecraft:badlands"],
  "fluctuation": {
    "enable": true,
    "cycle_type": "day",
    "amplitude": 0.3,
    "offset_tick": 0
  },
  "rules": {
    "cultivate_suppress": false,
    "tribulation_modify": 0.15,
    "spirit_plant_bonus": 0.2,
    "alchemy_env_bonus": true,
    "natural_spawn_herb": true
  },
  "element_fit_bonus": 0.25,
  "element_conflict_penalty": 0.2,
  "noise": {
    "enable": true,
    "seed": 739430,
    "scale": 640.0,
    "amplitude": 5.0
  },
  "particle": {
    "particle": { "type": "minecraft:glow" },
    "count": 4,
    "speed": 0.01,
    "force": false,
    "spread": [0.5, 0.5, 0.5],
    "offset_x": 0.0,
    "offset_y": 0.5,
    "offset_z": 0.0
  },
  "client_render": {
    "fog_color": "#88ffdd",
    "render_distance": 64,
    "fog_strength": 0.35
  },
  "client_hud": {
    "stored_aura": {
      "maximum": 200.0,
      "bar_index": 1,
      "anchor": "left",
      "order": 4
    },
    "sensed_concentration": {
      "maximum": 200.0,
      "bar_index": 2,
      "anchor": "left",
      "order": 5
    }
  }
}
```

- `dimensions` 和 `biomes` 可以同时填写；维度匹配优先于群系匹配。列表为空仅表示该模板不会参与静态绑定，仍可被人工区域或阵法引用。
- 区块第一次加载时，以 `max(0, (base_aura + 柏林噪声) / 10 - 5)` 初始化；`noise.seed` 完全由数据包控制，便于整合包复现分布。
- `noise.scale` 越大，空间变化越平缓；内置环境使用约 `640` 至 `960`。常规环境建议将 `noise.amplitude` 保持为 `5`，对应未截断前约 `-5` 至 `5` 的噪声扰动。
- `element_aura` 的键是 `mxt:element` 注册表中的元素 ID。正值为适配，负值会降低对应灵根的修炼倍率。
- `aura_kinds` 是当前位置具备的灵气类型标记，用于数据驱动的类型判断；与 `cultivate_action.aura_kinds`、`alchemy_recipe.aura_kinds` 均为全包含关系。它不代表数值来源，元素浓度由 `element_aura` 表示。
- `fluctuation.cycle_type` 支持 `day`、`moon`、`static`。波动只影响查询到的环境浓度；区块库存按 `regen_per_tick` 每秒更新。
- `rules.cultivate_suppress` 会中止正在进行的修炼。`tribulation_modify` 注入公式变量 `aura_tribulation_modifier`。`spirit_plant_bonus`、`alchemy_env_bonus` 和 `natural_spawn_herb` 当前仅完成数据解析，尚未接入灵植生长、炼丹增益和自然生成消费者，属于制作中字段。
- `client_hud` 可整体省略。`stored_aura` 显示区块附件中的灵气库存，`sensed_concentration` 显示当前位置解析后的灵气浓度；两者也都可以单独省略。
- `particle` 是灵气区域顶层的可选粒子效果，使用原版 `ParticleTypes.CODEC` 解析粒子类型。`count`、`speed`、`spread`、`offset_*` 与 `force` 会原样传给原版粒子发送 API；字段省略时才不发送粒子，`count: 0` 保留原版的特殊定向粒子语义。
- `client_render` 只负责客户端雾效，粒子不再放在其中。`fog_strength` 控制雾色和雾距离覆盖原版值的比例，`0` 为不覆盖，`1` 为完全覆盖，默认值为 `0.35`。
- 服务端每秒向玩家同步一次当前位置最终灵气浓度和来源 `aura_zone`。HUD 的感知浓度条和雾效均使用该快照；雾效强度还会按 `concentration / max(base_aura, 1)` 缩放，因此低浓度区域会更淡。灵气粒子仍按每 5 tick 刷新。
- `realm_stage.breakthrough_particle` 是可选的突破境界粒子；字段省略时不发送。标准预设为 `minecraft:end_rod`、`count: 20`、`speed: 0.03`、`spread: [0.6, 1.0, 0.6]`、`offset_y: 0.8`。
- 两个 HUD 条均使用 Origins 风格的 71x8 贴图。`maximum` 是满条对应的浓度，必须大于零；`bar_index` 选择贴图行和图标，`inverted` 可选且默认为 `false`。`anchor` 为 `left` 或 `right`，`order` 控制同侧灵气条从下到上的顺序；灵气条会自动排在同侧资源条上方。
- 推荐的自然灵气模板将 `base_aura` 设为 `0`，并启用正负噪声。经 `/ 10 - 5` 处理后，大面积区域没有自然灵气；`block_aura.aura_per_block` 会在此基础上按区块内方块数量累加，可将灵石矿脉配置为远高于自然值。

自然世界基础灵气使用 `max(0, (base_aura + noise) / 10 - 5)` 计算，负值会归零；灵石等方块的灵气贡献仍会在此基础上累加。

## 阵法联动

阵法定义可增加 `aura_zone`：

```json
{
  "structure_template": "example:gathering_array",
  "radius": 8,
  "aura_zone": "example:spirit_gathering"
}
```

活跃阵法以阵眼和 `radius` 覆盖范围内环境。阵法失效、维护失败或结构被破坏后，覆盖自动消失。

## 人工区域与 KubeJS

```js
const aura = Mxt.api().getAura(player.level, player.blockPos)
console.log(aura.concentration())

const area = Mxt.api().addAuraBox(
  player.level, 'example:blessing_land',
  0, 64, 0, 64, 128, 64, 10
)
Mxt.api().removeAuraArea(player.level, area)
```

人工区域会保存到世界。`priority` 越大，同类人工区域重叠时越优先。

KubeJS 事件名为 `MxtEvents.auraZone`，事件的 `kind` 是 `enter`、`leave`、`tick` 或 `override`；`override` 可取消以拒绝阵法环境覆盖。

## 其他系统字段

炼丹配方可使用：

```json
{
  "aura_kinds": ["example:aura_kind/fire"],
  "minimum_aura": 50
}
```

妖兽档案可使用：

```json
{
  "preferred_aura_elements": ["example:fire"],
  "minimum_aura": 30
}
```

服务端可用 `/mxt aura query` 查询脚下最终环境；站在灵石矿石上时，可用 `/mxt aura vein` 查询相连矿脉数量与等级。
