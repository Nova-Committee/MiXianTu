# 模块实现审计

**此文档已过时，新版：https://docs.qq.com/sheet/DWW9qRU1ST2Nob3Z5**

审计日期：2026-08-20。

本项目目前注册 **33 个原版 NeoForge 数据包注册表**。本文件将“通用数据驱动能力”与具体玩法拆开记录，避免某个玩法复用了成熟的
Action、Condition 或 NumberProvider 后，被误判为这些基础能力尚未实现。

## 判定标准

- **完成**：定义、所有字段的运行时消费者、存储/同步和入口已构成服务端闭环。
- **制作中**：定义与大部分运行时已存在，但至少一个字段、入口或下游联动没有消费者。
- **预留**：仅有数据结构、固有类型表或资源；尚未形成主要玩法闭环。

### 伤害管线

| 能力 | 状态 | 已实现内容 | 边界 |
| --- | --- | --- | --- |
| `DamageCalculationService` | 完成 | 模组自己发出的伤害只有这一条公共路径，分两层：**第一层出力**（发伤害处，攻击方一侧）把定义里的基础值乘以施放带来的 `damage_multiplier` 与**这一击的元素**对目标元素的 `overcomes`；**第二层减免**（`LivingIncomingDamageEvent`，受击方一侧）乘以受击者元素对**这一击的元素**的 `adapted_to`。第一层放在发伤害处是因为只有那里同时知道施法者、目标和正在施放的能力，第二层放在受击处是因为只有那里能看到所有打过来的伤害（别的模组、原版摔落与怪物攻击都算），而且"适应什么"本来就是受击者的属性；两层不会重复结算——第二层挂的事件每次伤害序列只触发一次，无论这一击是谁发的。**2026-09-20：两层读同一份"这一击是什么元素"**，由 `DamageElements` 从伤害类型反查元素的认领（没人认领才回落到攻击者灵根），因此第二层这个只拿得到 `DamageSource` 的地方也能算环境伤害的属性；同一个元素集合随后用于往目标身上积累附着（`element.damage_attachment`），所以"算多少"与"攒多少"永远一致。归拢进来的路径：`mxt:damage`（默认无归属，嵌在目标/乘客/装备行为里时才把施法者记为加害者）、`mxt:damage_target`（施加者记为加害者）、阵法的 `attack` 模块（按 `attribute_to_owner` 决定归属，`damage_type` 有就用）、`mxt:explode`（每次单体伤害过第一层，施法者记为爆炸起因，元素按 `minecraft:explosion` 的认领读）。加害者与来源在这里统一构造：声明了 `damage_type` 就用它并把加害者记为起因，没声明就按原版 `playerAttack`/`mobAttack`/`generic` 选择。 | 元素倍率住在 `element` 定义里，这个服务自己不带任何数值；`mxt:lightning` 等由原版结算的环境伤害不过第一层（没有可归的攻击者），但只要有元素认领了它的伤害类型，第二层照算属性；`mxt:damage` 打在自己身上时不记归属，因此没有克制与适应可言（`damage_multiplier` 是"这次施放值多少"，仍然生效——反噬随功法水平变重）；多个功法都授予同一能力时取最高的 `damage_multiplier`（不相乘）。 |
