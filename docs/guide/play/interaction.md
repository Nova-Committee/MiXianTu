### 灵气工作台

灵气工作台复用原版工作台布局，但只接受 `spirit_shaped` 和 `spirit_shapeless`。输入物品会保留在界面中；只有存在匹配配方时才接收配方声明的灵气，并在取出结果时扣除。

### 展示架

展示架可以放入或取出单个物品，物品会在方块中心上方掉落。若物品实现灵力访问接口，Jade 显示物品和灵力百分比。架上的物品靠**灵力射线**（`burst_amount` 大于 0 的灵气资源，快捷键发射）灌注：射线命中展示架即可，瞄准架子上显示的那件物品也算命中（方块本身的高度到 1.4375，显示的物品浮在 1.65，射线按"格子＋上面一格"来判定）。灌满时物品自己决定做什么——符箓会就地发动并以展示架的位置作为激发地点。

### Curios 槽位

本模组提供 `back_weapon` 两格、`belt_item` 两格与 `charm` 四格。背部和腰部槽位受服务端配置「饰品栏 → 背部槽位 / 腰部槽位」控制，快捷键可交换主手和背部第一个槽位物品。

四个 `charm` 槽位用的是 **Curios 内置的 `charm` 槽型**（槽位名字与图标由 Curios 提供，本模组只在它上面补了格数与校验器），只接收定义里声明了 `curios_equipable: true` 的法器；Curios 自带的 `curios:tag` 校验器没有被摘掉，所以 `curios:charm` 物品标签仍然可以放别的东西。放在 charm 槽里的法器照常生效：Curios 上的物品会被技能同步读到，它授予的被动／主动技能一样进人物面板（主动技能还会出现在轮盘配置界面的技能池里）。这四格不渲染在角色身上。

### 法器长按

手持一件被 `artifact` 认领、且定义里声明了 `hold_ticks`（默认 `20` 刻）的物品，按住右键不放：

- **没有主人**：按住满整段才认主——先判 `claim_condition`，然后写归属并跑 `claim_action`（它的默认值就是**扣 4 点生命**），最后跑一次 `use_action`。中途松手什么都不结算、也不扣血/不扣代价。**代价没有任何预检**：生命不够也照扣，可能当场死亡（创造模式这类打不掉血的持有者免费）。
- **主人是自己**：按住期间把自己的灵气灌进去——`spirit_capacity` 里写了几种灵气就灌几种，每种每刻 1 点，1:1 从自己对应灵气池扣，灌满或松手为止；每一个真的收下灵气的刻各跑一次 `pour_action`，整段走完再跑一次 `use_action`。
- **主人是别人**：这次右键**不接管**——不出现长按姿势，物品按自己的规则处理这次点击，动作栏只说一句「此物已认主他人」。
- **主人是自己但已灌满**：同上，不接管，提示「此物已充满灵气」。

认主这件事由三个字段描述：`claim_condition`（能不能认）、`claim_action`（认下时做什么，**默认就是扣 4 点生命**）、`pour_action` / `use_action`（注灵与收尾）。它们都是数据包里的行为，所以"免费认主"写 `"claim_action": {"type": "mxt:no_op"}`，"既付代价又有效果"就把行为写成数组（`mxt:consume_health` 后面接别的）。**留空 `claim_action` 不是免费**，那是默认的扣 4 点血。三条写归属的路（长按、`mxt:set_artifact_owner` 战利品函数、脚本）都会跑 `claim_action`。

想让"带在身上"持续付代价，用 `abilities` 里的 `mxt:upkeep`（`costs` + `interval` + `on_fail` + `owner_only`），那是逐刻结算的，不要塞进 `claim_action`（认主只发生一次）。

注灵时动作栏按**按住期间累计**报「注入灵气 N 点」（原版按住不放会连续重开 use 周期，所以不会每个周期从 0 重数），整段结束报「本次共注入灵气 N 点」；哪一门灵气不够就点名「自身灵气不足：<灵气名>」，而法器真的充满时什么都不报。

潜行右键永远不是长按（潜行是物品的"另一个行为"）；食物、药水这类自带用途的物品若同时是法器，它自己的用途优先。字段与条件写法见[数据包格式](../../数据包格式.md#artifact)。

### `/display`

`/display [player] [slot]` 在聊天中展示指定槽位物品。省略玩家时向全服广播，省略槽位时使用主手；指定玩家时只向该玩家发送私聊式提示。
