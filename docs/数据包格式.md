# MiXianTu 数据包 JSON 格式

本文是 MiXianTu 数据包定义的总览。每个动态注册表条目都是一个 JSON 文件；Java 固有注册表只提供 `type` 分派和 Codec，数据包只能填写已存在的字段，不能在 JSON 中创建新的 Java 行为。

注册表是否已经形成完整运行时闭环，以[模块实现审计](模块实现审计.md)为准。本文记录当前代码的加载契约，未实现的消费者不会被描述为已实现。

## 文件位置

动态注册表文件统一放在：

```text
data/<命名空间>/mxt/<注册表名>/<路径>.json
```

例如：

```text
data/example/mxt/ability/firebolt.json
```

该文件的定义 ID 为 `example:firebolt`。文件名可以包含目录，目录会成为 ID 路径的一部分。

数据包标签使用原版标签路径：

```text
data/<命名空间>/tags/mxt/<注册表名>/<标签路径>.json
```

动态注册表的停用标签固定为：

```text
data/mxt/tags/mxt/<注册表名>/disabled.json
```

```json
{
  "replace": false,
  "values": [
    "example:old_definition",
    "othermod:disabled_definition"
  ]
}
```

`disabled` 中的条目不会被对应服务主动使用，但仍然保留在注册表中，允许其他定义安全地持有它的 Holder。项目尚未发布，不承诺旧 JSON 或旧存档兼容。

## 加载与覆盖

- 31 个动态注册表使用 NeoForge 原版数据包注册表加载；服务端重载后校验，并通过原版同步机制提供客户端只读快照。
- 文件冲突遵循 Minecraft 数据包优先级：高优先级数据包覆盖低优先级数据包的同一路径。
- 原版标签使用 `replace: false` 时，值按数据包合并顺序追加；除品质排序标签外，玩法不依赖标签值顺序。
- 数据包只读，定义中没有通用的 `schema_version`、`enabled` 或 `tags` 字段。
- 必填的单个 Holder 引用不存在时，整个数据包重载失败；可选 Holder 和容错列表引用按对应 Codec 处理。
- `/reload` 成功后才替换当前快照；失败时继续使用旧快照。

## 基础类型

| 类型 | JSON 形状 | 说明 |
| --- | --- | --- |
| `String` | `"fire"` | 普通字符串。 |
| `Boolean` | `true` | 布尔值。 |
| `Integer` | `20` | 整数，范围以字段表为准。 |
| `Long` | `100000` | 长整数，范围以字段表为准。 |
| `Double` | `1.5` | 双精度数；加载阶段拒绝 `NaN` 和无穷大。 |
| `Identifier` | `"example:fire"` | 带命名空间的资源 ID。 |
| `Holder<T>` | `"example:resource"` | 指向动态注册表或原版注册表的单个条目。 |
| `Tag<T>` | `"#example:fire"` | 原版标签引用，`#` 不能省略。 |
| `HolderOrTag<T>` | 字符串或字符串数组 | 单个 ID、单个标签或混合数组。 |
| `ItemMatcher` | ID、标签或混合数组 | 物品绑定表的 `items` 字段；匹配现有物品，不创建物品。 |
| `Text Component` | 字符串或文本对象 | 支持翻译键字符串和原版文本组件。 |
| `ItemStackTemplate` | `{"id":"minecraft:stone"}` | 原版物品堆模板，可附带 `count` 和数据组件。 |
| `NumberProvider` | 数字、字符串或对象 | 常量、exp4j 表达式或固有数值提供器。 |
| `EntityAction` | 对象或对象数组 | 对实体执行行为；数组按顺序执行。 |
| `BiEntityAction` | 对象或对象数组 | 对来源实体和目标实体执行行为。 |
| `BlockAction` | 对象或对象数组 | 对方块位置执行行为。 |
| `ItemAction` | 对象或对象数组 | 对物品堆执行行为。 |
| `EntityCondition` | 对象或对象数组 | 数组表示全部条件都必须满足。 |

### `ResourceCost` 与 `ResourceGain`

凡是需要消耗或增加资源的字段都使用数组；每项的结构统一为：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `Holder<resource>` | 资源注册表条目。 |
| `amount` | `NumberProvider` | 成本必须在运行时得到有限正数；收益允许为 `0`。 |

```json
"costs": [
  {"id": "example:qi", "amount": "5 + level"},
  {"id": "example:stamina", "amount": 2}
]
```

### `AttributeEntry`

属性修正使用 `minecraft:generic.attack_damage` 等原版属性 Holder：

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `attribute` | `Holder<Attribute>` | **必填** | 原版属性 ID。 |
| `id` | `Identifier` | **必填** | 原版 `AttributeModifier` 的唯一 ID。 |
| `amount` | `Double` | **必填** | 没有动态 `value` 时使用的基础值。 |
| `operation` | Enum | **必填** | `add_value`、`add_multiplied_base` 或 `add_multiplied_total`。 |
| `value` | `NumberProvider` | 无 | 填写后每 tick 在服务端按实体上下文重新计算，替代 `amount`。 |

## Holder、标签与匹配器

跨注册表字段尽量在数据包加载阶段解析成 Holder，不在运行时重复查询注册表。

### 单值和标签

```json
{
  "resource": "example:spirit_power",
  "ability_requirements": "#example:fire_abilities"
}
```

### 混合数组

支持 ID、标签混合的字段可以直接写数组：

```json
{
  "ability_requirements": [
    "example:fireball",
    "#example:basic_fire_abilities"
  ]
}
```

数组中的每一项会保留为 Holder 或 TagKey；重复值不会自动改变语义。`AutoIgnoreListCodec` 允许列表中的无效可选项被忽略，具体字段表会标明是否使用该 Codec。

### `ItemMatcher`

`item_binding`、`weapon_binding`、`pill_binding`、`technique_binding`、`spirit_herb`、`item_aura` 和 `currency` 的 `items` 字段支持以下三种写法：

```json
"items": "minecraft:apple"
```

```json
"items": "#minecraft:logs"
```

```json
"items": ["minecraft:apple", "#minecraft:logs", "othermod:token"]
```

匹配器只引用已经注册的物品。多个定义同时匹配时，按 `priority` 从低到高选择；当前这些数据类的优先级固定为 `0`。

## 数值提供器

所有需要随等级、境界或事件上下文变化的数值都可以使用 `NumberProvider`。求值在服务端完成，客户端只使用同步后的结果。

### 简写

数字自动解析为常量：

```json
"amount": 5
```

字符串自动解析为表达式：

```json
"amount": "4 + level * 0.5"
```

### 结构化表达式

```json
{
  "type": "mxt:expression",
  "expression": "base_damage * multiplier",
  "params": {
    "base_damage": 8,
    "multiplier": "1 + level * 0.1"
  }
}
```

`params` 的值本身也是 `NumberProvider`，并覆盖同名上下文变量。表达式中未注册的变量按 `0` 处理；加载阶段公式语法错误会使重载失败，运行时的 `NaN` 或无穷大会记录单行警告并返回 `0`。

### 固有数值提供器

| `type` | 字段 | 说明 |
| --- | --- | --- |
| `mxt:constant` | `value` | 固定数值。数字简写等价于该类型。 |
| `mxt:expression` | `expression`、`params` | exp4j 表达式；`params` 可覆盖上下文变量。 |
| `mxt:context_variable` | `variable`、`fallback` | 读取当前上下文变量，不存在时使用回退值。 |
| `mxt:sum` | `summands` | 数值提供器求和。 |
| `mxt:uniform` | `min`、`max` | 使用传入上下文的 `RandomSource` 取均匀随机值。 |
| `mxt:binomial` | `n`、`p` | `n` 次伯努利试验；`n` 为 `0..16384`，`p` 为 `0..1`。 |
| `mxt:weighted_list` | `distribution` | 按正整数 `weight` 选择 `data`。 |
| `mxt:js` | 类型专用字段 | 调用 KubeJS 数值提供器扩展。 |

实体和 Level 的 `RandomSource` 会优先传入随机提供器；不要在客户端重新滚动随机值来决定游戏结果。

### 常见公式变量

公式变量由固有 `mxt:formula_variable` 注册表提供。常见上下文包括 `level`、`realm_rank`、`absorbed_aura`、`resource`、`base_damage`、`attack_speed` 和 `aura_tribulation_modifier`。不同事件提供的变量可能不同；使用 `params` 可以为同一公式显式提供变量。

## 固有类型分派

下列字段使用 Java 固有注册表的 `MapCodec`。数据包只能传入 `type` 和该类型的参数，不能添加新的 `type`：

| 数据类型 | 分派字段 | 作用 |
| --- | --- | --- |
| `Ability` | `ability.type` | 顶层字段名为 `ability`，嵌套对象中的 `type` 选择技能生命周期和触发方式。 |
| `CurseType` | `type` | 诅咒的持续和过期方式。 |
| `EntityAction` | `type` | 实体行为。 |
| `BiEntityAction` | `type` | 双实体行为。 |
| `BlockAction` | `type` | 方块行为。 |
| `ItemAction` | `type` | 物品行为。 |
| `EntityCondition` | `type` | 实体条件。 |
| `BiEntityCondition` | `type` | 双实体条件。 |
| `BlockCondition` | `type` | 方块条件。 |
| `ItemCondition` | `type` | 物品条件。 |
| `DamageCondition` | `type` | 伤害条件。 |
| `ResourceBarRenderer` | `type` | 资源条绘制器。 |
| `ResourceBarVisibility` | `type` | 资源条显示条件。 |
| `Badge` | `type` | 徽章结构。 |

行为和条件数组是简写：

```json
"entity_action": [
  {"type": "mxt:heal", "amount": 2},
  {"type": "mxt:apply_curse", "curse": "example:burning", "stacks": 1}
]
```

所有行为的具体字段以固有类型 Codec 为准。内置类型由 `MxtEntityActions`、`MxtBiEntityActions`、`MxtBlockActions`、`MxtItemActions`、`MxtEntityConditions` 等类分组注册；数据包重载不会向这些固有注册表添加条目。

## 资源、境界与修炼

### `resource`

文件位置：`data/<namespace>/mxt/resource/<id>.json`

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `default_value` | `NumberProvider` | **必填** | 新建附件时的当前值。 |
| `min` | `NumberProvider` | `0` | 资源下限。 |
| `max` | `NumberProvider` | **必填** | 动态上限；可使用境界和已吸收灵气变量。 |
| `regen` | `NumberProvider` | `0` | 每 tick 的自然恢复值。 |
| `burst_amount` | `NumberProvider` | `0` | 大于 `0` 时，该资源可由“发射灵力”快捷键消耗并作为每发灵力射线的数值。每个数据包应只配置一个此值大于 `0` 的默认灵力资源。 |
| `particle_color` | `RGBColor` | `#FFFFFF` | 灵力射线使用的粒子颜色。可写入 `#RRGGBB` 或 `0..16777215` 整数。 |
| `cultivation_to_resource` | 对象 | `multiplier=1,max_per_tick=1` | 从修为计数抽取资源回复蓝条。 |
| `resource_to_cultivation` | 对象 | `multiplier=1,max_per_tick=1` | 仅修炼模式下把资源转回修为。 |
| `bars` | `List<ResourceBar>` | `[]` | 内联资源条；为空时不显示该资源。 |
| `first_realm` | `Holder<realm_stage>` | 无 | 该资源对应境界链的首个境界。 |

`cultivation_to_resource` 和 `resource_to_cultivation` 的两个字段如下：

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `multiplier` | `NumberProvider` | `1` | 来源值转换为目标值的倍率。 |
| `max_per_tick` | `NumberProvider` | `1` | 每 tick 最多消耗的来源值；限制的是来源，不是目标。 |

示例：

```json
{
  "default_value": 0,
  "max": "100 + realm_rank * 20 + absorbed_aura * 0.1",
  "regen": 0.25,
  "burst_amount": 10,
  "particle_color": "#66CCFF",
  "cultivation_to_resource": {"multiplier": 1, "max_per_tick": 2},
  "resource_to_cultivation": {"multiplier": 0.5, "max_per_tick": 1},
  "bars": [
    {
      "context": "self_hud",
      "anchor": "left",
      "order": 0,
      "renderer": {"type": "mxt:boss_bar", "bar_index": 1}
    }
  ],
  "first_realm": "example:foundation"
}
```

修炼吸收默认只回复当前境界对应资源；只有处于修炼状态时才允许反向转换。`max` 和 `regen` 在服务端求值，客户端不参与结算。

### `resource.bars`

`bars` 是 `resource` 内联数组，不是独立动态注册表。

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `context` | `self_hud` / `target_overlay` / `boss_overlay` | `self_hud` | 条显示在哪个上下文。 |
| `anchor` | `left` / `right` | **必填** | 自我 HUD 的左列或右列。 |
| `order` | Integer | `0` | 同一列中越小越靠近原版热键栏。 |
| `visibility` | `ResourceBarVisibility` | `mxt:always` | 是否显示。 |
| `renderer` | `ResourceBarRenderer` | **必填** | 绘制方式。 |
| `value_display` | `none` / `current` / `current_and_maximum` / `percentage` | `none` | 数值文本显示方式。 |
| `replace_default` | Boolean | `false` | 同资源同上下文时替换普通声明。 |

内置绘制器包括 `mxt:boss_bar`、`mxt:textured_bar`、`mxt:segmented_bar`、`mxt:radial_bar` 和 `mxt:text_only`。`mxt:boss_bar` 可配置 `sprite_location`、`bar_index`、`icon_index` 和 `inverted`，贴图默认使用 `mxt:textures/gui/resource_bar.png`。渲染通过 NeoForge GUI Layer 接入，条只显示在左列或右列，不占用屏幕中央。

绘制器参数：

| `type` | 字段 | 默认 | 说明 |
| --- | --- | --- | --- |
| `mxt:boss_bar` | `sprite_location`、`bar_index`、`icon_index`、`inverted` | 见上文 | Origins 风格 71x8 条和图标。 |
| `mxt:textured_bar` | `background_sprite`、`fill_sprite`、`width`、`height`、`fill_color`、`show_value` | `fill_color=#ffffff,show_value=false` | 使用两张独立贴图。宽高范围 `1..1024`。 |
| `mxt:segmented_bar` | `segments`、`gap`、`full_color`、`empty_color` | `gap=1,full_color=#ffffff,empty_color=#555555` | 分段条；`segments` 范围 `1..256`。 |
| `mxt:radial_bar` | `radius`、`thickness`、`start_angle`、`end_angle`、`fill_color` | `start_angle=0,end_angle=360,fill_color=#ffffff` | 径向条。 |
| `mxt:text_only` | `format`、`color`、`show_maximum` | `%current%,#ffffff,false` | 只显示文本；格式支持 `%current%`。 |

可见性类型：`mxt:always`、`mxt:non_full`、`mxt:recently_changed`（`hold_ticks` 默认 `60`）、`mxt:resource_range`（必填 `min`、`max`）、`mxt:and`、`mxt:or` 和 `mxt:not`。

### `badge`

文件位置：`data/<namespace>/mxt/badge/<id>.json`

Badge 当前是预留的可写数据包注册表，不会自动显示在选择界面或图鉴中。定义使用固有 `type` 分派：

| `type` | 字段 | 默认 | 说明 |
| --- | --- | --- | --- |
| `mxt:empty` | 无 | - | 空占位徽章。 |
| `mxt:sprite` | `sprite` | **必填** | 只显示贴图。 |
| `mxt:tooltip` | `sprite`、`text` | `text` 为空文本 | 带悬浮说明的贴图。 |
| `mxt:keybind` | `sprite`、`text`、`key` | `text=""`, `key="key.mxt.primary_active"` | 记录客户端按键映射。 |
| `mxt:crafting_recipe` | `sprite`、`recipe`、`from_power`、`prefix`、`suffix` | `from_power=false` | 预留配方提示元数据。 |

```json
{
  "type": "mxt:tooltip",
  "sprite": "mxt:textures/gui/badge/info.png",
  "text": "badge.example.info"
}
```

### `realm_stage`

文件位置：`data/<namespace>/mxt/realm_stage/<id>.json`

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `resource` | `Holder<resource>` | **必填** | 强绑定的灵气/修为资源；一个境界只能属于一个资源链。 |
| `aura_share_weight` | `NumberProvider` | `1` | `aura_zone.distribution: realm_weighted` 时参与同区块灵气分配的权重。 |
| `cultivate_condition` | `EntityCondition` | `mxt:always_true` | 该境界允许修炼的环境条件；例如用 `mxt:aura_range` 要求最低浓度。 |
| `next_realm` | `Holder<realm_stage>` | 无 | 线性链的下一个境界；最多一个。 |
| `progress_threshold` | `NumberProvider` | **必填** | 当前境界达到下一境界所需的修为计数。 |
| `upgrade_conditions` | `List<EntityCondition>` | `[]` | 统一升级条件数组，全部满足才可突破。 |
| `passive_modifiers` | `List<AttributeEntry>` | `[]` | 当前境界提供的原版属性修正；条目包含 `attribute`、原版 modifier 的 `id/amount/operation`，并可选填写公式 `value`。 |

示例：

```json
{
  "resource": "example:qi",
  "aura_share_weight": 2,
  "cultivate_condition": {"type": "mxt:aura_range", "min": 20, "max": 200},

  "progress_threshold": "1000 + level * 250",
  "upgrade_conditions": [
    {"type": "mxt:realm", "realm": "example:foundation"},
    {"type": "mxt:resource_compare", "resource": "example:qi", "min": 100}
  ],
  "costs": [{"id": "example:qi", "amount": 100}],
  "success_action": {
    "type": "mxt:grant_ability",
    "ability": "example:body_tempering",
    "source": "example:foundation"

```

境界附件保存当前境界 Holder；服务器境界缓存保存“境界 -> 灵气”的映射。境界链只能通过 `next_realm` 单向推进。

自然环境使用 `max(0, (base_aura + noise) / 10 - 5)` 初始化，噪声由 `seed`、`scale`、`amplitude` 控制；`max` 省略时即为这个初始值。可用固定数值、`{ "type": "mxt:fixed", "value": 100 }`、`{ "type": "mxt:initial_multiplier", "multiplier": 2 }` 或 `{ "type": "mxt:unlimited" }`。方块灵气会额外提高有效容量，不占用环境上限。环境优先级为群系 < 维度 < 永久区域 < 阵法覆写。到期修炼玩家共享同一块区块库存：`random` 随机优先满足，`equal` 做公平分配，`realm_weighted` 按境界权重分配；配额不足会同比降低本次修炼收益。

#### `fluctuation`

### `item_aura`

文件位置：`data/<namespace>/mxt/item_aura/<id>.json`

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `items` | `ItemMatcher` | **必填** | 手持时可作为灵气燃料的现有物品。 |
| `total_aura` | `NumberProvider` | **必填** | 首次处理一件物品时写入其 `mxt:item_aura.remain` 的总量。 |
| `consume_speed` | `NumberProvider` | **必填** | 每 tick 消耗燃料值。 |
| `release_speed` | `NumberProvider` | **必填** | 每 tick 向当前境界资源条释放的燃料量。 |
| `result_stack` | `ItemStackTemplate` | 无 | 当前物品完全耗尽时额外给予返还物品；不配置则只移除原物品。 |
| `exhausted_action` | `EntityAction` | `mxt:no_op` | 当前燃料耗尽行为。 |

修炼模式下，当前待消耗物品保存在实体 `mxt:float_holding_item` 附件中，剩余灵气保存在物品自身的 `mxt:item_aura` 组件（仅 `remain` 字段）中。附件为空时，先选择物品栏内剩余值最小的有效半耗尽物品；若没有，才按主手、再副手取新的匹配物品并写入 `total_aura`。中断修炼、登出或死亡会归还附件物品；只有剩余值耗尽时才移除物品、给予 `result_stack` 并执行 `exhausted_action`。附件也可由其它系统使用，因此灵气服务只处理带有自身组件且仍匹配有效定义的物品；客户端不渲染燃料条。

## 重载、同步与调试

- 使用 `/reload` 重新加载数据包；JSON 解析、Holder 解析和 Codec 校验均在服务端完成。
- 动态注册表由原版同步机制发送给客户端；客户端 HUD、雾效和贴图只负责展示，不决定扣除、突破、锻造或兑换结果。
- `/mxt aura query` 查询当前位置最终灵气；`/mxt aura vein` 查询灵石矿脉信息。
- 测试模组数据位于 `src/test-mod/resources/data/mxt_test/mxt`，启动测试服务端可验证数据包闭环。
- 精确的当前完成度、字段消费者和测试覆盖见[模块实现审计](模块实现审计.md)。

:::warning
Codec 是唯一的加载契约。本文中的默认值、字段范围和示例以当前源码为准；数据包写入未列出的字段不会自动生效，写入未知 `type` 会导致重载失败。
:::
