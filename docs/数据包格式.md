# MiXianTu 数据包格式

本文档说明 MiXianTu 已注册的动态数据表。除原版配方、战利品表和标签外，这些定义均由服务端在数据包重载时读取，并在校验通过后同步至客户端。

## 数据类型

下表使用的类型名称与 JSON 示例保持一致：

| 类型 | 说明 | 示例 |
|------|------|------|
| `String` | 文本字符串 | `"fire"` |
| `Boolean` | 真或假 | `true` |
| `Integer` | 整数 | `20` |
| `Long` | 长整数 | `100000` |
| `NumberProvider` | 常量、公式或数值提供器 | `"10 + level * 2"` |
| `Identifier` | 带命名空间的资源 ID | `"mxt:spirit_power"` |
| `List<T>` | 某类型的数组 | `["mxt:fire", "mxt:water"]` |
| `Object` | 键值对象 | `{"key": "value"}` |
| `Item Stack` | 原版物品堆叠 | `{"id": "minecraft:diamond", "count": 3}` |

## 目录、ID 与覆盖

每个动态注册表均使用以下路径：

```text
data/<命名空间>/mxt/<注册表名>/<路径>.json
```

例如 `data/example/mxt/ability/fireball.json` 的定义 ID 是 `example:fireball`。`mxt` 是模组命名空间，不随数据包命名空间变化。

高优先级数据包中相同文件路径会覆盖低优先级数据包的同一条目。每个动态注册表都有一个保留标签 `disabled`：该标签中的 entry
不参与对应玩法，但定义本身仍然存在，其他条目仍可引用它。停用条目不需要复制或修改原 JSON。

动态注册表标签使用原版标签语法，路径为：

```text
data/<命名空间>/tags/mxt/<注册表名>/<标签路径>.json
```

保留的 `disabled` 标签固定使用模组命名空间，停用 `mxt:copper_coin` 和 `example:old_coin` 的路径为：

```text
data/mxt/tags/mxt/currency/disabled.json
```

内容为：

```json
{
  "replace": false,
  "values": [
    "mxt:copper_coin",
    "example:old_coin"
  ]
}
```

普通自定义标签示例（标签命名空间可以使用数据包命名空间）：

```json
{
  "replace": false,
  "values": [
    "mxt:fireball",
    "example:lightning"
  ]
}
```

标签表达的是成员关系，**不要依赖 `values` 数组的顺序**。

## 通用数值与注册表标签

不存在适用于所有定义的 `tags` 或 `enabled` JSON 字段。动态注册表的成员关系和启用状态均由原版标签文件控制：entry 位于该注册表的 `disabled` 标签中时视为停用，否则视为启用。

各数据类型中的 `compatibility_tags`、`exclusive_tags`、`aura_tags` 等是该类型自己的字段；它们不是注册表标签，也不具有通用的筛选语义。字段是否支持应以对应 Codec 为准。

所有 ID 均为资源位置，例如 `mxt:spirit_power`、`minecraft:diamond`、`othermod:token`。

大量数值字段采用 `NumberProvider`，可写成以下三种形式：

```json
42
```

```json
"10 + level * 2"
```

```json
{
  "type": "mxt:context_variable",
  "variable": "level",
  "fallback": 1
}
```

字符串公式由 exp4j 计算。公式变量由实际事件上下文提供，未提供的变量会按上下文的默认值处理。技能、诅咒、资源消耗、属性修正等所有数值字段应优先使用此机制，而不是在数据包中固化等级相关数值。

资源消耗统一写为数组，每一项固定具有 `id` 与 `amount`：

```json
"costs": [
{"id": "mxt:spirit_power", "amount": "5 + level"},
{"id": "mxt:stamina", "amount": 2}
]
```

`id` 必须指向 `resource` 注册表中的有效条目；计算后的 `amount` 必须是有限正数。

为准；Codec 是唯一的实际加载契约。

## 资源与资源条

### `resource`

```json
{
  "default_value": 100,
  "min": 0,
  "max": "100 + level * 20",
  "regen": "0.5 + realm_level * 0.1",
  "default_bar": "mxt:spirit_power_hud"
}
```

`default_value` 与 `max` 是必填数值；`min` 和 `regen` 可省略。`default_bar` 若存在，必须引用 `resource_bar` 条目。

### `resource_bar`

```json
{
  "resource": "mxt:spirit_power",
  "context": "self_hud",
  "anchor": "above_hotbar",
  "order": 10,
  "visibility": {
    "type": "mxt:always"
  },
  "renderer": {
    "type": "mxt:segmented_bar",
    "segments": 10,
    "gap": 1,
    "full_color": "#4e9cff",
    "empty_color": "#2b3445"
  },
  "replace_default": false
}
```

`resource`、`anchor` 与 `renderer` 必填。`context` 可为 `self_hud`、`target_overlay` 或 `boss_overlay`；`anchor` 可为
`below_health`、`above_hotbar`、`top_left_stack`、`top_right_stack`。`renderer` 和 `visibility` 由固有注册表的 `type`
分派：代码定义行为和 MapCodec，数据包只提供参数。内置渲染器为 `mxt:textured_bar`、`mxt:segmented_bar`、`mxt:radial_bar`、
`mxt:text_only`；内置可见性为 `mxt:always`、`mxt:non_full`、`mxt:recently_changed`、`mxt:resource_range`、`mxt:and`、`mxt:or`、
`mxt:not`。

## 技能、条件与行为

### `ability`

```json
{
  "type": "mxt:triggered",
  "trigger": "mxt:use",
  "costs": [
    {
      "id": "mxt:spirit_power",
      "amount": "10 + level"
    }
  ],
  "cast_time": 0,
  "cooldown": "20 * 5",
  "components": [],
  "modifiers": [
    {
      "attribute": "minecraft:generic.attack_damage",
      "operation": "add_value",
      "value": "level * 0.25"
    }
  ],
  "condition": {
    "type": "mxt:sneaking"
  },
  "entity_action": {
    "type": "mxt:add_resource",
    "resource": "mxt:spirit_power",
    "amount": 1
  },
  "target_condition": {
    "type": "mxt:distance",
    "maximum": 8
  },
  "bi_entity_action": {
    "type": "mxt:damage_target",
    "amount": "4 + level"
  },
  "element_affinity": [
    "mxt:fire"
  ]
}
```

`type` 是固有技能类型，决定额外字段和触发方式。`cast_time`、`cooldown`、属性修正值和行为数值都可使用公式。属性操作可为
`add_value`、`add_multiplied_base`、`add_multiplied_total`。

动作与条件也是“固有注册表定义行为 + 数据包以 `type`
调用”的格式。单项写为对象；动作、实体条件、双实体条件、方块条件和物品条件均允许直接写数组作为简写，数组按顺序执行动作，或按“全部满足”组合条件：

```json
"entity_action": [
{"type": "mxt:heal", "amount": 2},
{"type": "mxt:apply_curse", "curse": "mxt:burning", "stacks": 1}
]
```

常用行为包括 `add_resource`、`damage`、`heal`、`apply_curse`、`remove_curse`、`grant_ability`、`spawn_entity`、`teleport`、
`set_block`。常用条件包括 `has_ability`、`has_curse`、`resource_compare`、`realm`、`sneaking`、`distance`、`same_team`。每种
`type` 所允许的字段由其固有 MapCodec 决定。

## 灵根、体质、元素与诅咒

`spirit_root` 以 `element` 绑定灵根，主要字段为 `element`、`granted_abilities`、`compatibility_tags`。`physique`
与元素不绑定，主要字段为 `modifiers`、`granted_abilities`、`holder_conditions`、`exclusive_tags`。两者均可通过 `granted_abilities`引用技能。

`element` 包含 `overcomes` 与 `adapted_to` ID 数组；所有引用都必须存在。

`curse` 使用固有诅咒类型 `type`，并支持 `duration_ticks`、`tick_interval`、`max_stacks`、`stacking_mode`、
`application_condition`、`on_apply`、`on_tick`、`on_remove`、`cleanse_tags`、`allow_force_remove`。诅咒行为可直接引用技能、药物、事件等定义中的
`curse` 字段；应用与移除均在服务端执行。

## 锻造

### `forging_method`

```json
{
  "value_delta": 3,
  "costs": [
    {
      "id": "mxt:stamina",
      "amount": 2
    }
  ],
  "conditions": [
    "mxt:has_hammer"
  ],
  "display_icon": "mxt:hammer"
}
```

`value_delta` 必填且不能为 `0`。正数使锻打条向右移动，负数向左移动。

### `forging_blueprint`

```json
{
  "input": "minecraft:iron_sword",
  "allowed_methods": [
    "mxt:heavy_strike",
    "mxt:light_strike"
  ],
  "meter_min": -10,
  "meter_max": 10,
  "target_min": 2,
  "target_max": 4,
  "finish_pattern": {
    "steps": [
      "mxt:heavy_strike",
      "mxt:light_strike",
      "mxt:heavy_strike",
      "mxt:light_strike",
      "mxt:light_strike",
      "mxt:heavy_strike"
    ],
    "required_suffix_steps": 3,
    "show_finish_pattern": true
  },
  "max_steps": 32,
  "quality_by_extra_steps": [
    {
      "max_extra_steps": 0,
      "quality": "mxt:excellent"
    },
    {
      "max_extra_steps": 5,
      "quality": "mxt:normal"
    },
    {
      "max_extra_steps": 2147483647,
      "quality": "mxt:poor"
    }
  ],
  "result": "mxt:forged_iron_sword",
  "workstation_blocks": [
    "minecraft:anvil"
  ],
  "failure_settlement": {
    "result": "minecraft:iron_nugget",
    "input_return_ratio": 0.25,
    "material_loss_ratio": 0.75
  }
}
```

锻打条初始值为 `0`。成功时最终值必须落入 `[target_min, target_max]`，且最后 `required_suffix_steps` 步与
`finish_pattern.steps` 的末尾完全匹配。`required_suffix_steps` 为 `0` 到 `6`；只要大于 `0`，`steps` 必须恰为 6 项，且每项必须在
`allowed_methods` 中。

系统从允许的锻打方式计算抵达目标区间的最优步数；实际成功步数与该最优值的差值为“额外步数”，由 `quality_by_extra_steps`
决定品质。阈值必须升序排列，且最后一项 `max_extra_steps` 必须为 `2147483647`。`failure_settlement` 中两个比例范围均为 `0` 到
`1`。

## 货币

### `currency`

```json
{
  "item": "minecraft:emerald",
  "value": 100,
  "exchanges": [
    {
      "cost": 4,
      "result": {
        "id": "minecraft:diamond"
      }
    }
  ]
}
```

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `item` | 物品 ID | **必填** | 货币物品，用于面额结算。 |
| `value` | 长整数 | **必填** | 单个物品的正整数面额。 |
| `exchanges` | 兑换数组 | **必填** | 当前货币的单向兑换选项；可使用空数组。 |

每个兑换项为 `{ "cost": 兑换消耗数量, "result": Item Stack }`。`cost` 范围为 `1` 到 `99`；`result` 的 `id` 必填，`count` 默认为 `1`，并可提供 `components` 对象。兑换站以切石机式列表按数组顺序显示这些单向选项，不再根据面额推导比例；支票桌仍只读取 `item` 与 `value`。禁用标签路径为 `data/mxt/tags/mxt/currency/disabled.json`。完整示例与工作站规则见 [经济系统数据包格式](经济系统数据包格式.md)。

默认硬币为 `mxt:copper_coin` (1)、`mxt:iron_coin` (10)、`mxt:gold_coin` (100)、`mxt:diamond_coin` (1000)、
`mxt:emerald_coin` (10000)、`mxt:netherite_coin` (100000)
。更详细的经济工作站规则见 [经济系统数据包格式](经济系统数据包格式.md)。

## 引用校验与重载

- 所有跨表 ID，例如资源消耗、元素、技能、诅咒、资源条和锻打方式，必须指向同一次重载中存在的条目；被 `disabled`
  标签标记的条目仍然可以作为引用目标，但不能被玩法服务主动使用。
- 定义先收集全部 ID、再解析数据，因此允许前向引用和循环引用；不存在的 ID 会令整个重载失败，旧数据保持生效。
- 使用 `/reload` 或重启服务器后才会应用修改。校验成功后服务器会将快照同步给客户端。
- 复杂行为不可只在 JSON 中“发明”新 `type`。需要先在代码中注册对应 MapCodec 与运行时行为，再由数据包传入该类型的数据。
